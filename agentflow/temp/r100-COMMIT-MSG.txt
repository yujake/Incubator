## 一、`quote_verified_rows` 与文献那条腿都改走 `evidencebits.quote_state`

收工门里数引文的两处（`quote_verified_rows`、以及按 `\bibitem` 定分母那一条）此前直接读
`quote_verified is True` —— 于是"说了通过、却说不清怎么通过的"（`quote_mode` 空/认不出的词）
**照样算通过**，与 `quote_state` 那条纪律分家（业主 2026-10-14 的两档口径要求它算**没查**）。
现在两处都走同一个读口径，并且把方式分开报：

```
"true" = verbatim + semantic     # 两档之和
"false" = mismatch
"unchecked" = 没查（含"方式说不清"那一档）
"verbatim" / "semantic"          # 新增两栏：前一个不花钱、后一个是 H 判的
```

## 二、顺带逮到并修掉一处真缺陷：收工门那一格曾悄悄退成 `unknown`

`_leg_reading` 是一个跨上千行的大 if 链，函数体里另有一处
`from . import evidencebits as EB`（局部导入）。Python 的规则是：**函数里任何一处赋值/导入
都会让整个函数里的这个名字变局部** —— 于是我在上面那几档用模块级 `EB` 时直接
`UnboundLocalError`，而收工门的症状是那一格从 `pass` **静默退成 `unknown`**
（`tests/test_closing_gate.py` 当场红，是它逮住的）。删掉那处局部导入即可。

判据：`test_the_closing_gate_counts_by_the_same_two_columns`（新）——
老行（`True` 无方式）按逐字读、`semantic` 单独报、**手改盘上 JSON 造的 `fuzzy` 行算没查**
（写入侧本来会拒它，而这一档要挡的正是绕过写入侧的行的）、`true` 是两档之和。
