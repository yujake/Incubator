R96（goal 第 2 轮）：语义那一档的判据本体 —— 引文与来源「说同一件事」才算过

业主 2026-10-14 的裁定落到判据层：语义相同即可，而"结论强于引文"照样不通过。
这一轮把**判据本体**写出来（不碰权限面、不碰 H 的动作表），下一轮接 B 唤起 H。

## 一、新判据 `quote.same_meaning`（`judges.py`）

四档词表，逐条对着业主那句：

- `same_meaning`（通过档）= 语义相同 —— **允许改写、换记号、跨语言、简写**；
- `different` = 说的不是同一件事（对象/条件/结论对不上）；
- `stronger_than_source` = 引文把来源的结论**加强了**（来源说"在某条件下"、引文写成无条件；
  来源说"可能"、引文写成"必然"）⇒ **不算通过**（这一条是 H 的老判据，语义档不许把它放宽）；
- `unjudgeable` = 材料不足以判。

prompt 里明写一句反向纪律：**不要因为字面不完全一样就判 different —— 那是逐字比对，
不是这一条要的**（`test_a_rewritten_quote_passes_on_meaning_not_on_letters` 会读 prompt 里这句）。
两条负控（`registry_problems` 要求 ≥2）：引文删了条件、引文与来源根本不是一件事；
两条都"字面上沾边、语义上不成立"——正是这一档存在的理由。

## 二、适配器与唯一映射（`judges.py`）

- `quote_semantics_judge_for(seam)`：把模型缝接成 `(quote, span, statement, where)` →
  `{"verdict", "why", "call"}`。`call` 带 **model / prompt_sha256 / prompt_version /
  judge_version** —— 业主那句"语义那一档必须留证据"里的**可复查的调用记录**就是它；
  缝没接（没有 key）⇒ `judge_not_wired` ⇒ `verdict="unknown"` + 理由写明"没判成，
  不是判过了没问题"；坏 JSON 同理。
- `quote_fields_from_verdict(verdict, why)`：判定 ⇒ `(quote_verified, quote_mode, quote_reason)`
  的**唯一**口径 —— `same_meaning` ⇒ `(True, "semantic", …)`；
  `different` / `stronger_than_source` ⇒ `(False, "", …)`；
  其余 ⇒ `(None, "", "还没查：…")`（三态里的第三档，不许折成通过）。

**没有**把模型调用塞进 `quoteverify.check_quote`：逐字那一档仍是禁改区里那份不花钱的实现，
两档分居两处、靠 `quote_mode` 那一栏分开记账（这是上一轮定的口径，这一轮守住）。

## 三、判据（`tests/test_quote_semantics.py`，17 → 22 条）

新增 5 条：判据表准入（在册 + ≥2 负控 + 整表自检干净）、**改写引文按语义通过**
（并断言调用记录在场、prompt 里有那句反向纪律）、**结论强于来源仍不通过**、
**没有缝 ⇒ 没查**（既不是通过也不是不通过）、**坏 JSON ⇒ 没查**。
