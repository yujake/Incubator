M 那一条是业主②那句的正面回答：一张「这类活 → 收件人 → 起手动作」的决策表，外加

`tests/test_the_conductor_does_not_directly_control_bfv.py` 是**同一条裁定的两侧**：
那边守权限面，这边守"M 的操作手册里写着该换哪条路"。

业主原话里还有半句「如果特别适合该智能体职责**可直接写进前置提示词**」——
**今天的落法是不加**（理由写进 `draft/120` §②）：前置里已经有形状表与伙伴表，
M 那条决策表正是这两张表的**用法**，再写进去就是把同一件事说第三遍。

## 二、skills 这一侧修掉三处「判据/内容自己的毛病」

都不是新功能，是**已有的东西查了个假面、或人眼看不出来**：

1. **`validate()` 查的工具面是假的**。旧口径 `build_registry()`（不带工作区根）
   ⇒ `fs.*` 整组根本不注册 ⇒ `fs.read` 这种**真名**被判成「不在工具面上」；
   而且"注册表里有"不等于"这个角色拿得到"（C/H/V 是只读角色）。
   现在按角色取 `for_role()` 那一份**已过只读过滤**的工具面，并加反负控
   「`fs.write` 在注册表里、但 C 拿不到 ⇒ 必须红」。
2. **slug 那三格没人查**。真机里真出现过一条 slug 是 `" pessimistic-先找边界与反例"`
   （行首一个空格）与一条含空格的 `形式化-能机器核的才签 formal`：`summary` / `when` /
   `body` / 动作 / 工具**全部照绿**，而盘上会多出名字带空格的 md、索引里两条的差异
   人眼看不出来。现在机器查（非空 / 无空白 / 能当文件名 / 全目录唯一），两条已改名。
3. **shared 两条 skill 给 M 下了做不到的指令**：它们声明用 `table.*`，而 M 的工具面里
   **没有**库表类工具（只有 `conductor.*` 与 fs 那几件）。改为声明人人都有的一件
   （`fs.read`），正文里写明「库表工具在多数角色手上、主控用 `fs.read` 读同一份 JSON」。

判据：`tests/test_agent_skills.py` 8 条 → **14 条**，六条反负控（虚构动作 / 越权动作 /
`when` 空 / 工具不在本角色面上 / slug 带空白 / slug 重名）；另加"目录必须覆盖
`shared` + 十个角色每一格"（少写一个键以前是静默的）、"索引只列自己 + shared"、
"M 那条决策表必须写着两条间接链且不许把 F/V 列成能直接派"。

提示词版本 p106 → p107；面快照重冻并**逐格走查**：差异 10 条 = 十个角色的 `prompt`，
每条只多出自己新增的那几行索引（A/C/D/F/G 各 +2、M +1；B/E/H/V 只有 shared 未变），
`actions` / `tools` / 边 / 计数等其余各格逐字未动。

## 三、① 的最后一处漏网：`runflow` 也走价目表了

`agentflow run` / `runflow.run_topic` 那条路此前**不走价目表** ——
`modelcost.price_of` 只读环境变量与缺省价（0.27 / 1.10）。于是同一个工作区里，
多智能体那条按厂商价目表算、单跑那条按旧缺省价算，**两个数字都自洽、谁也不会报错**。

- 「从配置里读厂商与模型」收成**一处**：`modelgw.vendor_model_of`（含"没配 vendor
  就按 `base_url` 的**主机名**认一家"——不给子串匹配留后门）；
  `price_of` / `price_of_full` / `llmseam._price_now` 都走它（此前 `llmseam` 里抄了一份、
  `modelcost` 那份干脆没有）。
- `runflow` 改成按**这一趟自己的时间戳**取价（`price_of(cfg, at=stamp)`）：跑在低谷、
  收尾时已进峰值的那一趟，读墙钟会被整趟按峰值计价，而账面上看不出来。
  `is_peak` 也因此开始收 ISO 串（调用方手上就是那个串）。
- 新判据两条：`test_the_two_number_price_also_knows_the_vendor_and_the_clock`、
  `test_the_run_prices_at_its_own_timestamp_not_the_wall_clock`（含反真空：峰值那趟
  必须是低谷那趟的两倍）。
