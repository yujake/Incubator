## 一、逐页核对逮到的产品缺陷：验收页正文里的 markdown 记号

真浏览器打开 `/acceptance`，正文里有 2 处 `**`：`「该问的问了」这条**没查成**（不是通过…）`。
出处不在前端，而在后端 —— `src/agentflow/reviewaccept.py` 写给人看的 `details[...]` 文案里
带着 markdown 记号，而验收页把 `acc.details[k]` **逐字**打印，JSX 又不解析 markdown，
于是用户看到的是多出来的星号。

修法：把这 7 行文案里的 14 个 `**` 去掉（**只动文案，判据键名与 pass/fail/unknown 逻辑
一个字节都没动**）。改的是 `reviewaccept.py`：38 / 54 / 103 / 206 / 220 / 224 / 371 七行。

判据：`tests/test_review_acceptance.py` 新增
`test_no_user_facing_reason_string_carries_markdown_markers` —— 按 AST 取该模块的
"非文档字符串"常量，断言里面没有 `**…**`（注释与 docstring 不上屏，不算缺陷），
并带负控（取样文件正文里的记号必须报出来）。放在这一组，是因为
`webui.readers.acceptance_face` 是验收页那几句话的唯一产出方。

## 三、顺带逮到三处"从没跑过所以没露"的判据缺陷（都在同一个文件里）

本模块此前一次都没执行过（没装 playwright ⇒ 整模块 skip），所以下面三处一直躺着：

1. `_workspace` 夹具挂着 `@contextmanager` 却写 `return root`（生成器里 `return` 等于立刻
   收工）⇒ 每条用例都在 `with` 那一行炸 `TypeError: 'WindowsPath' object is not an iterator`。
   改成 `yield root`。
2. 收工顺序错了：`with _sync.sync_playwright() as pw:` 包着 `yield`，生成器一 `yield` 就出了
   那个 `with`，用例跑完恢复时驱动已经 `stop()`，`browser.close()` 于是报
   `Event loop is closed!` —— **每条用例都在收尾时炸**，看上去像产品缺陷，其实是夹具。
   改成显式 `start()/stop()`：先关浏览器、再停驱动、最后关服务。
3. `audit.read(root)` 这个函数**从来不存在**（真名是 `audit.read_actions`）⇒ 5 处调用一并改正。

另外两处原先 `skip`（"Machine 页还是 W0 空壳"）的判据**已经过期**（R81 起设置表单、
停机按钮都在），这一轮换成真断言：
- 设置表单那一格既不回填、也不明文上屏（真 key 写盘之后整页 HTML 里一个字都没有）；
- 叫停要按两下：第一次只"上膛"（盘上零改动、台账零行），第二次才落停机开关。

为了让第二条能成立，顺手把 key 那一格从 `type="text"` 改成 `type="password"`
（`ui/src/pages/Machine.tsx`，**key 只写不读**这条纪律的另一半：不回填 ≠ 不上屏），
并在 `tests/test_webui_pages.py` 的那条设置面板判据里加一行静态断言钉住它。

浏览器起不来时仍旧 `skip`（unknown 不是 pass）：`_launch_kwargs()` 先读盘上有没有
playwright 自带那份 chromium，没有就用本机 Edge —— **不在同一个 `sync_playwright()` 上下文里
"先失败一次再换一条"**，那样会把驱动的事件循环搞废（实测过一次：11 条判据全红）。
