R95（goal 第 1 轮）：引文回验分两档 —— 逐字命中 / 语义相同（数据模型 + B 的登记入口）

业主 2026-10-14：「回验不应该是十分呆板的逐字验证，而是保持语义相同即可」，
并裁定落点是 **B 唤起 H**（「允许 B 和 H 协作，B 唤起 H」）。这一轮先落**不动权限面**的
那一半：把"通过"这件事拆成一对自洽的栏，并让写入口说实。

## 一、两栏的分工（`schema.py`）

- `quote_verified`：三态**结论**（True 通过 / False 不一致 / None 还没查）—— 口径没变；
- `quote_mode`：**通过的方式** —— 新栏，受控词表 `QUOTE_MODES = ("verbatim", "semantic")`：
  `verbatim` = 逐字命中（`quoteverify.check_quote` 那一档，不花模型钱，先走它）；
  `semantic` = 语义相同（交给 H 判：引文与来源**说同一件事**即通过，允许改写、换记号、
  跨语言；「结论强于引文」仍判不通过）。

`_normalize_quote_mode()`（`Relation.validate` / `Statement.validate` 共用）把两栏摆成
自洽的一对，三条：

1. `True` 而方式空 ⇒ **记实成 `verbatim`** —— 这一栏是今天才有的，在那之前
   `quote_verified=True` 只可能来自 `check_quote`（逐字那一档）：是历史事实，不是默认值。
   判据 `test_a_legacy_external_lit_row_keeps_its_citation_credit` 早就在钉这条读法，
   所以旧行**不被追溯性降级**（真跑：evidence_bits / statements_table / closing_gate /
   schema / bits_producer 共 176 条全绿，零 fixture 改动）；
2. 不是 `True`（`False` / `None`）⇒ 方式一律归空串（方式对"没通过/还没查"没有意义）；
3. 词表外的值 ⇒ 拒收（"两栏不许互相冒充"这条靠它兜住）。

## 二、读侧的唯一边界（`evidencebits.quote_state()`）

四态字面量：`verbatim` / `semantic` / `mismatch` / `unchecked`。两条要紧的：

- `True` + **认不出的词** ⇒ `unchecked`（说不出怎么通过的，不算查过）；
- `True` + 空 ⇒ `verbatim`（历史行，同上）。

`bits_from_row` 与"哪些命题算干净引用对象"（`clean_statement_ids`）都改走它 ——
于是**语义档一样能拿到引用学分**，而理由那一栏会把两档说开（"逐字核过" /
"语义核过（H 判：与来源说同一件事）"），读的人不必去猜"核过"是哪种核过。

## 三、写入口说实（`agent_b/`）

- `run_once.py`（逐字那一档）：`quote_mode="verbatim" if chk.verified is True else ""`；
- `core.py` 的 reprocess 修补路径（同样是 `check_quote` 之后写 True）：补 `"quote_mode": "verbatim"`；
- `register_statement.py`（`--subagents` 下模型真正走的那一件）：新增 `quote_mode` 入参，
  写进 payload 与返回值 —— 语义档就从这里进来（H 判完回填的那一步在下一轮）。
