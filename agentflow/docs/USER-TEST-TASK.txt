审阅并 polish 这篇论文。它是**外部论文**（别人写的，未发表）：out/paper/main.tex 是你可以改的主稿，source/ 是只读基线（一个字节都不许改）。

按这个顺序做，每一步都要有读数：

1. 先看清盘上有什么（fs.list / fs.stat / fs.read 是你自己的眼睛）：out/paper/、source/、code/ 三处都要看；main.tex 约 26 KB / 475 行，分段读进来（fs.read 支持 start_line / max_lines）。
2. **派活之前先看对方的动作表**（conductor.role_spec(role_name="A") 等）——按动作表里真实存在的名字派，不要凭印象写动作名。
3. 登记这一步分两件，**两件都有明确的指向**：
   （a）把 **source/ 里那份论文本体**（source/main.pdf）登记成 literature 行 —— `pattern` 指到它本身（`*.pdf`），不要用通配把整个目录扫进来。
   （b）把论文里的定理与证明登记进命题台账：`source_lit_id` 必须是**论文那一行**的 lit_id；**还没逐字比对的命题不要传 `quote_verified`**（三态：不传 = 还没查），并在 `quote_reason` 里写清为什么还没查。
4. 派 G 用 build_document 另起一行「我方修订稿」（claims 的 citations 引论文那一行的 lit:）。**注意**：`evidence_kind='cross_check'` 的断言必须自带那句逐字常量「数值交叉验证，不构成证明」（拿不准就用 `heuristic`，别在这上面反复试）。
5. **把正文真正改掉**（这是 P2）：逐字定位要改的几处，**用 `fs.edit`**（`path` + `old_string` + `new_string`，一次一处、不命中就拒）。**不要**用 `fs.write` 重写整份大文件（真机实测会被输出额度截断、整趟作废）。
6. 派 H 审我方稿件（doc_id 用**我方稿件**的 id）；H 落了发现就派 G 修。
7. **让论文包跟上台账**：派 G 走 **`G.paper_package`** —— 它一次做完「重渲染 → 重编译 → 核锚」并回报 verdict 与漂移条数（`project` 给项目根 `"."`）。**不要**指望 `G.revise` / `G.render` / `G.refresh_markdown`：它们动的是稿件 markdown，不是论文包（真机实测：连派三次 revise，`main.pdf` 与锚文件一个字节都没变，锚必然 drifted）。
8. **关键取舍用 ask_user 问一次，然后停下等回答**：把当前状态与「卡在哪」写进报告，不要在没有回答时当成默许继续 —— 框架里会有人回答你，回答回来之后可以续跑。
9. 你自己把交付说明写到 out/review/REPORT.md（fs.write；重写要 overwrite=true）。**它必须是九节**：一、任务与范围 / 二、逐条读数 / 三、定理与引理清单 / 四、形式化覆盖 / 五、引文核验 / 六、体例与表述 / 七、我们做的补救 / 八、未决问题 / 九、诚实边界；**每一节都要有读数**（数字或台账行号）—— 没有内容的节也要写清依据（例如「本轮未做形式化核验：formal 级实验 0 条」），**空标题不算交了这一节**；并**分栏**写「我们补的」与「原文的」，报告里要出现 `origin=own_result`、`依据`、`sha`。
10. 收工前用 conductor.closing 自检：`project_dir` 给 `"."`（项目根），`report_path` 给 out/review/REPORT.md。它会把缺的节名逐个报出来 —— **按它改到 report_shape 过为止**，再把 can_close / failed / unknowns 原样写进交付说明。
11. 留出最后几步做第 9–10 步：报告没写出来等于没交。

不许把没做的事写成做了；拿不到读数就写「未核到」并说明卡在哪一条。目标变更（例如把「审这篇论文」改成「研究一个新问题」）必须先 ask_user。
