# 成文流水线：从依赖链到论文（彩排经验）

> 这不是规范条文，是一份**经验记录**：2026-11-26 的彩排里，我们把「依赖链驱动的成文路径」
> 从设计走了一遍（真台账副本 + 真产品入口 + 机械拼装 + 逐条对齐），这里记下**真读数**与**踩过的坑**。
> 读者：G（写论文的角色）与维护者。

## 0. 一句话

论文的骨架不是"先写引言再补定义"，而是**先算出这条证明链，再按链的顺序铺条目**：
C 给出顺序 → G 按顺序分章编号 → 对应表逐行指回台账与文件 → 拼装 → 逐条对齐。
彩排证明：前三步今天已经有实现（C 的 `proof_path`、B 的依赖面、G 的 MAPPING），
难的不是算法，是**每一步都要能被复算**。

## 1. 流水线五步

| 步 | 谁做 | 今天靠什么 | 产出 |
|---|---|---|---|
| ① 算链 | C | `agent_c/proof_path.plan_path(targets, ...)`（纯函数）→ `analysis.register_report` 落库 | `order`（逐位）、`roots`（四档）、`excluded`（及原因）、`choices`（选路及理由）、`checked` |
| ② 分章 | G | 语义自由：章可重排、可按主题合并 | 章序 + 每条的 `plan_index`（路径里的位次） |
| ③ 重编号 | G | 按"章.序"重排：`definition:1.1…` / `theorem:2.2` / `theorem:3.1` | 正文 label |
| ④ 对应表 | G | `papermapping.Row`：文中条目 → `ledger_id` → `file`（+ 穷举程序 / 形式化程序两列） | `MAPPING.json` |
| ⑤ 对齐 | G（可机械） | 四查（见 §5） | 对齐读数（0 问题才算成） |

## 2. C 的输出怎么读（真读数）

彩排目标：`000024`（Erdős–Rado 第二定理）+ `000021`（admissible 列核心）。真台账副本 71 条命题 / 44 条依赖。

```
order(15) = lit:000000 → 000011 → 000028 → 000021 → 000002 → 000004 → 000005 → 000009
            → 000014 → 000001 → 000013 → 000016 → 000012 → 000018 → 000024
roots      = lit:000000（引文成果）+ 8 条定义（root_tier=definition）
excluded   = 000026「不是任何目标的前提：它反过来引用了路径上的 Intersection Theorems…」
             000034/000035/000038/000039/000040「…但没有任何目标用到它」
             exp:000000「只服务 设整数 r ≥ 4 …」
```

要点：
- **`excluded` 必须读**。它回答"为什么某条不进论文"——彩排里正是靠它确认"兄弟分支不进正文"。
- **`order` 里的目标可能不在末尾**：`000021` 是目标之一，但它闭包小，排在第 4 位。
  这不是错，是"多目标按闭包大小排"的后果；**分章时由 G 把它挪到自己的章**（见 §3）。
- **深度是事实**：这张真台账只有 2 层（目标 → 两条 `Theorem I/II` → 定义），
  因为 B 的稿基本自足、正文里只出现 `Theorem II`/`Theorem I` 短名。
  **链的深度不由算法决定，由稿子里真有没有引用决定**；别为了让深度好看去伪造边。

## 3. 分章的边界（G 的自由度与硬边界）

允许：
- 章可以重排（彩排把章排成：定义 → 引文定理 → 主目标 → 另一目标）；
- 长篇可按主题合章；概念不必全堆在开头（用到的才写，且**第一次用到之前**出现）。

硬边界：
- **章内顺序必须守 C 的路径顺序**（依赖在前、使用在后）。彩排把 `000021` 从第 4 位挪进自己的章，
  但它在那一章里的相对位置仍照路径；
- 任何一次重排都要**留痕**：对应表里同时给 `plan_index`（路径位次）与正文顺序，
  报告里写清"这是分章自由度，不是偷偷改 C 的结论"。

## 4. 重编号与对应表

规则（彩排用的）：
- 环境按条目种类：`definition` / `theorem` / `lemma` / `proposition` / `citation`；
- 编号 = 章号 + 章内序，**章内序就是叙述顺序**；
- 定义行**没有证明稿**（这是它与定理行的区别），但**必须有 `ledger_id`**；
- 定理行必须有：稿路径 + 证明正文 sha（今天多一列"台账里的 proof_sha"便于对拍）。

真读数（15 行，0 对齐问题）：

```
citation:2.1   lit:000000   000006/erdos-rado-1960-….pdf
definition:1.1 stmt:000011  —（概念行：正文取 statement_full）
theorem:3.1    stmt:000024  manuscripts/B/b-proof-000005.md
theorem:4.1    stmt:000021  manuscripts/F/f-proof-000000.md
definition:1.10 stmt:000012 —（第 10 条定义，排在第 1 章末）
```

一个细节：**定义 1.10 落在章末、却被 `000016` 用到**——说明"章内顺序"是按路径给的，
不是按"定义都在最前"给的；这正是"不必把概念堆在开头"的落地形态。

### 重编号只在"顺序"上受约束，章边界由 G 定

设计里那张示例编号（概念1.1 / 概念1.2 / 引理3.1 / 引理3.2 / 定理3.3 / 概念4.1 / 引理4.2 / 定理4.3）
是**一种**分章方式，不是唯一答案。判据要求的只有两件事：

1. **编号随叙述顺序严格递增**（同章内）；
2. **章内顺序守路径**（依赖在前）。

实测（例 3 的夹具，`tests/_proof_path_fixture.py::EX3`）：C 给的顺序是
`概念1 → 概念3 → A → C → E → 概念2 → B → D`，与设计逐位相同；
若按"定义进第 1 章、其余进第 3 章"编号，得到 `definition:1.1/1.2、lemma:3.1/3.2、theorem:3.3、
definition:1.3、lemma:3.4、theorem:3.5` —— 单调、可复算、与路径一致；
设计示例把 `概念2` 之后的条目另起第 4 章（`概念4.1、引理4.2、定理4.3`），同样合法。
**两种编号都对**，区别只在章边界；对应表记的是"文中条目 ↔ 库号 ↔ 文件"，所以无论怎么分章都追得回。


## 5. 机械拼装的坑（彩排真踩的）

把台账里的纯文本直接拼进 `.tex` 会炸，按顺序踩了三层：

1. **LaTeX 特殊字符**：`X_P`、`|S|%` 里的 `_ % & #` 必须转义，**但 `$...$` 里的不转**（会破坏数学）；
2. **Unicode 数学符号**：`⊆ ∩ ∪ ≥` 等要映射成宏（`\subseteq` 等），**且映射要区分数学内外**——
   在 `$...$` 里塞 `$\subseteq$` 会嵌套失败（彩排的第三版就死在这里）；
3. **中文**：需要 `ctex`（或 xelatex + fontspec），否则中文与中文标点全报错。

诚实结论：**彩排的 tex 生成正确、对齐正确，但尚未编译通过**。
真实写作是 G 自己写 LaTeX，这一层本就该由 `doc.paper_compile` 的 `problems`（含 `main.log` 的
overfull/underfull/未定义引用）与 texaudit 的结构判据来兜——机械拼装只是彩排省钱的替代品。

## 6. 对齐四查（每行都要过）

1. 对应表写的 `file` == 台账 `statements.manuscripts` 里登记的那条路径；
2. 那份文件**在盘上**；
3. 证明正文的 sha256 == 对应表里的 `sha256`（彩排还多核一列"台账 `proof_text` 的 sha"）；
4. 那段证明正文**真的出现在 tex 里**（子串命中，防止"表里写了、正文没拼"）。

彩排结果：15 行 × 四查 = 0 问题。这条不能省——它是"对应表真实"的唯一证明。

## 7. 给 G 的自检清单（判据句，不是配额）

- 落笔前：**读 C 的报告**（`analysis_reports` 里 `proof_chain` 那条），它的 `order` 决定条目的先后；
  `excluded` 里每一条都要能在论文里说清"为什么不写它"（至少心里有数）。
- 分章：可以重排章，**但章内顺序照路径**；重排要记在对应表里（`plan_index` + 正文位置两列）。
- 每个条目：先问"它在链里被谁用到、在第几步"——**没被用到的条目不写进正文**（除非它是目标）。
- 每条定理：对应表必须指到**稿路径与 sha**；定义行指到 `ledger_id` 即可（没有稿是对的）。
- 拼装/引用：引一条定义时，用它在正文里的编号（重编号后的），并在对应表里能追回库号。
- 交稿前：跑一遍对齐四查（哪怕手工），**表与正文互相指不上的，一律先修表或修正文，不许留**。
