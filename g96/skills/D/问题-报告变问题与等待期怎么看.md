# 问题从哪来、什么时候推进、在等的时候看什么

- 名字：`问题-报告变问题与等待期怎么看`
- 属于：`D`
- 什么时候读它：拿到一份 C 的分析报告、判一个问题证据够不够、或要看在等的那几条请求有没有答上问题时
- 一句话：报告→问题（去重靠 merged_origins）、证据够就推进、等待期用三态判「新证据答上了吗」
- 会用到的动作（角色.动作）：D.ingest, D.ingest_detailed, D.consider, D.assess, D.submit_gaps, D.poll, D.research
- 会用到的工具：table.get, table.list, table.search, table.update, fs.read

# 问题的三段：从哪来 → 推不推 → 在等什么

## 一、报告 → 问题：`D.ingest`

`D.ingest(report, c_contradictions=…)` 把一份 **C 的分析报告**消化成研究问题，
返回**新建的** `question_id` 列表。

⚠️ **"命中等价问题所以没新建"与"新建了"必须能区分**：命中等价时它不新建行，
而是把这一次的来源并进原有那一行（写成 `merged_origins: …`）。
所以"返回空列表"**不等于**"这份报告没用"——它常常是"这条题我们已经有了"。
要逐条看过程（含**被跳过的那些及原因**）用 `D.ingest_detailed`。

## 二、推不推：`D.consider`（这一格缺了会静默卡死）

`D.consider(qid)` 是状态机里"**评估 → 分支**"那一步：

- **证据足够** ⇒ 把问题推进到 `researching`（下一步就该写结论了）；
- **证据不足** ⇒ 交给 `D.submit_gaps` 去提问（它会查重与看预算）。

**为什么这一格必须存在**（不是设计洁癖）：早先"足够"那一支**什么都不做**，
问题就永远停在 `open`；而 `D.research` 只处理 `researching`
⇒ **证据充足的问题永远不会被研究、也永远不会出现在报告的"现有证据"一节里**，
表现为"D 溯源为空"。那不是工具没接上，是**状态机少了一条边**。

## 三、在等的时候：`D.poll`（三态，别折平）

`D.poll` 检查等待中的请求，把**就绪**的问题拉回 `researching`。它只依据三样**落盘**数据判定
（请求的 `done`/`outcome`、文献的 `processed`）—— 因此不需要模型，也不会随措辞漂移。

**但它不止判"消化完了"，还要判"新证据真的回答了那个问题吗"**：
该请求带来的新落库关系交给 `interactions.evidence_relevance`：

| 读数 | 怎么办 |
|---|---|
| `relevant` | 就绪 ⇒ 拉回 `researching`，并入新关系/文献 |
| `irrelevant` | **不推进**，notes 记 `evidence_arrived_but_irrelevant`，并把该问题优先级降一档（high→medium→low，**low 不再降**） |
| `checked=False` | **不推进**，只记 `evidence_relevance_unchecked` —— **绝不写成一个看起来像结论的"不相关"** |

**为什么这条三层不能折成两层**：旧判据（请求 done ＋ 文献 processed）只说明"消化完了"。
折平的后果是：**一个查不到东西的问题会反复触发同一件事的检索**，把 A 的产能烧在同一个空洞上。

⚠️ **`relations=None` 与 `relations=[]` 是两件事**（这是本动作的第三态）：
前者是"**调用方拿不到关系快照**"（没查），后者是"查了、这批文献**没带来新关系**"。

⚠️ **矛盾问题（`kind="contradiction"`）不降优先级**：它的优先级来自"知识内部可能互相冲突"
这一事实，不会因为一次检索落空而变得不重要；I2 的收敛靠**轮数上限 ＋ 全局配额**，不靠降优先级。
所以那一类只记笔记、不动 priority。
