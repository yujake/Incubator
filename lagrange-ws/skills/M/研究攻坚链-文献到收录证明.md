# 研究攻坚链（文献 → 图 → 候选路径 → 猜想 → 攻坚 → 走查 → 收录证明）

- 名字：`研究攻坚链-文献到收录证明`
- 属于：`M`
- 什么时候读它：任务是「探索某定理的更短证明路径」、或要拿一条可判结论（猜想/证明级断言）的时候；以及一条链走到一半、要判断下一跳派不派得出去的时候
- 一句话：七跳定序（检索→图→候选路径→猜想→攻坚→走查→收录）；跳一步要写明理由，读数以台账为准
- 会用到的动作（角色.动作）：A.search_literature, B.run_once, B.register_statement, C.handle, D.propose_question, E.run_experiment
- 会用到的工具：conductor.summon, conductor.ledger, fs.read

# 研究攻坚链：文献 → 图 → 候选路径 → 猜想 → 攻坚 → 走查 → 收录证明

**顺序即语义**，七个跳一次都不许调换（这一行就是那条链本身）：

A → B → C → D → F → V → B(收录证明)

这一段链是"研究攻坚"那一类活的全貌：从一个开放问题出发，把文献变成图，从图里看出
"可能的更短路径"，把候选立成可判猜想，逐轮攻坚，证明由 V 走查签成立，
最后由 B 把**证明**收录成命题落库。

⚠️ 链上有**两个 B**，它们是两件不同的活：前一个 B 把文献消化成概念与关系（把图建起来），
后一个 B 把 V 签过的证明收成一条命题（把证明落库）。把它读成"B 只做一次"，
这一条链就断在最后一跳上了。

## 每一跳的四件事（入口条件 / 产物 / 出口判据 / 卡住时怎么办）

| 跳 | 入口条件 | 产物（落到哪张表/哪一格） | 出口判据（什么算这一步做完了） | 卡住时怎么办 |
|---|---|---|---|---|
| **A** 检索 | 问题已翻译成该方向的规范术语（题面式说法不算入口：查不到不等于没有） | 待新增文献列表（每委托重置，可增/删/查），审完**一键迁移 ≤10 篇**进 `literature` | 入库 ≤10 且报告里"已入库（含一句摘要）/未入库（含筛除理由）"两块都在 | 拿不到就写 `unresolved`，不许拿"没搜到"当"不存在" |
| **B** 概念与关系 | 已有入库文献 | `statements` 一行一条（`kind=concept`）＋ `relations`（`kind` / `quote` / `quote_verified` 三格） | 关系能回答"这两个概念什么关系、凭哪一句原文"；**空边不许产出** | 抽不完就报"未抽取 K 篇"，不许假装抽完 |
| **C** 关系分析 | 图上已有概念与关系 | `analysis_reports` 一条：**候选的更短路径** ＋ **关键那一步是什么** ＋ 为什么因此更短 | 能说清"删掉/替换掉哪一步" | 图太空就如实写"数据未抽取，算不出"（回头要 B 补抽），不许硬编候选 |
| **D** 立可判猜想 | C 报了候选路径（**C 的那份报告已经在盘上**） | `conjectures` 一条，`testable` 非空且写清"若成立则省掉哪一步" | `testable` 是**可执行/可判**的（不是"值得研究"这种） | 立不出就逐条写"C 的哪一条为什么立不出"，不许跳过不读 |
| **F** 攻坚 | 有一条 `testable` 猜想 | `attack_plans` 的 `history` 每一轮一个受控产物：reduction / proof / counterexample_request / dead_end | 每一轮都让**卡点更具体一步**；`no_change` **不是产物** | 走不通落 dead_end：写清卡在哪一步、缺什么才能往下 |
| **V** 走查 | F 交出了证明级断言 | `verifications/<命题号>.jsonl` 一行（`verdict` / `unresolved_errors` / `proof_sha256`） | 只有「成立」且 `unresolved_errors=0` 才算签过；**先判哪一步承重**并指出步号与原句 | 签不了就让它空着，不许拿"我大致看过了"补 |
| **B** 收录证明 | V 已签「成立」且 `proof_sha256` 与现行正文相符 | `statements` 一行：`evidence_kind=proof_review`、`proof_text` 逐字、`origin=own_result` | 走 B 自己的入库正路（工具名逐字 own.register_statement）：同一份内容再交一次即**就地升档、不新建行**；`bits` 由秘书算 | 闸拒收就把**拒收理由原话**写进报告，不许硬降档、不许虚报 |

## 三条调度纪律（这一节才是"怎么派"）

### 一、顺序不许跳

C 没出报告就不要派 D；D 没立出猜想就不要派 F（F 那一腿由 D 开：`M → D → F`，
你手上没有到 F 的边）；V 没签就不要让 B 写成 `proof_review`。
**跳过哪一步必须写明为什么跳过** —— 写进 `conductor.summon` 的 `task` 里，
不是写在自己的想法里：下一跳的人只能看到那一格，看不到你为什么跳。

### 二、要回头

C 的报告**落盘之后必须回头再派一次 D**（第一轮常常是 D 在 C 之前被派掉的，等于没读）；
同理 B 报"未抽取 K 篇"时，要判断 K 是否挡住 C 的分析 —— 挡住就先把 B 补抽那一条派回去，
别直接把一张残图交给 C。

### 三、每一跳只信盘上读数

`conductor.ledger` 核它动没动；"交回了什么"以台账为准，不以汇报措辞为准。
汇报里写"已入库/已抽完/已签过"，而台账那一行没有 ⇒ 这一跳**没发生**。

## 一条反面（这一条最贵）

把整条链当成"派七个活"：每一跳都派出去了，却没有一处读盘上的产物。
表现是账面上十几次调用、每一跳都"交回了"，而 `literature` / `relations` /
`analysis_reports` / `conjectures` / `attack_plans` / `verifications` / `statements`
挨个看过去全都没长 —— 链的语义在**产物之间**，不在派活次数里。
