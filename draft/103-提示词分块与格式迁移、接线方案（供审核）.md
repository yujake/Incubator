> 每一条"现状"都指到 `文件:行号`。上游：`draft/101`（DSH 怎么写的 + 我们的读数）、

## 0. 一句话结论

这件事是**三条互相独立的轴**，必须分开做、分开验收 —— 混在一起做，就没有任何一条判据能说清"到底动了什么"：

| 轴 | 做什么 | 文本会变吗 | 硬判据 |
|---|---|---|---|
| **A 分块** | 六个大段切成块（段名 + order 现算） | **不变（逐字节）** | 十角色 `prompt_sha256` 逐格不变 |
| **B 迁移** | 手写文本从 Python 常量搬进预设目录（YAML + md） | **会变** | 原行守恒 + `PROMPT_VERSION` bump + 重冻 |
| **C 接线** | composition 行 → 段；instructions / contexts → user 消息 | 不变（新通道默认空） | 三态 + 预算 + 追加式 |

三条轴的**依赖方向**是 A → B → C：先有块（A）、块才谈得上"哪些块由文件给"（B）、
文件才谈得上"由哪一行挂进来"（C）。倒过来做（先接线）会得到一个"能挂但内容仍在代码里"的空壳。

**为每个智能体定制**这件事在数据上已经存在（§1.4 的实测：C 的边是空的、D 的次要官能是空的、
H 没有政策、M 没有姿态、V 有两套提示词），只是今天由 Python 的 `if` 表达；
本方案的 C 轴把它搬成**每个角色一份 composition**（§5 逐角色给组合）。

### 1.5 接线缝在哪（真实调用链）

复跑：`grep -n "ask_step\|system = \|_prompt(\|_maybe_compact" src/agentflow/agent_loop.py`。

```text
agent_loop.py:2690   run.prompt_audit = AP.prompt_audit(role, registry=…, **facts)     ← 审计读数（整份进 runs/*.json）
agent_loop.py:2691   system = AP.system_prompt(role, registry=…, **facts)              ← 每趟**算一次**
agent_loop.py:2699   messages = [user_message(_opening_transcript(…))]                 ← S-C 裁定 5甲：开场是第一条 user 消息
agent_loop.py:2871   messages = self._maybe_compact(messages, step=step, run=run)      ← 步边界上的压缩（在 ask_step 之前）
agent_loop.py:2872   data, call = self.seam.ask_step(self._prompt(messages, step=step),
                                                      system=system, task_id=…, face=face)
llmseam.py:512-525   ask_step(prompt, *, system="", …) → ask(prompt, system=system, …)
```

三条结论（决定了 C 轴怎么接）：

1. **段通道是"每趟算一次"**：`system` 在步循环之外算好，每步原样传下去 ⇒
   **在 `system` 里加块不会破坏 cache**（一趟之内是常量），但**跨趟**变了就会变。
2. **动态内容只能走 `messages`**：`instructions`（工作区指令）与 `contexts`（运行时快照）
   都必须是 user 角色消息，落点就是 `messages` —— 与 DSH 的分类逐字一致
   （段进 system，快照与工作区指令进 user 消息）。
3. **落点有两个**：开场（`:2699`，基线）与步边界（`:2871` 附近，增量）。
   压缩（`_maybe_compact`）在增量之前跑，所以"新到的指令"不会被刚压过的历史吃掉 ——
   这正是 DSH 的追加式纪律（`dsh-agent-instructions/README:181`："newly visible content follows
   the reusable request prefix"）。

### 1.6 端口现状（机制已经搬完的四件 + 两个真缺陷）

| 批次 | 提交 | 内容 |
|---|---|---|
| 1 | `d0d5390` | `promptkit.py` 补**动态上下文**（`Context` / 抑制 / supersede 头） |
| 2 | `12f574e` | `persona.py`：身份两个具名槽位 + `scope` 必填；已接进 `role_prompt_registry` |
| 3 | `4f45aa0` | `presets.py`：目录 = 一个预设、根优先级、坏预设带理由、挂一次 + 生成戳、复制式创作 |
| 4 | `3922e2f` | `instructions.py`：工作区指令的发现 / 去重 / maxBytes 降级 / 转义 / 追加式状态 |
| 5 | `17f06fd` | 预设层改用 **DSH 的 YAML 格式**；`⚠️ requires_human`（`pyproject.toml` 加 `PyYAML>=6.0`，FC-27 待 2 人签） |

两个真缺陷是判据抓出来的（不是推演出来的），它们直接决定 A/B 轴怎么写：

1. `PresetMount.is_stale()`：把"没挂过 + 组装文件不在"（两边都是 `None`）判成**不过期**，
   接着去取一个不存在的挂载值（`KeyError`）。
2. `instructions.render_baseline()`：第一版按"由宽到窄依次装"，于是**更宽的那一份恰好塞得下时，
   最具体的那一份被丢掉** —— 与 DSH 逐字口径相反。

两个缺陷的教训同一条：**"看起来没超预算"与"该装的那一份装进去了"是两件事**。
A/B 轴的判据因此都要"正面读数"（段名清单、sha256、行守恒），不能只判"没报错"。

### 2.3 批一**不许**动 `PROMPT_VERSION`

判据逐字（`tests/test_agent_prompts.py:1487-1489`）：

```python
if not changed and version != frozen_version:
    bad.append("PROMPT_VERSION 动了…而十格摘要一格没变 ⇒ 这一版号在说什么："
```

## 3. 轴 B：格式迁移（内容 → 预设目录）

### 3.1 哪些块能变成文件、哪些必须留在代码里

判据只有一条：**这段文本是"写死的"还是"现算的"**。

| 类别 | 块 | 为什么 |
|---|---|---|
| **必须留代码**（现算） | `FACULTIES`（现算三档，`faculties_text`）· `PARTNERS`（现算边/参数/接线态，`partners_lines`）· `TOOL_xx`（现算工具面，`tools_lines`）· `OUTPUT_CONTRACT`（现算动作表，`actions_lines`）· `TOOLCHAIN_FACTS`（这台机器的读数）· `WORKSPACE_FACTS`（版本与表名）· `TASK_FRAME`（这一次的运行时事实） | 它们的正文由注册表/能力表/磁盘现状决定。搬进文件 = 允许文件与事实各说一套，而那是本仓反复记过的那类缺陷（`draft/34` §3 的"必须生成"一栏） |
| **可以变文件**（写死的） | `ROLE_BRIEFS` 的六格（职责 / 边界 / 政策 / 姿态 / 签名错误 / 交付物）· `LOOP_PROTOCOL` · `PAPER_PACK` · `EVIDENCE_CONTRACT` · `HANDOFF_PROTOCOL` · `THREE_STATE` 的固定半 | 它们是手写散文；今天改一句话要动 Python 源码并重跑全量测试 |

**一张不变式**（A 轴与 B 轴的交界）：文件给的块与现算的块在装配后必须**互不覆盖** ——
同一个段名两次注册会抛（`promptkit.py:214-219`），所以"文件写了 `ROLE_BOUNDARY`、
代码又想生成 `ROLE_BOUNDARY`"这件事会**注册即炸**，不是静默后写赢。

### 3.3 与 DSH 的一处刻意偏差：**共享块不复制**

DSH 的预设是"整份复制"，它自己承认代价（`dsh-agent-presets/README:179` 逐字）：
"A copy is a snapshot that drifts … there is no patch semantics at this layer to express
'standard plus one change'"。它随包的 `cordis` / `code` 就是把 standard **抄一遍再改**。

我们**不照抄这一条**：十个角色的提示词共享三大块（证据契约 / 手稿协议 / 循环协议），
而它们是同一份判据、同一个来源（引文回验、手稿编号、三态词表）——
复制十份等于把"改一处、漂九处"制度化。所以：

- **共享块一份**（`_shared/`），每个角色的 composition 用**相对路径**引用；
- **角色专属块**每个角色一份（`blocks/`），它们本来就该各写各的；
- 漂移由一条判据守：`_shared/*.md` 的每个文件都必须被至少两个角色的 composition 引用
  （一个都不引用的共享文件 = 死文件；只有一个角色引用的共享文件 = 该搬进那个角色的 `blocks/`）。

这与 `draft/102` §2.2 的 order 表不冲突：order 是**渲染顺序**，引用是**内容来源**。

### 4.2 段通道（静态）：`role_prompt_registry` 变成"挂预设"

今天：`role_prompt_registry(role, registry=…, **facts)` 里**硬编码**了全部注册
（`agent_prompts.py:2004-2143`）。

改后：

```python
def role_prompt_registry(role, *, registry=None, **facts) -> PromptRegistry:
    preset = role_preset(role)                 # presets.discover(...) 找这个角色的预设
    if preset is None or preset.broken:        # 找不到 / 坏了 ⇒ 回落到内置的代码注册
        return _builtin_registry(role, registry=registry, **facts)
    reg = PromptRegistry()
    _register_variables(reg, role, **facts)    # 变量与今天逐字相同
    COMPOSITION.compose(reg, preset, role=role, resolve=RESOLVERS)
    return reg
```

**回落是必须的**（三态纪律）：预设坏掉时不许"半组装"，也不许让整个系统起不来 ——
落点是"回落到内置注册 + 把回落这件事记进审计读数"（`prompt_audit` 加一格
`preset: {id, path, trust, generation, broken}`）。

### 4.3 user 消息通道（动态）：instructions 与 contexts 的落点

| 通道 | 时机 | 落点 | 判据 |
|---|---|---|---|
| 运行时上下文快照 | 每趟开场 + 每次装配后变了 | `messages` 的**第一条**（在 `_opening_transcript` 之后）或步边界追加 | 空快照不发（`join_context_sections` 返回空串）；被抑制时 `contexts_suppressed=True` 是一个能点名的状态 |
| 工作区指令（基线） | 每趟第一次 `ask_step` 之前 | `messages` 追加一条 user 消息 | `render_baseline` 的 `byte_count <= maxBytes`；空链零 token |
| 工作区指令（增量） | 成功的 `read`/`write`/`edit` 之后**下一步** | 步边界（`agent_loop.py:2871` 附近）追加 | `InstructionState.plan()` 只报 add/replace/remove；`unchanged` 不注入 |

三处共同的纪律（逐字来自 DSH，`draft/101` §4.4）：**追加式**、**新内容排在可复用前缀之后**、
**提供者失败不加消息**（绝不产生半条）。

### 4.4 生成戳与挂一次在接线里怎么用

`PresetMount` 的语义是"一个预设挂一次、戳变了才换代"（`presets.py`）。
在本框架里，"挂"的产物**不能是一个进程级的注册表**（那是 DSH 的 Cordis 模型），
因为我们的 `role_prompt_registry` 每次调用都新建注册表（`agent_prompts.py:2016-2017` 的
逐字理由：混用全局注册表会让两次运行互相看见对方的任务）。

所以接线用 `PresetMount` 的**两件东西**、不用它的第三件：

- 用它：**生成戳**（"这个角色的预设文件变过没有"）与**代数**（`generation`），
  落到 `prompt_audit` 里 ⇒ 事后能回答"这次跑的是第几代预设"；
- 用它：**坏预设拒挂**（`mount` 抛 ⇒ 回落，见 §4.2）；
- 不用它：`_mounted` 那个进程级缓存 —— 我们的注册表是**每趟新建**的（prefix 稳定在
  "一趟之内"这个粒度上，`agent_loop.py:2691` 每趟算一次）。

### 4.5 不做的事

- 不把权限/沙箱/审批搬进提示词（`draft/34` §4）。
- 不为"看起来更强"而给每个角色塞满块：`minimal` 那一课逐字是"整份提示词就是一句 persona"。
- 不让预设决定**哪些工具可见**（那是 `tools/base.for_role` 与 `capabilities.ALLOWED_EDGES`
  的权限面；预设只写提示词文本）。
- 不做"用户可以现场改提示词"的入口（本轮不做；预设是部署面）。

### 5.2 逐角色的定制点（每条都带证据）

**A 检索**（19 工具 / 5 动作 / 出边 1 / 入边 5）
