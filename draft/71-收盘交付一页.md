## §6 写给下一个接手的人（这一批挣到的四条纪律）

1. **判据必须与本机设置解耦**：一台"配好了 key 与工具链"的机器上，一堆断言"没配时"分支的判据会全红（本批 11 条）。钉在 `tests/conftest.py`，守卫在 `test_settings.py`。
2. **被引用的证据物必须入库**：判据在盘上查存在性（`(ws_root / ref).exists()`）⇒ 不入库，一份全新 clone 里那条判据**必然红**。入库按仓库自己的维护约定走（`/temp/*` + 逐条 `!/temp/<名>` 登记），**不用 `git add -f` 绕**；并且要先量一次门的命中数证明没把禁改区的输入藏起来。
3. **改提示词段与抬 `PROMPT_VERSION` 尽量同提交**：分两个提交会在中间留一段"段变了而版本没动"的红（本批 p42→p43 就是这么补的）。
4. **判据里的正则不许有嵌套量词**（`(?:X*Y+)*?`）：指数回溯会把整条门钉死；改完要同时钉"有界时间"与"仍认得出来"两件事。
