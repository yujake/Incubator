> 这份稿子是**从源码逐字取出来的**（生成器 `temp/_dump_role_prompts.py`），不是手抄。生成时刻见文末；每个片段都带 `文件:行号`，可以照着复核。

> **一句话结论**：本框架的 A–H 角色**不是提示词驱动的智能体**，它们是**确定性代码对象**；整仓真正发给模型的提示词只有三处 + 两个角色的私有钩子 —— 也就是说，**「每个角色一份前置提示词」这件事在今天并不存在**。下面把「实际存在的东西」逐字列全，再把「缺它的代价」写在最后一节。

```text

请按两段作答。
第一段：只陈述你确知的实质结论，最多三句，不要罗列参考文献，无法确知的部分明确写“不确定”。
第二段：给出一个 ```lean4 代码块，把第一段里一条可机械检查的断言写成最小形式化。硬要求：① 自包含，只用 Lean 4 核心语法，不要 import Mathlib 或任何第三方库；② 只用核心策略（`rfl` / `decide` / `simp` / `exact` / `norm_num` 之一）；③ 代码块必须能被 `lean` 单独编译通过，所以宁可把断言化成具体的有限计算，不要写需要大量库引理的抽象命题；④ 若你无法给出能通过的代码块，就明确写“无法给出可检查的形式化”，不要写通不过的代码。
```

## 2. 抽取缝的提示词（`AgentB` 的唯一出口，走 `llm.DEFAULT_PROMPT_TEMPLATE`）

出处：`src/agentflow/llm.py` 的 `DEFAULT_PROMPT_TEMPLATE`（`Final[str]`，模板里的 `{LIT_ID}` / `{DOCUMENT_TEXT}` 用 `str.replace` 渲染，不用 `format`）。

```text
你是文献知识抽取器。请从下面给出的文献正文中抽取"概念"与"概念间关系"。

【文献标识】{LIT_ID}

【输入正文】
正文按页给出，页与页之间用形如 <<<PAGE 3>>> 的行分隔。
这些分隔行是定位标记，不属于文献内容，绝对不要把它们写进 quote。

--- BEGIN DOCUMENT ---
{DOCUMENT_TEXT}
--- END DOCUMENT ---

【输出格式】只输出一个 JSON 对象，不要任何解释性文字，不要 Markdown 围栏：

{
  "concepts": [
    {
      "name": "概念名（尽量用正文中出现的原词，不要自行翻译）",
      "definition": "该概念的定义（可以是正文原句的紧致改写）",
      "aliases": ["正文中出现的异名/缩写，没有就给空数组"],
      "page": 1
    }
  ],
  "relations": [
    {
      "concept_names": ["概念A", "概念B"],
      "description": "这条关系说了什么（用你自己的话陈述）",
      "quote": "支撑该关系的原文，必须逐字照抄",
      "page_range": {"start": 1, "end": 1}
    }
  ]
}

【硬性规则，违反会导致整条记录被丢弃】
1. relations[].quote 必须是输入正文里**逐字出现**的一段连续文字。
   允许的差异只有：首尾空白、句内换行、大小写。
   不要改写、不要翻译、不要用省略号截断、不要拼接不连续的两段文字。
2. **如果你无法在正文里逐字找到支撑某条关系的原句，就不要输出这条关系。**
   少输出一条关系是可接受的；编造引文是不可接受的，它会被自动校验剔除。
3. relations[].page_range 必须标出该引文所在的页（依据 <<<PAGE n>>> 标记），
   1-based、闭区间、start <= end。引文跨页时用跨页区间。
   注意：这里的页码一律指 <<<PAGE n>>> 里的 n，也就是这一段正文被切给
   你时的序号；不要用书里印在页眉页脚上的那个页码。两者常常不相等：
   一本有前言/目录/封面的书里，"印着第 3 页"的那一页很可能是 <<<PAGE 8>>>。
   实测（2026-09-28）：一本书的前 12 条关系全部按"印着的页码"报，恒定比
   <<<PAGE n>>> 小 5，于是全部被逐字回验判为 not_found（引文是真的，页码是错的）。
   判据：`<<<PAGE n>>>` 就在你眼前的正文里，印着的页码得你自己去认 —— 用眼前的那个。
4. relations[].concept_names 至少给出 2 个概念名；只有一个概念时不输出该关系。
5. 概念名要与正文用词一致（英文正文就用英文名），不要输出空名或纯符号名。
6. 没有可抽取内容时输出 {"concepts": [], "relations": []}。
7. 条数上限：概念最多 12 条、关系最多 12 条。挑最能代表这段正文的，宁可少而准。
   这条上限不是口味问题：输出的 JSON 一旦超过模型单次回复的 token 上限，就会被截在
   半句上，整次抽取因解析失败而作废（连已经正确的条目也一起丢掉）。
   实测（2026-09-28）：一本 417 页的书连读两次都栽在这里（`Expecting ',' delimiter`），
   把上限从"不限制"收到 12 条之后就不再触发。
8. page_range 里填的是 <<<PAGE n>>> 的 n（见第 3 条），**不是**书里印的页码。
   把第 3 条再强调一次是因为它错得最贵：引文逐字正确、页码错 5 页，回验照样判
   not_found，而读者从产物上看到的是"这条关系的出处找不到"。
```

## 4. 判据类提示词与它们的现状（`judge.judge_json` 是「唯一缝协议」）

`src/agentflow/judge.py` 的头部逐字写着这条协议（`draft/29` §3.1）：

```text
LLM 判定的唯一缝协议：一个函数、一套失败词表、一条"没查成不等于没找到"的纪律。

## 这一层解决什么

`draft/29` §3.1 要求所有角色用同一个 LLM 缝：角色自己不做 prompt 拼装与结果解析的
分支（那是"把智能体写成大程序"），而是调这里的一个函数，拿到
"判定 + 没查成的原因"。原因非空时，调用方必须走确定性回退并把它留痕 ——
既不许当成功，也不许折成"没找到"。

## 三态在这里的落点

`judge_json` 返回 `(dict | None, problem)`，`problem` 为空串才算"查成了"：

- `judge_not_wired`：没接线（`llm is None`）。这是"没查成"，不是"没有这个结论"。
- `judge_timeout`：超时。可以重试，但重试策略在调用方（受预算约束）。
- `judge_bad_json`：返回的不是合法 JSON（LLM 的输出形态不可控）。
- `judge_over_budget`：预算耗尽（由调用方抛 `BudgetExhausted`，或由计量层拒绝）。
- `judge_refused`：判定方明确拒绝（由调用方抛 `JudgeRefused`）。
- `judge_failed:<异常类名>`：其它异常。逐字带上类名，便于事后归因。

为什么把后两个做成异常而不是字符串：字符串靠调用方记得传，异常由本函数当场归类 ——
"记得传"与"结构上必然发生"是两件事（本仓库反复踩过前者）。
```

**实测**：`judge_json` 在 `src/` 里**只有定义、没有调用点** —— `agent_a/f/g/h.py` 的 docstring 都写着「判定必须走 `judge.judge_json`」，但那四处的判据今天是纯确定性代码（`judge_json` 的实参在源码里零命中）。

逐角色的私有钩子提示词已在 §3 里逐字给出（C 两处、D 一处）。

## 6. 我的判断：这份材料说明系统离交付标准还有多远

**结论先说**：**你想要的"各角色前置提示词"在这套系统里不存在**。不是"写得不好"，
是**没有**。A / B / E / F / G / H **六个角色一份提示词都没有**；C 两处、D 一处，
而且都是**可选钩子**（构造时 `llm=None`，默认关闭，有确定性回退）。整仓唯一的
system prompt 是三句话（§1.1），只服务于 `runflow` 那条"主题 → 三句结论"的演示级流程。

这不是"实现漏了"这么简单，它是这套系统的**结构性选择**：角色的边界被定义成
**权限面 + 工具面 + 代码判据**（可机械判、可负控），而不是**提示词**（不可机械判）。
§3 里每个角色"拿到的东西"就是这个选择的产物 —— 它们的"前置" = 工具面 + capabilities
动作 + 模块 docstring 里的契约，而不是一段写给模型看的人设。

按交付标准算，下面 8 条是我从这份材料里读出来的**实打实的缺陷**：

1. **提示词层是空的，而文档承诺了它。** `judge.py` 的头部逐字写着"所有角色用同一个 LLM 缝"，
   `agent_a/f/g/h.py` 的 docstring 逐字写着"判定必须走 `judge.judge_json`"，
   而 `judge_json` 在 `src/` 里**零调用点**。这是本项目最忌的形态（文档说有、代码里没有）：
   读的人以为有一层语义判据，实际上那四处的判据全是确定性代码。
2. **接了模型的三处（C×2、D×1）没有任何"可复现记录"。** 没有 `system`（只有 user 文本）、
   没有提示词版本号、没有"这次结论来自模型"的落库字段。对比 `runflow` 那条流程：
   它的 `prompt_version` 是**落进 run-manifest 的**（`v1` / `v2-lean` 两版，未知版本显式拒绝）。
   ⇒ 同一个仓库里"接模型"这件事有两套纪律，而严格的那套只用在演示流程上。
3. **提示词的护栏全靠事后检查，提示词本身不承担契约。** C 的两处、D 的一处都在提示词里
   写了"只输出 JSON、不要解释"，然后靠 `json.loads` 事后判；`v2-lean` 把"要能编译通过"
   写进 user prompt，然后靠 `lean` 事后判。**这没有错**（事后判比提示词可靠），
   但它意味着提示词写得再差也只影响**产出率**、不影响**正确性** —— 于是没有任何判据
   会逼着提示词变好。唯一一份被真跑打磨过的提示词是 B 的抽取模板（§2：页码那条教训逐字在里面，
   还有 `tests/test_local_corpus_flow.py` 盯着那两条硬规则）。
4. **角色的"前置"没有分工语义。** 所有角色的前置是同一套（工具面 + capabilities + docstring），
   差别只在**工具多少**。也就是说"B 该干什么、H 不该干什么"这类分工**在提示词层面无处表达**，
   只在 docstring（给人看）与权限面（给机器判）里。端到端任务因此只能靠**脚本编排**
   （`pipeline.py` / `runflow.py` / `projects/*/code/acceptance.py`），不能靠角色自主。
5. **主控 M 的策略面是 `NotWiredError`。** `conductor.SubagentBackend.call` 直接抛，
   台账落 `refused/not_wired`。⇒ "谁该在什么时候叫谁"今天没有实现者，
   而 `capabilities.ALLOWED_EDGES` 只回答"能不能叫"。
6. **`draft/29` 的 29 个判断点一个都没接线。** 那份草案的质量不低（每个点都有：判断点 /
   允许的模型动作 / 输出契约 / 禁止项 / 负控），但它今天是一份**设计稿**。
   审阅提示词时最容易被误读的就是它 —— §3 每格里我都标明"那是设计稿，不是现状"。
7. **三条"绝不许交给 LLM"的规格是对的，但它们是代码约束，不是提示词约束。**
   E 的"自报 proof 一律降级"、H 的"不判数学"、G 的 `CROSS_CHECK_DISCLAIMER` 精确匹配 ——
   这三条在代码里成立（好）。写这份材料时我特意检查过：**不要**把它们改写成提示词里的
   "请注意不要……"，那是把结构约束降级成祈祷。
8. **`runflow.SYSTEM_PROMPT` 承担不了"研究助理"这个角色。** 三句话里没有体例要求、
   没有拒答条件（只有"不确定"）、没有输出结构（在 user prompt 里）、没有"证据从哪来"。
   它今天够用，只是因为那一步的产物注定是演示级的（三句话 + 一个 Lean 片段）。

### 6.2 要让"前置提示词"这件事成立，最小可行是什么

按本仓已有的纪律，我认为最小的一套是（不新增机制，全部复用现成的）：

1. **每个角色一份 `ROLE_PROMPT_<r>`，带版本号**，挂在既有的 `runflow.PROMPT_VERSIONS`
   那套纪律上（未知版本显式拒绝、不回退；版本号落档，可复现）。
2. **system 与 user 分开**：system 放"这个角色是什么、不许做什么、输出契约"，
   user 放这一次的具体输入（现在 C/D 的钩子只有 user）。
3. **三态落点复用 `judge.py` 的现成词表**（`judge_not_wired` / `judge_refused` /
   `judge_over_budget` / `judge_bad_json`）：没接线、拒答、预算、坏 JSON 与"判过了"必须分开。
4. **每条提示词配一条注入负控**（本仓的判据模板：注入"永远返回空/坏输出"的替身 ⇒
   必须走确定性回退并在审计字段里如实写明来源，**不许**静默当成成功）。
5. **不把代码约束改写成提示词**（缺陷 7）。

这五条**没有一条需要改禁改区**（`agent_*.py` 都不在 `.noai-paths` 里）；
唯一可能要人裁的是"角色的提示词版本要不要落进台账"这种口径问题。
