## §1 施工单 S-A：文件"读后写"（裁定 9甲，最高优先）

**改动面**
1. 新的观察台账（进程内、**不持久化**，照 DSH）：`(workspace, 路径) → 观测版本 sha256`，
   在 `tools/fs_tools.py` 的 `fs.read` / `fs.list` / `fs.stat` 成功返回时登记。
2. `fs.edit`：目标**没被观察过** ⇒ 拒 `not_observed`（模型侧统一措辞
   `cannot modify "<path>": file has not been read — read the file, then retry`）；
   观察过但盘上版本变了 ⇒ 拒 `stale_version`，并附 `— re-read the file, then retry`；
   观察过且一致 ⇒ 放行（今天那条可选的 `sha256` 参数保留，作为**第二道**独立核对）。
3. `fs.write`：**同一条闸**。另外照 DSH 补"读一个不存在的路径 = 授权**带防护的创建**"
   （`createIfAbsent` 语义：创建前再查一次，别覆盖并发创建者的文件）。
4. 错误码词表集中一处（`fs_tools.py` 顶部常量），三种态：`not_observed` / `not_found` / `stale_version`。

**判据**
- 正控：新工作区里直接 `fs.edit` 一个存在的文件 ⇒ `not_observed` 拒绝（**先读后改**才过）。
- 正控：读 → 改 ⇒ 过；读 → （外部改）→ 改 ⇒ `stale_version` 且提示重读。
- 负控：`fs.write` 新建一个**不存在**的文件 ⇒ 允许（"读缺失 ⇒ 授权创建"），
  但**已存在**的没读过 ⇒ 拒 —— 这两条必须分开判。
- 反真空：**恢复会话（观察表为空）时正控仍然拒** —— "没观察过"绝不许被当成"观察过且没变"。

**代价与风险**：真机上会出现更多拒绝（模型得先读一次）；对**大文件**的读会变贵
（DSH 的解法是"观察按版本而不是按内容"，我们照做：只存 sha256 与 mtime，不存内容）。
**风险**：如果观察表按"进程"记，而 `rebuild()`/续跑是**另一个进程** ⇒ 必须像 DSH 那样
"恢复的会话从无观察状态开始"（宁可贵一次，不许把旧的观察当授权）。

**依赖**：无。可独立开工。

## §2 施工单 S-B：把 `contextbudget` 接进循环 + 口径换 DSH（裁定 7乙 + 8乙）

**改动面**
1. **接线**（裁定 7乙 的前半）：在 `agent_loop.py` 的步骤边界（读插话之前、`ask_step` 之前）
   加一次 pre-step 判定：把本趟 `agent_step` 事件重建成有序条目 →
   `contextbudget.load_budget(config)` → 超阈值时 `compact(...)` → 用返回文本前置换掉
   transcript 的早期段，并把 `CompactResult.reason` 写进事件（三态审计）。
2. **补 DSH 的三条不变量**（裁定 7乙 的后半）：
   - **节点 0 永不遮蔽**：压缩范围**不许**碰任务原文与提示词那一段（今天只按条数切片）；
   - **工具配对平衡**：切点不许落在"一次工具调用与它的结果之间"（S-A 之后工具结果是真消息，
     这条才有结构可判）；
   - **"摘要必须更小"硬校验**：摘要后的量**不小于**被遮掉的量 ⇒ 判失败（不是"成功但没省"）。
3. **口径换 DSH**（裁定 8乙，与 FC-16 相反，**这是本单里唯一一处推翻既有纪律的改动**）：
   - 阈值从**字符**换成**token 压力**（`0.8 × contextWindow`，保留尾部 `0.16`）；
   - 摘要器从**机械**换成**LLM**（`summarize=` 传一个真调模型的实现）。
4. **两个必须一起写的约束**（否则会踩禁改区或口径）：
   - 摘要用的模型调用要记进**已有的**用量归口（`USAGE_SCOPES` 在 `schema.py`，**禁改区**）
     ⇒ 不许新造 scope 名，用现成的那一档；
   - `contextbudget` 的 docstring 与 `config.yaml` 注释里那句"默认路径绝不调 LLM（FC-16）"
     **必须一起改**（改行为不改声明 = 我们反复登记的那种反面形态）。

**判据**
- 正控：造一段超阈值的 transcript ⇒ 步骤边界真的压了一次，且事件里能看到
  `original_chars / kept_chars / shadowed / summarizer="llm"` 读数。
- 负控：未超阈值 ⇒ **一次也不压**（"没压"与"压了没效果"分开）。
- 反真空：压缩后转录里**仍然有**任务原文那一节（节点 0 不变量）。
- 三态：`contextWindow` 读不到 ⇒ 既不静默当零、也不阻断这一趟（照 DSH：
  自动路径警告一次、带完整历史继续）。
- 配对：在被切的那一段里放一次"调用 + 结果"，切完两半必须**同进同出**（负控：故意切中间 ⇒ 红）。

**代价与风险**：LLM 摘要**要花钱、且不确定可复现** —— 这一条正是我原来建议"保持机械"的理由，
裁定推翻它，那就必须补一条"摘要调用的花销与读数落进账本"的判据（否则钱会静默流走）。
**依赖**：S-A（配对结构）先做更稳；S-C 之后配对判据最好写。

## §3 施工单 S-C：每步发"消息序列"（裁定 5甲）

**改动面**
1. `agent_loop`：`transcript: str` **不再**是唯一历史载体 —— 改成 `messages: list[dict]`
   （`role: user / assistant / tool`，assistant 带 `tool_calls`，tool 带 `tool_call_id`），
   由**会话事件**派生（`agent_step` 那几条就能重建成序列，不必另存一份）。
2. `_prompt()` 退休成"**最后一条 user 消息的尾部提示**"（步数 / 预算 / 输出契约那几句照旧，
   但**不再**把整段历史拼进去）。
3. `resume_transcript(...)` ⇒ `resume_messages(...)`：从会话记录重建**序列**（逐条相等）。
4. 工具结果从"文本行"（`_payload_line` / `_bad_args_line`）改成真 `tool` 消息；
   `_clip_fields` 的截断**保留**（它是我们的取舍），但**截断这件事要写进那条消息本身**
   （照 DSH 的 `truncated` 语义：只说预算事实，绝不表示上游失败）。

**判据**
- 正控：两步的循环里，第二步发给模型的是
  `[system, user(收件箱/任务), assistant(tool_calls), tool(result)]` 四条，
  且第 4 条的 `tool_call_id` 等于第 3 条给的 id。
- 负控：把 `tool` 消息挂到错的 id ⇒ 夹具当场红。
- 反真空：序列里 assistant 那条**必须**带工具调用（否则这条判据只测了拼接）。
- **既有资产改写**：`tests/test_user_channel_stop_and_resume.py:288` 的"逐字节相等"
  改成"**逐条相等**"（改名 + 判据重写，理由写在用例里：字符串形态退休了）。

**代价与风险**：这是本单里**动得最深**的一处（历史载体换形态），它会牵动
`LoopRun.transcript` 的所有读者（Web UI 的事件回放、续跑、`--resume`）。
**建议**：分两小步落（先工具结果成真消息，再整序列化），每小步各配一次全量。
**依赖**：S-B 的配对不变量最好在它之后写。

**改动面**：`agent_loop` 里那两条阈值参数：提醒 `dead_loop_nudge: 3`（不动）、
判停 `max_dead_loop: 6 → 5`；并把"提醒"与"判停"在**读数**上分开（今天它们共用一条连击读数）：

`_stall_line`（同一条路的第二次提醒，`stall_nudge=3/stall_alert=6`）保持不动，但要在

反真空 —— 提醒那一档必须真的出现过（否则"两档分开"没有证据）。

**代价**：判停从 6 降到 5 ⇒ 比今天**更早**停（少烧一点钱，也可能少一次自我纠正的机会）。

## §5 施工单 S-E：逐工具超时（裁定 13甲）

**改动面**：`ToolSpec` 加可选 `timeout_ms`；执行期用"协作式"截止（只发取消信号，**不硬杀**）；
超时结果 = `Error: tool call timed out after <ms>ms` + 受控码 `timeout`。
**默认**：**不给**（照 DSH：只有声明了的工具才有截止）。第一批只给"会卡住的"那几件：
检索（网络）、模型下载类、起子进程（Lean/脚本）。
**判据**：正控 —— 声明 1s 的工具在 ~1s 后收到超时结果且**进程未被硬杀**；
负控 —— 未声明的工具不受影响；三态 —— 限时读不到（配置缺）时不许当 0。
**代价**：协作式意味着"忽略信号的工具会让调用方继续等"（DSH 的原话）——
要接受这一点，或者对起子进程那几件额外加一次"墙钟到点就收结果、进程留给清理"。
**依赖**：无。

## §6 施工单 S-F：**抄 DSH 的"没有内置轮次预算"**（当轮新裁定）

**这句话的落点**（我按 DSH 的原文口径翻译成我们的形态）：
DSH 的循环**不自己判停**：逐字「没有内置轮次预算——工具调用或 steering 会让当前轮次继续；
限制失控轮次的策略必须从既有生命周期扩展点（如 `agent/turn-stopping`）执行取消」
（`dsh-agent-loop/README.zh.md:200`）。

**改动面**
1. `max_steps` 从"循环自己收工的理由"降级为**策略读数 + 取消信号**：
   - 循环不再因步数到顶而 `stop_reason="max_steps"` 收工；
   - 步数超过策略上限时，由**策略层**（`policy.check` 的同一处，与预算/墙钟并列）发出取消 ⇒
     仍然是受控收尾，但"是不是该停"这件事的**判据不在循环里**。
2. 真跑配方里的 `--max-steps` 默认值改为 **0 = 不限**（读数是 `steps_used`），
   策略层若要限就给一个显式值。
3. **钱的闸与墙钟必须留**（这两件**不是**"轮次预算"）：`usd_budget` 与 `wall_clock_sec`
   照旧在策略层拦 —— 否则"不限步数"会变成"无限烧钱"。

**判据**
- 正控：一个连续 12 步都在调工具的循环，在 `max_steps=0` 下**不会**因步数收工
  （它要么自己 `final`，要么被预算/墙钟取消）。
- 负控：策略层显式给上限（例如 5）⇒ 第 5 步后**受控收尾**，且 `stop_reason` 记的是
  **策略取消**（不是"循环自己到了上限"）。
- 反真空：`stop_reason` 词表里 `max_steps` 这一档要么删、要么明确标成"策略取消的一种"；
  **不许**留一个永远不再产生的旧词。
- 钱：造一个"步数不限但预算极小"的循环 ⇒ 被 `budget` 停（证明闸还在）。

**代价与风险**：**这是我们最贵的一次放开**（步数不设限 ⇒ 一个卡住的循环会一直跑到预算耗尽）。
缓解：① 预算与墙钟仍是硬闸；② 判停/提醒读数（S-D）照旧；③ 真跑配方里显式写一个策略上限
（"默认不限"是**能力**，不是"每趟都不限"）。
**依赖**：与 S-D（提醒/判停）同向，建议同一批落。

## §7 施工单 S-G：父代理"等"子代理 —— 学 DSH 的**通知模型**（裁定 15）

**先把 DSH 怎么"等"说清楚**（`dsh-tool-subagent/README.zh.md:132`、`:165` 逐字口径）：
- **可继续委派（后台）**：父代理**继续干活**，孩子的结算以**通知**到达父级；
- **前台委派**：**只在"下一步动作依赖该结果"时**才用，此时阻塞等它的最终文本；
- 两条都不是"sleep 着等"：等待是**事件驱动**的（结算事件到达 / 工具调用返回）。

**改动面**（我们的形态）
1. **读数侧**：父代理收工前读一条"我名下还有几条在飞"（已有 `_in_flight_children_of`），
   把它写进收工门与状态视图（**读数，不拦**）。
2. **行为侧**：把今天"到扇出上限才等"（`fanout_wait_sec`）扩成"**有在飞的子代理就可等**"，
   但等的实现**照 DSH**：
   - 父代理**先接着干别的**（不空转）；
   - 孩子结算 ⇒ 以消息/通知到达（我们已有 `message` 形状与秘书投递）；
   - **确实没别的可干且还有在飞孩子**时，等的是"下一条事件"，**有界**（墙钟上限）；
   - 超时 ⇒ 记读数继续收工（不否决收工 —— 与裁定 1「收工由 M 判」一致）。
3. **不要**做"父代理循环里 sleep N 秒再看一次"—— 那是 DSH 明确没有的形态，
   而且会把墙钟吃掉。

**判据**
- 正控：父派了两个子任务后**不再空转**：它要么继续派别的活、要么收工前读到"还有 2 条在飞"。
- 正控：孩子结算后，父的名册/收件箱里能看到它的结果（通知到达）。
- 负控：**不许**用 `sleep` 实现"等"（判据：等待期间会话事件里没有空白的时间段，
  或直接断言"等"这条路上没有 sleep 调用）。
- 三态：等超时 ⇒ 收工**照样成立**，但门里带一条"还有 N 条在飞"的读数。

**代价**：父代理可能"收工时孩子还在飞"（这是裁定 1 允许的），代价是"父的交付可能没有孩子的结论"；
缓解是读数把它摆出来（谁在飞、飞到哪一步）。
**依赖**：与 S-H（子代理面）同一批最自然 —— "要等就得先看得见"。

## §8 施工单 S-H：完善名册 + 补一个"叫停某个子代理"（裁定 14）

**先确认盘上有什么（我查过了，回你"类似的设计"是哪几件）**：

  提示词里也教了「要点名时先 `{"roster": {"of": "self"}}` 看一眼活跃名册（名字 · 简介 · 状态）」
  （`agent_prompts.py:169`）。
- **退役（类比"结束一个子代理"）**：`retire` 形状 + `Conductor.retire_ready`（**只报不动作**）
  + `Secretary.retire`（父说了才做，`conductor.py:1556-1577`）。
- **没有的**：① 名册里**没有"这个子代理此刻在飞哪几个任务"**那一格；
  ② **没有** `interrupt_agent` 的等价物 —— 今天的 `Conductor.stop` 是**全局**停机
  （停机开关 + 广播），不是"停某一个孩子当前那一轮"。

**改动面**
1. `roster` 每一行补三格：`status`（`pending/running/ready`）、`in_flight`（它名下还在跑的任务数）、
   `last_reading`（它最近一条读数的一句话）。
2. 新形状 `interrupt`（名字待定）：`{"interrupt": {"name": "<名册名>"}}`
   ⇒ 只停目标**当前那一轮**（已排队的消息留着、后代继续跑 —— 照 DSH `interrupt_agent` 的三条），
   并落一条事件；**越权当面拒绝**（不是自己的子代理 ⇒ 拒；自己 ⇒ 拒；兄弟 ⇒ 拒）。
3. 提示词那一句跟着改（"要谁停就 `interrupt` 它，不要用全局叫停"）。

**判据**：正控 —— 父能列出自己的子代理与它此刻在飞几条；`interrupt` 后目标那一轮停、
**它的后代继续**、排队消息还在；负控 —— 对兄弟/自己/不存在的名字 ⇒ 受控拒绝；
反真空 —— 名册里至少有一条 `in_flight > 0` 的行（否则那一格没被测到）。

**代价**：`interrupt` 是**第一个"父能强停孩子"**的能力 —— 要写清它与"协作式取消"的关系
（不硬杀进程；起子进程那几件走已有的杀子孙登记）。**依赖**：S-G（"等"学 DSH）同批。

## §12 三条"我听不懂"的，用最白的话重讲（等你圈）

### 12-A（原第 11 条）模型的"心里话"要不要在下一轮再给它看一遍
模型每次回话分两段：**答案** + 前面那段**"我先想……"**（DSH 叫 reasoning content）。
我们今天：把"我先想……"收下来**只记字数**，下一轮**不再给它看**。
DSH：下一轮**原样带回去**。
- 甲 = 保持今天（不带回去）：省 token；缺点是长任务里它可能把同一件事想两遍。
- 乙 = 照 DSH 带回去：它记得自己想过什么；缺点是 token 变多，且那段话会变成"历史"的一部分。
- 丙 = 带回去但**单独标成"这是思考，不是正文"**（我的原建议）。
**要你圈的**：甲 / 乙 / 丙。

### 12-B（原第 12 条）"需要批准"的工具，今天其实没人拦
有些工具在声明里写着"需要人批准"（比如改盘、起进程）。但**今天这个声明只用来在工具清单里
标一个「⚠需审批」**，真跑的时候**没人拦** —— 有没有人在旁边，它都照跑。
DSH 是：真要批而**没有人应答时直接拒绝**（不是"没人就放行"）。
**要你定的两件**：
1. **哪些工具算"需要批准"**（候选：`fs.write` / `fs.edit` / `bash` / `pwsh` / 起子进程的实验）；
2. **没人应答时**：甲 = 拒绝（fail-closed，照 DSH）；乙 = 放行但落一条读数；丙 = 只加读数、行为不变。
**要你圈的**：第 1 问的候选清单要不要增删；第 2 问圈甲 / 乙 / 丙。

### 12-C（原第 16 条）`merged_at`：新标准里"这条关系哪天并进来的"查不到
旧标准每条关系有一格记**并表时间**；新标准**没有这一格**，所以现在问"这条边是哪天进来的"
答不出来。**要你圈的**：
- 甲 = 补一格（要动 `schema.py`，**禁改区**，得走人工）；
- 乙 = 不补，用事件日志里那条事件的时间戳代替（不改 schema，但读起来分散）；
- 丙 = 明确废弃它（"并表时间"这个说法从文档里去掉）。
