1. **开跑前给可行性论证**（基于当前系统：机制通不通、要哪些外部条件、判"通过"的标准是什么），
   论证通过才跑；
2. 预算 `--budget-usd 5`；每趟先给足步数与墙钟（避免"不是钱卡住"）；
3. 跑完**按实际产出**（报告 / 稿件 / 论文 / 会话记录 / 台账）裁定缺陷，逐条针对性优化；
4. 改动（含禁改区）必须有明确理由并记录，**以根除问题为纲**，不以最小化改动为目的；
5. **每轮把所有该做的改动做完，再一起跑一次全量**（lint / 全量 pytest / FC-27 门 / 登记 + 提交）；
6. 不再向用户提问；独立完成。

4. **手稿成体**：`documents` 里有一份进展手稿（`kind=note`/`survey`），≥ 4 条断言、
   **每条带 `citations`**，其中至少 1 条 `lit:`（引到取回的原文）；
5. **说明九节**：`out/review/REPORT.md` 九节齐全、每节有读数；

8. **我的裁定（我自己做）**：手稿里每条断言的引文与原文一致（抽查 3 条），
   且"更短路径"的候选路线（例如：把 Wiles 的模性提升换成更弱的输入、绕开
