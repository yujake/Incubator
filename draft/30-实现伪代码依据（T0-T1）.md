# 实现伪代码依据（T0–T1）—— 改代码前必须先对上的那一份

> **这份文件是"依据"，不是说明。** 规则只有一条：
> **没有对应伪代码条目的代码改动，不许做**；实现与伪代码不一致时，
> **先改这里并写明理由**，再改代码 —— 不许默默偏离。
>
> 定它的理由（所有者逐字）："**为严防改程序时的幻觉，请先定好伪代码当作依据**"。
> 幻觉的典型形态不是"写错一行"，而是**顺手发明**：发明一个不存在的字段、
> 一个没登记的状态、一个没人读的键。所以每一节都带固定的四个栏目：
> **契约**（签名/数据结构，逐字）/ **伪代码** / **判据**（正控）/ **负控**（注入会咬），
> 外加 **不做**（这份条目刻意不管什么）。
>
> 覆盖范围：**T0（非禁改区）、T1（猜想数据面）、T2（猜想状态机的跨对象不变量）与
> T3-H（主控接线）**。T3/T4 的伪代码在各自开工前
> 按同一格式补写 —— 同样"没有条目不许动"。出处一律指向 `draft/29` 的节号。

**依据的事实（实测，`draft/29` §1.6 有复核命令）**：`S.TABLES` 15 张 ·

## T0-1 `fulltextstore` 落仓（新模块；出处 `draft/29` §7.4 Shape C + §10.6 第 2 条）

**目标**：正文按内容寻址只存一份；产物里只留引用。

**契约（逐字）**

```text
STORE_VERSION = 1
STORE_DIR_NAME = ".fulltext"
HASH_PREFIX = 16

pages_text_sha256(pages: Sequence[str]) -> str      # sha256("\n".join(pages))；口径与旧 text 字段逐字一致
file_sha256(path: str | Path) -> str
store_dir_for(project_dir: str | Path) -> Path      # Path(project_dir)/".fulltext"（只算路径，不建目录）
ref_name(pdf_sha256: str, pages: Sequence[str]) -> str    # f"{pdf[:16]}-{text[:16]}.json"
put(pages, *, store_dir, pdf_sha256="", pdf_path="", pdf_bytes=0, backend="", encoding=None) -> dict
load(ref, *, allowed_dir=None, verify_file_hash=True) -> tuple[list[str], str]
verify_ref(ref, *, allowed_dir=None) -> dict
inventory(store_dir) -> list[dict]
selftest() -> int
```

**store 文件（JSON，`sort_keys=True`，LF，UTF-8）键**：
`store_version / pdf_sha256 / pdf_path / pdf_bytes / backend / encoding / pages / chars /
text_sha256 / text_pages`

**产物侧 `text_ref` 键**：`store / path / text_sha256 / file_sha256 / pages / chars / pdf_sha256`

**`load` 的 problem 词表（空串 = 读成了）**：
`store_not_a_mapping` · `store_out_of_store` · `store_file_missing` · `store_file_unreadable` ·
`store_file_hash_mismatch` · `store_not_a_store_file` · `store_text_hash_mismatch` · `store_pages_mismatch`

**伪代码**

```text

  校验 pages 非空（空 ⇒ ValueError：没有内容的 store 文件不是证据）
  mkdir store_dir
  target = store_dir / ref_name(pdf_sha256, pages)
  if target 存在:
      data, problem = _read_store_file(target)
      if problem == "" and data.text_sha256 == pages_text_sha256(pages): return _ref_of(target, data)
  写 blob = json(payload, sort_keys=True, indent=1) → tmp（带 pid）→ os.replace(tmp, target)
  回读校验：_read_store_file(target)；problem 非空 ⇒ raise OSError（写完不核对 = "看起来成功"）
  return _ref_of(target, data)

load(ref, allowed_dir, verify_file_hash):
  ref 不是 Mapping / 缺 path ⇒ ("", store_not_a_mapping)
  _store_allowed(path, allowed_dir) 非空 ⇒ 直接返回它（allowed_dir 给了就必须落在里面；
      没给则要求父目录名 == ".fulltext"）—— 这一层挡的是"被改过的 evidence.json 指向任意文件"
  verify_file_hash and ref.file_sha256: 比对 file_sha256(path) ⇒ 不符 ⇒ store_file_hash_mismatch
  data, problem = _read_store_file(path) ⇒ 有问题原样返回
  pages = data.text_pages；空 ⇒ store_not_a_store_file
  比对 ref.text_sha256 与 pages_text_sha256(pages) ⇒ 不符 ⇒ store_text_hash_mismatch
  比对 ref.pages 与 len(pages) ⇒ 不符 ⇒ store_pages_mismatch
  return pages, ""
```

**判据**：`tests/test_fulltextstore.py` 12 条（正控：存读一致 / 幂等 / 同书不同正文各占一文件 /
负控：删文件、改一字节、换正文并同步改 `file_sha256`、页数不符、越界路径、未知 `store_version`、

**负控**：`temp/_ev_inject_check.py` 的四条注入（跳过字节哈希层 / 越界放行 / 跳过页数层 /
跳过正文哈希层）**必须各自咬住对应用例**。**已实测：四条全咬住 + 干净副本 12 passed。**

**不做**：不做 GC / 不做引用计数 / 不加锁（store 文件内容寻址、写同名文件只在哈希碰撞时发生）。

## T0-3 `evidence.py` 读侧：两处内联直读合流成一个函数（出处 §10.4 第 7 项）

**契约**

```text
_fulltext_pages(source, cache: dict[str, tuple[list[str], str]] | None = None) -> tuple[list[str], str]
_pages_of(source, cache=None) -> tuple[list[str], str, str]
_check_quote_levels(source, quote, fn, *, cache=None) -> (结果, 异常, locator, 级别, 有可比文本吗)
```

**伪代码**

```text
_fulltext_pages(source, cache):
  full = source.get("fulltext")
  if not (full 是 Mapping and full.status == "ok"): return [], "fulltext_not_ok"
  ref = full.get("text_ref")
  if ref 是 Mapping and ref.path:
      key = str(ref["path"])
      if cache is not None and key in cache: return cache[key]
      pages, problem = fulltextstore.load(ref)          # allowed_dir 不传 ⇒ 结构判据（父目录名 .fulltext）
      if cache is not None: cache[key] = (pages, problem)
      return pages, problem
  inline = [str(p) for p in (full.get("text_pages") or [])]
  return (inline, "") if inline else ([], "fulltext_no_text")

_pages_of(source, cache):
  pages, problem = _fulltext_pages(source, cache)
  if pages: return pages, "fulltext", "用的是已获取的全文逐页文本"
  abstract = source.abstract
  if abstract:
      why = "只拿到摘要（这篇没有可用的全文文本）" if problem in ("", "fulltext_not_ok", "fulltext_no_text") \
            else f"全文逐页文本取不到（{problem}）⇒ 只到摘要级"
      return [abstract], "abstract", why
  return [], "abstract", ("这条来源没有任何可比的文本" if not problem else f"全文逐页文本取不到（{problem}）且没有摘要")
```

**`cache` 的作用域**：**每次 `verify_claims` 内的局部字典**（键 = ref path）—— 不用模块级缓存，
理由是模块级缓存会跨调用掩盖"文件被改"。**这一条写进代码注释。**

**判据**：`tests/test_evidence.py` 断言"用 ref 的产物"与"用内联的等价产物"得到同一 level/locator/page。

**负控**：把 store 文件内容换成另一段文本（**同步改 `file_sha256`**）⇒ 必须由
`store_text_hash_mismatch` 拦下，**不许**用被换掉的文本去核引文。

**不做**：不改摘要级的字符偏移口径（`:1391` `_locate` 原样）。

## T0-8 LLM 注入缝：默认关闭、零调用、失败留痕（出处 §3.1 + §4 的 P1）

**契约**

```text
# 角色构造签名新增关键字参数（kwonly，默认 None）：
AgentA(store, *, providers, downloader, config, actor, llm=None)
AgentE(store, *, config, workspace_root, log, llm=None, tools, actor)   # 已存在，接线即可
AgentF(store, *, config, log, e, tools, actor, llm=None)
AgentG(store, *, config, workspace_root, log, tools, llm=None)
AgentH(store, *, config, log, tools, writers, llm=None)

# 统一缝协议（与 D 现在的用法一致，不新造抽象）：
完整形 = complete(prompt: str) -> str
解析   = llm.parse_llm_json(raw) -> dict
失败词表 = judge_not_wired / judge_timeout / judge_bad_json / judge_over_budget / judge_refused
```

**伪代码（每个 LLM 点的统一形态）**

```text
def _judge(self, point: str, prompt: str) -> tuple[dict | None, str]:
    """返回 (判定, 没查成的原因)。原因非空 ⇒ 调用方必须走确定性回退并留痕。"""
    if self.llm is None:                       return None, "judge_not_wired"
    try: raw = self.llm.complete(prompt)
    except TimeoutError:                       return None, "judge_timeout"
    except Exception as exc:                   return None, f"judge_failed:{type(exc).__name__}"
    try: data = llm.parse_llm_json(raw)
    except Exception:                          return None, "judge_bad_json"
    if not isinstance(data, dict):             return None, "judge_bad_json"
    return data, ""
```

**每个点的接线形态（先做插座，不改行为）**

```text
判定, why = self._judge("L-A1", prompt)
if why:
    plans, plans_from = [topic], why            # 确定性回退 = 今天的实现
else:
    plans, plans_from = 归一化(判定), "llm"
审计字段里写 plans_from（这一格是"为什么是它"的可观察面，与 I7 同族）
```

**判据（P1 的核心）**：
① `llm=None` ⇒ 行为与改前**逐字节相同**（对同一输入跑两版，产物 sha256 相等）；
② `llm=None` ⇒ **零 LLM 调用**（注入一个"一被调用就抛异常"的假对象，断言从未被调用）；
③ 接线且失败 ⇒ 走回退 + `why` 进审计字段，**不许**静默当成功、**不许**折成 `not_found`。

**负控**：把回退分支删掉（失败即抛）⇒ 用例②必须变红。

**不做**：本条目**不接线任何真实的语义判定**（`L-*` 的判定逻辑各自等自己的伪代码条目）。

## T0-9 M 的工具链（主 Agent 的落地）：派活 / 看台账 / 冷热启动 / 优雅停止（出处：所有者口述）

> 所有者逐字："**到时候要过关的时候不是你把任务派给这些智能体，用户只会一两句话描述需求，
> 要 M 亲自制定计划把活派下去**"。
> ⇒ 验收时那个"派活的人"必须是 **M**，不是会话里的父代理；
> 于是 `conductor.SubagentBackend` 的 `NotWiredError` 从"记录在案的欠账"变成**验收阻塞项**。

**目标（修正后）**：**M 是主 Agent** —— 用户只对它说一两句话，它用**自己的工具链**去
理解 → 派活 → 看结果 → 再派 → 汇总。**计划不是被解析的 JSON，计划就是它的工具调用序列**
（落 `tasks` 台账）。程序只负责提供**工具与闸门**，"想做什么"由 M 自己想。

**契约（逐字）**

```text
# 已落地：新增工具模块 src/agentflow/tools/conductor_tools.py（新文件，非禁改区），
# 注册进 tools/__init__.py 的 _MODULES；roles=("M",)；只放编排面工具。
#
# 落地后与设计的三处偏差（都是工具层的**硬约束**，不是口味问题）：
#   1. 工具名统一用 `conductor.` 前缀：工具层按 `_MODULES` 机械派生组前缀
#      （`_TOOL_GROUP_PREFIXES`），一个模块一个前缀；`state.summary` / `project.ensure`
#      / `role.spec` 那样的多前缀会把 `capabilities._TOOL_GROUPS_BY_ROLE` 也拖下水。
#   2. 形参不许与 `ToolRegistry.call` 自己的形参撞名（`name` / `role` / `args` /
#      `budget` / `spill_root`）：`role` 是**调用方角色**（`P-14` 的调用期权限判据）、
#      `name` 是工具名。撞名的后果是"模型传的目标角色被读成调用者身份"。故：
#      `target_role` / `project_name` / `role_name`。
#   3. 召唤方身份是**受控词表**（`schema.ROLES` ∪ {M}）：自造 `"agent-M"` 会被
#      `Conductor` 拒为 `unknown_role`（实测撞过）⇒ 用 `by=S.CONDUCTOR_ROLE`。

conductor.summon(target_role, action, params=None, input_key="") -> dict
    唯一的"派活"动作。内部依次过：ALLOWED_EDGES → CAPABILITIES → _check_params
    → policy.check_edge（四上限）→ _meter_guard（预算）→ 派给 backend → 写终态。
    返回 SummonResult 的那组键（含 status/outcome/refusal_reason/detail）。
    `input_key` 不给会被 `verify_tasks` 报 `task_without_input_key`（循环检测要用它）。
conductor.ledger(view="tree"|"stats"|"issues"|"verify", root_task_id="") -> dict
    看台账：这一轮派了什么、被拒了什么、还剩多少预算。
conductor.stop(reason="user", drain_sec=30) -> dict
    优雅停止（这是"总控"该有的动作，不是"kill"）：
      ① 置共享 CancelToken ⇒ 不再接受新召唤；
      ② 等在飞任务收尾，超过 drain_sec 转协作式取消；
      ③ 合成终态：每个 start 恰有一个 end，不留僵尸（复用 `dispose()`）；
      ④ 被砍的结果记 unknown outcome（不自动重试，FC-20 第 4 条）；
      ⑤ 落一份"续跑简报"（做了什么 / 剩什么 / 从哪继续）；
      ⑥ 返回 stop receipt。**`reason` 回报首次生效的那个**（终态先到先得，FC-20 第 2 条）。
conductor.resume_brief() -> dict
    读续跑简报 + 若仍有未终态行，逐条明确报出（不隐藏、不自动续跑）。
conductor.cancel(reason="user", detail="") -> dict
    硬取消（协作式，FC-20 四条纪律）。与 stop 的区别：cancel 不等收尾，stop 先尝试收尾。
conductor.ensure_project(project_name="", start="auto"|"cold"|"warm", books_dir="", books_limit=None) -> dict
    冷启动/热启动由 M 决定：返回 `{name, path, mode, requested, state, why, created, ingested}`；
    `projects.resolve` 的四态（absent / empty / workspace / not_a_project）如实给，不许替 M 猜。
    （冷 = 文件夹不存在 ⇒ 新建；热 = 已存在且是工作区 ⇒ 复用已有知识层；
    别人的目录 ⇒ 明确失败，绝不初始化进去。）
conductor.state() -> dict

    只读状态视图：各表计数 + 猜想按状态 + 未决问题 + 未接线/未知项（给 M 判断用的"眼"）。
conductor.role_spec(role_name) -> dict
    某角色的规格 + 工具面 + 允许的动作（M 决定派给谁；subagent backend 用它当 brief）。

# 执行后端（既有设计不变，DESIGN-CONDUCTOR.md §6）：
#   LocalBackend = 进程内确定性 Python 实现（测试 / 离线 / 可复现）
#   subagent     = 把 (role, action, params) 交给 harness 的子 Agent（带该角色的工具面与规格）
```

**M 的"计划"长什么样（伪代码 —— 注意这里没有"计划解析器"）**

```text
M（主 Agent，跑在 harness 里，手上有上面那套工具）：
    loop:
        看 state.summary() 与 conductor.ledger()       # 眼：状态与台账
        决定下一步                                      # 这是 M 自己的推理，不是我的代码
        调 conductor.summon(role, action, params)       # 手：派活；闸门在工具内部
        若 refused：读 refusal_reason，改主意或换角色      # 再计划 = 再来一轮；工具调用即记录
        直到 M 认为需求已满足 → 汇总給用户
    # 台账就是 M 的思考轨迹：tasks 行（by="agent-M"）+ 每次 summon 的输入与结局
```

**闸门（沿用既有实现，不另写一份）**：`capabilities.ALLOWED_EDGES`（谁召唤谁）·
`capabilities.CAPABILITIES`（动作是否存在）· `conductor._check_params`（参数接缝）·
`policy.check_edge`（四上限）· `Conductor._meter_guard`（预算）。**被拒不是崩溃**：
落 `refused` 行并把理由作为下一轮的输入（这就是"再计划"）。

**判据（正控）**
1. **M 的工具面非空，且只有编排面工具**（派活 / 看台账 / 停止 / 看状态 / 起工作区；
   **无**领域写工具）—— `CAPABILITIES["M"] = ()` 与 `WRITE_SETS["M"] = {}` 一个字都不改；
2. 一次真实运行里 M 能**连续多轮** `summon`（≥3 步），每步过闸门，被拒带 `refusal_reason` 且 M 改道；
3. `tasks` 台账能重建 M 的决策序列（第 n 步派了谁、结果如何）；
4. `role.spec(role)` 能把某角色渲染成 brief 且与 `capabilities` **同源**（不新造第二份规格）；
5. **冷/热启动由 M 决定**：M 调 `project.ensure(start=…)` 拿到四态后自己选，
   且选择落台账（判据：产物里能读到"这次是冷还是热、为什么"）；
6. **优雅停止五条**：`stop` 之后 ① 不再新开任务；② 在飞收尾成终态、**无僵尸行**；
   ③ 被砍的记 unknown outcome 且**不自动重试**；④ 落**续跑简报**；⑤ 第二次 `stop` 不改第一次的 reason；
7. **停得下、接得上**：`stop` 之后命令 `project.ensure(start="auto")` 必得**热启动**（文件夹在），
   M 能凭 `resume_brief` 从"剩什么"接着做 —— 判据：停/续两次运行的台账能拼成一条完整链。

**负控（注入会咬）**
1. 把 `conductor.summon` 从 M 的工具面摘掉 ⇒ M **无法派活**，必须如实报"没有可用工具"，
   **不许**退回"开发者在会话里手工派活"；
2. 把 `project.ensure` 摘掉 ⇒ M 无法建/复用工作区，必须如实报缺工具（不许暗中替它建）；
3. 让 M 试调越权动作（领域写）⇒ 工具内部拒，落 `refused`；
4. 让 M 试派给不可召唤的角色（M 自己）⇒ `NON_SUMMONABLE` 拒；
5. 预算耗尽后继续派 ⇒ `refused/budget_exceeded`，台账留痕；
6. **stop 之后仍能新开任务** ⇒ 判据必须红（这是"停止只对某一层生效"的经典失效）；
7. **stop 之后留下 `running` 行** ⇒ `conductor.verify_tasks()` 必须报出来；
8. **被取消的任务被自动重试** ⇒ 判据必须红（FC-20 第 4 条）；
9. **`resume_brief` 缺失或空** ⇒ 判据必须红（那就是"粗暴 kill"而不是"优雅停止"）。

**不做（这一栏是本条目的重点）**：不写"计划 JSON schema"、不写 prompt 模板库、
不写 plan 解析器、不写重计划状态机 —— 那些正是"把智能体写成大程序"的形态。
程序只提供**工具与闸门**；"想做什么"由 M 想，轨迹由 `tasks` 台账如实记下。

## T2 猜想的状态机不变量（跨对象那一半；出处 `draft/29` §7.7 + §7.8.1/§7.8.2）

`refuted` 必须真的挂着一个反例，`promoted` 必须真的落在一条已闭合的证据链上。

```text
① proved_without_formal_proof:
   status == "proved" ∧ ¬FC22 三条

② promoted_without_closed_dep（升格 = 两跳，两跳都要真）：
   第一跳（猜想→断言）：promoted_to = {"kind":"document_claim","id":"<doc>#<claim>"}
        且该 doc 里的该 claim 存在（缺 ⇒ T1 的 promotion_target_missing 已报，这里不重复）
   第二跳（断言→证据）：该 claim 的 evidence_kind == "proof"
        ∧ 该 claim 的 citations 里含 "exp:<proof_experiment_id>"
        ∧ 存在 Dependency(status=="closed" ∧ source_experiment_id==proof_experiment_id)
   任何一跳不成立 ⇒ promoted_without_closed_dep

③ refuted_without_counterexample:
   status == "refuted" ∧ e(counterexample_experiment_id).result != "refutes"
   （`inconclusive` 不得转 `refuted`：三态不许折平）

④ supported_without_support:
   status == "supported_not_proved" ∧ 不存在 eid ∈ experiment_ids 使 e(eid).result == "supports"

⑤ status_conflicts_with_experiment:
   status ∈ {"proved","promoted","supported_not_proved"}
   ∧ 存在 eid ∈ experiment_ids 使 e(eid).result == "refutes"
```

**判据（正控）**：`tests/test_conjectures_status.py`（新）—— 每条码各一条"合法行 ⇒ 不报"，
外加"五条码一起在一库两猜想上 coexists ⇒ 只报该报的那几条"。

**负控（注入会咬，每条码各一条）**：把正控里那一处证据**改坏一个字段**（例如把
`method="formal"` 改成 `"numeric"`、把 claim 的 `citations` 里的 `exp:` 换掉、
把反例实验的 `result` 改成 `"inconclusive"`），断言**恰好**该码出现且条数为 1。
另有一条"注入无效"的自检：改一个与被测码无关的字段 ⇒ 该码**不得**出现
（否则测的是"任何改动都报"，不是这条判据）。

**不做（今天判不了的三件事，逐条给出为什么）**

```text
1. §7.8.2-2 的字面形态"该断言**引用猜想**"：引文语法只有 `rel:` / `lit:` /
   `exp:` 三种前缀（`schema.py:1226-1228` 逐字），**没有** `conj:` ⇒ "断言→猜想"
   这条边今天没有数据面。本条目改用两跳（`promoted_to` 指名言辞 + 该言语 `citations`
   含 `exp:<proof>`），能判的是"升格确实挂在真证据上"这件事；
   "谁引了哪个猜想"要新开条目加引文前缀或新字段。
2. §7.8.1"被 dependencies（作为前提）引用的猜想**不得硬删**"：`Dependency` 只有
   `source_lit_id` / `source_experiment_id`，**没有** `source_conjecture_id`
   （`draft/29` §7.8.3 已列这条为待加的 schema 面）⇒ 今天只判得了"悬空"（T1 已做），
   判不了"被引用"。硬删检测还依赖"行没了但事件还在"，那是 `rebuild`/事件的判据，不是 verify_all。
3. §7.7 第 3 条的**完整**反向（实验说 `refutes`、而猜想根本没把它列进 `experiment_ids`）：
   `Experiment` 只有 `for_question_id`（指向研究问题），**没有** `conjecture_id`
   （`draft/29` §7.8.3 列为待加）⇒ 今天判不了"这个实验在检验哪个猜想"。
   本条目只判**已列进来的**那个方向（⑤）。
```

**这三条不做的事已登记为残余（`draft/28` §138），并明确"加字段 = 新条目 + FC-27 人审"**。

## T3-H 主控接线：把 A–H 接到 `LocalBackend`（出处 `draft/31` P10/P11）

> **为什么它不在 `draft/29` §10.5 的四层里**：那四层讲的是**领域面**（缝 / 数据面 / 判据面 /
> 契约面）；这一条是**执行面**的接线 —— M 的工具已经装好（T0-9），但默认登记表为空，
> 于是 `summon` 如实落 `refused/not_wired`。P10 要求"派活由 M 用工具链完成"，
> 所以线必须接上。它不动任何红线，也不属于 T1–T4 的任何一层。

**目标**：给出一层**薄接线**（新文件 `src/agentflow/host.py`，非禁改区），把
`LocalBackend` 要的角色登记表按各角色**实测的构造签名**造出来。
它不是计划器：**不含**计划 JSON schema、prompt 模板库、plan 解析器、重计划状态机。

**契约（逐字）**

```text
WIRING_STATES = ("wired", "no_provider")

build_role_registry(store, *, llm=None, providers=None, extractor=None,
                    config=None, workspace_root=None) -> dict[str, tuple[str, Callable]]
    # role -> ("factory", fn)，fn 的调用形态是 fn(*, store=...)（LocalBackend 的契约）
wiring_status(store, *, providers=None, ...) -> dict[str, str]     # 每个角色一格 WIRING_STATES

wired_tool_registry(store, *, policy=None, ..., **build_kw) -> RegistryBuild
selftest() -> int
```

**伪代码**

```text
build_role_registry:
  cfg = dict(config or {})
  A: providers 为空 ⇒ **不进登记表**（不编造 provider 列表；见"三态"）
     否则 AgentA(store, providers=[...], llm=llm, config=cfg.agent_a)
  B: AgentB(store, extractor=LLMExtractor(llm) if llm else RuleExtractor(),
            extract_text=extract.extract_text, config=cfg.agent_b)
     # B 的实测签名里**没有** llm：它的 LLM 走 extractor 协议（draft/29 §1.2）
  C: AgentC(store, config=cfg.agent_c, llm=llm)
  D: AgentD(store, config=cfg.agent_d, llm=llm, c=<本登记表造的 C>)     # 构造期定死"谁能叫谁"
  E: AgentE(store, config=cfg.agent_e, workspace_root=root, llm=llm)
  F: AgentF(store, config=cfg.agent_f, llm=llm, e=<本登记表造的 E>)
  G: AgentG(store, config=cfg.agent_g, workspace_root=root, llm=llm)
  H: AgentH(store, config=cfg.agent_h, llm=llm)
  单例：同一 (角色, store 根) 只建一次（D 与 C 必须拿到**同一个** C 实例）
  ⚠️ 工厂收下 LocalBackend 传进来的 store 并用它建实例（不许捕获外部 store：
```

**判据（正控，`tests/test_host_wiring.py`）**

1. `providers` 给全 ⇒ 登记表恰好覆盖 `schema.ROLES`（A–H）且每项 `kind == "factory"`；
2. `providers=None` ⇒ 表里没有 `A`，且 `wiring_status()["A"] == "no_provider"`，其余 7 个是 `wired`；
3. **真的派得出去**：`wired_conductor(...).summon(role="C", action="gaps", input_key=...)`
   ⇒ `status="done" / outcome="ok"`，台账一行 `called_by="M"`，`verify_tasks() == []`；
4. **多步**：连续 ≥3 次 summon（C/G/H），台账能按 `task_id` 重建成序列（P10 第 ③ 条）；

6. **默认零 LLM 调用**：`llm=None` 建出来的角色，其 `llm` 属性必须是 `None`；

| 注入 | 必须出现 |

## 幻觉防线（每条改动都适用）

1. **只能改伪代码里出现过的字段/键/状态/函数名**；需要新东西 ⇒ 先在本文件加条目。
2. **每个数字必须来自命令输出**（贴命令与时刻）；估出来的数一律标 `待实测`。
3. **三态不许折平**：没查成（`unknown` / `not_wired` / `judge_*`）≠ 查过了没有（`not_found`）。
4. **禁改区改动**：先备份到 `temp/`（含时间戳）+ 记 sha256 ⇒ 改 ⇒ `--baseline` 刷 hash ⇒
   四道门（或定向判据）。**AI 不写 `reviewers`。**
5. **默认关闭原则**：新接线在未显式启用时，行为与改前**逐字节相同**（P1 判据）。
6. **每条新判据必须带注入负控**（把实现短路 ⇒ 用例变红）；没有负控的判据不算判据。
