### 决策 1 — `SCHEMA_VERSION` 是否从 1 升到 2

- **现状与证据**：`schema.py:18` 逐字 `SCHEMA_VERSION = 1` `[本次确认]`；`schema.py:2702-2703` 是 `validate_table` 的**第一道**闸、
  **先于**所有行级校验：`if doc.get("schema_version") != SCHEMA_VERSION: raise ValueError(f"{table} schema_version 应为 …")` `[本次确认]`。
  本轮现算：两根 `data/*.json` 1404 份、其中 1322 份落进 `TABLES`、`documents.json` 实际 79 份 `[本次确认]`。
  `48-01` §0.1 的两根全量 `validate_table` = **通过 1322 / 失败 0 / 逃逸 0**；`46-01` §1.4 末段逐字"动它 `validate_table:2702-2703` 拒掉全部 1322 份旧快照"。
  本簇各条目的改动方向全在"放宽 / 纯增量 / 不动行形状"一侧：R-05 只改判据（`48-01` §1.1）、F-01 只填早已存在的 `bits`（`schema.py:1613` `[本次确认]`）、
  P-06 删一条 `raise`（`schema.py:1657-1663`）、EE-06 路线 2 只做"存在才校验"（`48-01` §1.9）、EE-07 路线 B 只改注释（`schema.py:1604-1605`）。
  同向证据：`48-01` §0.2 的实测 —— `claims[].status` 进必填 ⇒ **1270/52 红**、`Statement.grade` 进必填 ⇒ **1289/33 红** `[48-01 §0.2 引]`；

    `schema.py:2702` 这条闸的语义是"磁盘格式契约"，而本簇不动格式 `[判断类]`。
  - 成本：文件 0 / 落点 0 / 行数 0 / 会红测试 **0** / 快照重冻 0 / 真机影响 1322 与 969 两份基线**恒等**。

    （版本错 + 字段级 `ValueError`），症状不可分。
  - 兼容闸：1322/0/0 与 969 份基线都保持（`48-01` §0.1 的命令）。
  - 禁改区：`schema.py` 在 `.noai-paths:93`（`[category: schema-migration]`）**与** `:102`（`[category: eval-criteria]`）两条 `[本次确认]`；不动 ⇒ 不触发门。
- **方案 B：升到 2（并同批给迁移工具）**

  - 理由：版本号是"存储契约变过"的唯一机器可读信号（`AGENTS.md` 的平移表逐字"schema 迁移（磁盘格式契约）"）`[本次确认]`。
  - 成本：文件 ≥3（`schema.py` 1 行 + `store.py` 或新迁移脚本 + 判据）；落点 ≥3；估计行数 80–150（迁移工具）+1；

  - 兼容闸：**不通过** —— 必须先迁移。
  - 禁改区：`schema.py`（`:93`/`:102`）+ `store.py`（`:94`）双命中 `[本次确认]`；改后报备人审、不代签、需 2 名 reviewer。
- **不裁的默认后果**：保持 1。今天谁都读得出来；"这批判据被放宽过"只留在提交信息里 —— 下一批若有人拿 `SCHEMA_VERSION` 判"契约没动过"，
  就会把 R-05/P-06/EE-06 的判据放宽误当成"一直如此"。
