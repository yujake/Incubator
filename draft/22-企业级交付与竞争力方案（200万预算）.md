## §0 认知重置：这个项目现在处在什么位置

你给的标准是"真正能落地的企业级项目"。那就必须先把"落地"拆成可测的东西，再诚实地看现在到哪了。
下表每一行都是**实测**（符号级），不是印象。

### 1.1 成熟度评分（L0 无 → L5 行业标杆）

| # | 维度 | 现状 | 级别 | 实测证据 |
|---:|---|---|:--:|---|
| 1 | **模型连通性**（挂 key 能不能跑） | **完全没有** | **L0** | 全仓 `src/agentflow` grep `API_KEY\|api_key\|httpx\|requests.post\|base_url` **0 命中**；`llm.py:1092` 的 `def complete()` 在**自检桩类**里，不是真客户端；`pyproject.toml:22-24` 运行期依赖只有 `filelock` |
| 2 | 编排进生产路径 | 台账在生产里不被写 | L1 | `store.tx("tasks", actor="conductor")` 仅出现在 `conductor.py`；`Conductor` 只被 `tests/test_conductor.py`、`tests/test_scheduler.py` 导入（`draft/20` §1.1） |
| 3 | 子智能体真实性 | 进程内 handler | L1 | `SubagentBackend.call` 恒抛 `NotWiredError`（`conductor.py:229-256`）⇒ 记 `refused/not_wired` |
| 4 | 形式化验证 | **只探测不验证** | **L0** | `verify_tools.py:55-58` 只跑 `lean --version` / `coqc --version`；同文件逐字警告"猜'环境里应该有 lean'会让 `checked` 字段变成谎话" |
| 5 | 评测台 | 只有口径、没有 runner | **L0** | `schema.EvalResult` 有 `benchmark/version/split/k/decontamination/date/source` 七项必填（`:1485`）且 `verify.py:741` 逐字警告 **miniF2F 的四口径陷阱**（97%/69%/34.8%/40%）；但**没有任何代码跑过基准** |
| 6 | 持久化与并发 | 单文件 JSON + 文件锁 | L1 | `store.py` 的 `LOCK_ORDER` + 原子写 + 事件重放；无 DB、无 WAL、无多租户 |
| 7 | 观测与成本 | 有账、无观测 | L2 | `usage_ledger` + `tokenmeter`（`spent/tokens_for/by_role/retry_overhead`）；**无 trace / metrics / 告警**，且 `by_role`/`retry_overhead` 生产调用方 = 0 |
| 8 | 部署与运维 | **无** | **L0** | 无 `Dockerfile` / compose / Makefile（实测 glob 无命中）；无 `[project.scripts]`；**仓库不是 git 仓库** ⇒ 无 CI、无评审流、无历史 |
| 9 | 安全与密钥 | **无** | **L0** | 无密钥管理、无认证/授权服务；角色权限（`READ_ONLY_ROLES`/`for_role`）是**进程内约束**，不是对外权限面 |
| 10 | 检索数据源 | 有客户端、无工程化 | L2 | `providers.py` 用 `urllib` 直连 OpenAlex/Crossref 等（`:590`）；无配额管理、无缓存层、无来源合规审查 |
| 11 | **治理与质量纪律** | **企业级** | **L4–L5** | FC-01…FC-27 覆盖矩阵、三态纪律、禁改区 + 2 reviewer、1509 测试 / 8 deselect、9 条 lint 规则、11 个验收脚本、负控自证生效 |
| 12 | 产品/交付面 | 只有 CLI | **L0** | `python -m agentflow.cli`；无服务端、无 API、无审阅界面、无报告托管 |

**汇总**：12 个维度里 **6 个是 L0**，其中**第 1 条（模型连通性）是致命的** ——
"让每一次思考都在想真问题"（`draft/20` §14）这句话在今天**没有落地对象**：
系统里没有任何一次真实的模型调用。之前 20/21 号方案做的是**权限、责任、工具箱的设计**，
它们全都建立在"已经有会思考的智能体"这个前提上，而这个前提目前**不成立**。

> **对既有工作的定性（不作废）**：01–19 号是本项目最有价值的资产之一 —— 它把
> "数学产出的可信性"变成一个可机械检查的问题（引文逐字回验、证据等级、依赖闭合、
> **判据真空检测**）。**同行普遍做不到这一层**。它不是产品，但它是产品的护城河图纸。

## §2 目标：把"落地"与"比拼"写成可测指标

### 2.1 "能落地"的可测定义（O1–O4）

| # | 指标 | 目标 | 判据 |
|---|---|---|---|
| O1 | **端到端可跑** | 一条命令、一个真实 key、一个课题 → 一套产物 | `python -m agentflow.cli run --topic … --budget-usd 5` 退出码 0；产物含运行清单/断言台账/逐字回验的引文/报告/成本账 |
| O2 | **可复现** | 同输入 + 同 prompt 版本 + 同模型版本 ⇒ 台账可复算 | 干净机器重跑：成本差异 ≤5%，产物差异**逐项可解释**（不要求逐字节，要求差异有出处） |
| O3 | **失败可解释** | key 缺失 / 配额耗尽 / 超时 / 后端不可用 ⇒ 三态，不崩 | 四种故障各一条负控；`unknown ≠ fail ≠ pass` 全部落表 |
| O4 | **成本可控** | 单任务成本可预算、可熔断 | 超预算即停并落 `budget_exhausted`；成本账与 `usage_ledger` 一致 |

### 2.2 "能比拼数学产出"的可测定义（O5–O8）

| # | 指标 | 目标 | 为什么这样定 |
|---|---|---|---|
| O5 | **可验证产物数** | 稳定产出 Lean 可检查的引理/命题（内域集） | 排行榜名次会被质疑；**机器检查过的引理无法作假** |
| O6 | **引文零幻觉** | 逐字回验通过率 ≥99.5%，**虚构引文 = 0**（零容忍） | 这是同行最薄弱、而我们已具备机制的地方（`quoteverify`/`claimanatomy`） |
| O7 | **公开基准（口径分离）** | miniF2F 端到端 / ProofNet / PutnamBench 子集，**每个数字必须标口径** | `schema.py:1481-1483` 已记录同一 miniF2F 数字可指四件不同的事（差 13–30 点）——不标口径的成绩等于造假 |
| O8 | **人工介入率** | 数学家只做**选题与验收**，介入 ≤20% 的步骤 | "自动做研究"若仍需人写证明，那就不是产出能力 |

### 2.3 单位经济（企业级必须回答的问题）

| 项 | 定义 | 目标（P4 定稿） |
|---|---|---|
| 元/可验证产物 | （模型 + 检索 + 验证 + 复核）总成本 ÷ Lean 检查通过的产物数 | 初值目标 **≤ ¥200/产物**；> ¥1000 触发止损（§8） |
| 元/被否证猜想 | 反例/证伪也是产出，且更便宜 | 单独统计，不混入上式 |
| 人时/产物 | 数学家验收人时 | ≤0.5 人时 |

## §3 竞争定位（诚实版）

### 3.1 不能拼的四件事（先说，避免把预算烧在必败战场）

| 不拼 | 原因 |
|---|---|
| **基础模型能力** | 2M 买不到预训练，也买不到前沿模型的独占通道 |
| **算力规模** | 同类实验室（AlphaProof 等）的单项目投入是 **TPU-days 量级**（本课题 08 号报告已量化并标注其不确定项）；我们只有 API 调用额度 |
| **通用定理证明 SOTA** | 需要长期模型迭代 + 巨大算力，且榜单领先不转化为客户价值 |
| **端到端通用数学研究** | 领域太宽，验证成本会吃掉全部预算 |

### 3.2 能拼的三件事（护城河在既有资产里）

| 楔子 | 为什么我们能赢 | 已有基础 |
|---|---|---|
| **① 可验证性优先** | 所有结论必须带机器检查或显式标注"不可验证"；**"验证通过"零假阳**。竞争者普遍给"看起来对的自然语言证明" | `verify.py` 的证据等级 / `proof_claim_rests_on_weaker_evidence` / 依赖闭合 |
| **② 引文零幻觉** | 逐字回验 + 拒答机制。这是**学术诚信的硬需求**，也是企业客户法务最在意的一条 | `quoteverify`（逐字回验）、`claimanatomy`（断言解剖）、`dedup`（同一文献单一主键） |
| **③ 细分领域深度** | 选定 1–2 个**可形式化**的子领域，目标产出"**可合并进 Mathlib 的引理**"——这是可核验、可署名、可累积的成果 | 现有 12 张表 + 关系图 + 攻坚/反例回流机制 |
| （④ 成本-结果比） | 用模型分级路由（贵模型只做判断、便宜模型做搬运）+ 缓存 + 复用，把单位成本压到可控 | `tokenmeter` 预算守卫 + 工具箱设计（`draft/20` §14） |

**卖点一句话**：企业/机构买的不是"我们排第几"，而是"**给我一份可审计、可复现、引文经得起查、
结论带机器检查的数学研究流水线**"。

## §6 预算分配（200 万）

| 项 | 金额（万元） | 占比 | 依据与口径 |
|---|---:|---:|---|
| 人力（6 人 × 5 个月 = 30 人月） | **100** | 50% | 3.33 万/人月全成本（含税与社保口径，**需按你的实际薪酬确认**） |
| 模型推理 API | **40** | 20% | 研发 + 评测消耗；**最大不确定项**，见下 |
| 形式化验证与算力 | **15** | 7.5% | Lean 4/Mathlib 环境、CI runner、向量/嵌入、少量 GPU 或纯 API |
| 数据与专家复核 | **20** | 10% | 内域集构建、数学家抽检与验收（O8 的分母）、文献合规审查 |
| 安全/合规/法务 | **10** | 5% | 密钥与 RBAC、数据来源许可、客户合规包 |
| 缓冲 | **15** | 7.5% | **偏薄**：优先用于 API 超支 |

**API 费用的估法（可复核）**：单任务 ≈ 200 次模型调用 × 平均 20k tokens ≈ 4M tokens；
按混合路由（贵模型 20% + 便宜模型 80%）折算后 ≈ **US$8–15/任务**；
40 万 ≈ US$5.6 万 ⇒ 可支撑 **约 4,000–7,000 个任务**（含评测与重试）。
**超支对策（预授权）**：① 提高便宜模型占比；② 加缓存与去重；③ 把 P4 的基准规模减半；
④ 动缓冲。**不允许**的做法：压缩 P2 的验证后端（那是护城河）。

## §7 交付标准（企业级 DoD）

### 7.1 全局五条（每一件交付物）

| # | 标准 | 判据 |
|---|---|---|

### 7.2 逐阶段 DoD
