## §2 三态纪律在这四条新面上的落点（这一批最要紧的一节）

新面全是"读数面"，所以每一条都按既有那三档写：`computed` / `unreadable`（没查成）/
`not_applicable`（还没写过）。最容易折错的三处：

1. **预算**：寄存器不在盘上 ⇒ `not_applicable`（还没设过，合法初态），**不是**"不限量"；
   寄存器读不出来 ⇒ `unreadable` + `problem` 原样带出，闸门退回命令行给的上限
   （少花是安全的那一侧）。已花那一栏另有一个 `spent_tri`：账本读不出来时金额是
   `null`（前端显 `unknown`），**不是 $0.000000** —— "没查成"与"一分钱没花"是两个词。
2. **在飞**：`answer` 只有三档字面量（`有` / `没有` / `没查成`）。这一格是用户决定
   "要不要叫停"时唯一能看的东西，所以读不出来时**必须**显"没查成"：把它画成"没有"
   会让"判不了"看起来像"没人跑"。`running_loops` 自己也是两路取并集（会话面 + 进程面），
   本页把 `unreadable_sessions` 单独列出来。
3. **状态报告**：`out/review` 下没有 `STATUS-*` ⇒ `not_applicable`（还没跑过那一档），
   不是"没查成"。

## §3 两处由判据当场抓出来的真实缺陷

**① 处理器的名字冲突：`POST /api/budget` 被读面吃掉了。**
`GET /api/budget`（读面）与 `POST /api/budget`（写面）分处两条零交线，两个函数**都叫**
`handle_budget`，而 `routes.handler_for(name)` 是按**名字**在三条子表里找处理器的
（`readers` 先被查到）⇒ 写请求派到了读面：实测 `POST /api/budget` 回了一份读数的 JSON
和 200，`--allow-writes` 那一道闸门一步都没走。读面那个改名为 `handle_budget_view`
（与 `handle_run_view` 同一形状），并把这件事写进它的 docstring。写这条时的新判据
（`test_the_budget_endpoint_refuses_without_writes_or_confirmation`）当场就抓到了它 ——
如果只写"回执 ok"那一条，这个洞会一直留着。

**② "路径不许重复"这条反真空判据的口径太窄。**
`test_the_route_table_is_the_single_source_for_dispatch` 原来断言 `ROUTES` 里的**路径**
不许重复；而 `GET /api/budget` 与 `POST /api/budget` 是**同一条路径上的两种动作**
（REST 里是常态）⇒ 一次**正确**的登记会被判成重复。判据改成按 `(方法, 路径)` 去重，
并补了"真重复一个 `(方法, 路径)` 必须红"的反真空那一半。
