## §1 规范形态（重新写过的版本；施工照这一节做）

### 1.1 这份记录是什么（业主 2026-10-08 深夜：**名册 + 对照表**）

业主原话：

> 「我认为可让每个代理记录其子代理时用名册（如 A1、D1、F1、F2……且带一句任务简介），
> 秘书维护对照表（就像查电话簿，看每个子代理代号的绝对编码是什么）然后做接线员的操作，
> 如此名册的增、删我觉得都应由秘书做，代理只负责说"我想加一个 D3，干什么活"或者
> "A1 退役"之类，因为要同时改名册和对照表。秘书维护对照表的好处是它还知道了子代理的角色，
> 代理的"查"自己调用工具看伪表，要能看到名册及工作状态，因为代理主要关注角色和工作。」

⇒ 这份记录有**两半**（都在**父这一侧**，措辞："父代理记录其子代理时用名册"）：

| 半 | 是什么 | 谁写 | 内容 |
|---|---|---|---|
| **名册** `R(P)` | 父 `P` 给自己名下子代理起的**本地名** | **秘书**（增、删都由它做） | 每一项：`本地名`（`<角色字母><序号>`，如 `A1` / `D1` / `F1` / `F2`）＋**一句任务简介**＋工作状态 |
| **对照表** `X` | **电话簿**：本地名 → **绝对编码** | **秘书**（与名册**同一次**改） | `(父, 本地名) → task_id`（绝对编码），并在读侧带上**角色**与状态 |

三条口径（每一条都有理由，改它要连带改判据）：

1. **本地名是相对的、绝对编码是全局的** ⇒ 必须有一张对照表：`D3` 只在"我这一个父"里有意义，
   而 `task_id`（`t-00xx`）是台账里唯一的那个东西。业主说的"接线员"就是这件事：
   代理说名字，秘书把它接到编码上（出站）／把编码翻译回名字（入站）。
2. **名册的增、删由秘书做，代理只说意图**（"我想加一个 D3，干什么这个活" / "A1 退役"）——
   理由业主已给："因为要同时改名册和对照表"。**代理不写名册、不写对照表。**
3. **"查"由代理自己调工具**（"看伪表"）：那个视图必须**同时**给出名册（本地名 + 一句简介）
   与**工作状态**，因为"代理主要关注角色和工作"（本地名里带角色字母，简介就是那件活）。

**与台账的关系（不许三处漂）**：名册与对照表都是**派生的索引**，唯一真相仍是 `tasks` 行。
所以三处之间的关系要有一条对账判据（§1.6 的判据②）：对照表里每一条 `(父, 本地名) → 编码`
必须能对回台账里一行真行；台账里每一条挂在 `P` 名下的**代理行**也必须能在对照表里找到
（找不到 ⇒ 如实报"未登记"，不许静默补一个名字）。名册与对照表**只许追加**（append-only），
删以"退役"事件行表达 —— 这样"某天名册里少了谁"永远读得回来。

- **成员只许是代理，不是工作项**：业主 A1=甲 之后 `tasks` 装两类行 ——
  **代理行**（`kind == ""`）才进名册；**工作项行**（`kind` 非空：`delegation` /
  `message` / `notice` / `report`）是"活"，它们进的是另一份读数
  `in_flight_items(P)`（"某条边名下未消的项"）。两轴一起才是 T2 的消边谓词，
  **不是互相代替**（工作项的收件人写成**本地名**，见 §1.6 的格式）。
- **每一次删（退役）都要留下消边读数**（谁说的、谁做的、依据哪几条）—— 否则"退役过"与
  "从没派过"在盘上长得一样。

### 1.2 增（业主第 4 句 + 名册口径）

**先纠一条包含关系（业主 2026-10-08 深夜的原话）**：

> 「派活不一定是增（可能是给已有活跃子代理派活），但增一定是派活。」

⇒ **增 ⊆ 派活**，而**派活 ⊋ 增**。所以"增"不是"派活"的同义词，而是派活这个事件在
记录上的**一个分支**：派活那一刻父要顺带决定"**复用**一个已有活跃子代理"，还是"**新起**一个"。

| 派活的去向（父在那一刻决定） | `R(P)`（代理轴） | 工作项轴 | 备注 |
|---|---|---|---|
| **复用**：派给一个已经活跃的子代理 | **不变**（不增） | +1（一条派活项，收件人 = 那个代号） | A2=甲的"同一个父复用"＋ A6=丙 的 `keep_alive`（"做完一件还待命"） |
| **新起**：拉起一个新的子代理 | **+1** 个代号 | +1（一条派活项，收件人 = 新代号） | 只有这一支是"增" |

增这一档的其余几格（两条分支共用）：

| 问题 | 答案（按业主口径） |
|---|---|
| 什么时候发生 | **派活那一刻**（`summon` / `summon_many` 这一步）——它是增的**唯一入口** |
| 谁决定 | **发起方（父）**：派给谁（角色）、派什么、复用还是新起 —— 模型给的是**意图**；**父不写名册** |
| 谁写名册/对照表 | **秘书**（`roster_add`：同时写名册那一行与对照表那一行；本地名由秘书按"同父同角色序号"分配） |
| 谁洗格式 | **秘书**（委托离开本体之前走一遍，与 `roster_add` 同一趟） |
| 谁落台账行 | 框架（`conductor` 一处建行：`_write_new_row` 是唯一的新行临界区；**秘书不建 `tasks` 行**） |
| 顺序 | ① 父说"加一个 D3，干这个活" → ② 秘书洗格式 + 定本地名 → ③ `conductor` 落行拿到**绝对编码** → ④ 秘书把对照表那一行补上绝对编码、名册那一行补上简介与状态（④ 失败 ⇒ 如实留痕，并在读侧标"未登记"，**不许**静默给一个新名字） |
| 幂等键 | `input_key`（已有：`<action>@<12hex>`；**不许挪用**，它是环检测键） |
| 读数 | 新起 ⇒ 名册 +1 项（本地名 + 一句简介）；复用 ⇒ 名册**逐字不变** |

**判定"复用还是新起"的口径不是新发明**：A2=甲（"同一个父复用、别的发起方新起一个"）
＋ A6=丙（父声明 `keep_alive`："这个实例做完一件还待命"）。缺了这两条，复用就没有判据，
于是"派活必然新起一行"——那正是今天代码的形态（见 §2 **E14**）。

**"洗一遍格式"的边界**（这一段是给施工的人看的，越界就是改内容）：

- **可以洗（格式面）**：动作真名（错名映到 `specs/<role>.py` 的候选）、`params` 的键名、
  必填字段、受控词表取值、`instance` 标签、`input_key` 归一；
- **一个字不许动（内容面）**：派给谁、派什么、`params` 里的值、`notify` 的正文与主张、
  证据与结论；
- **洗不动就受控拒绝**：不许静默补一行默认值；拒绝理由走受控词表（`REFUSAL_REASONS`）；
- **洗前 / 洗后并列落账**（`note_decision(before=…, after=…)`）：否则"模型说错了"与
  "秘书替它补对了"在盘上分不清；
- **权限面一个字不放宽**：过边表、闸门、能力面仍在 `conductor`；秘书不许因为"洗"而让一次
  本该被闸门拒掉的派活过门。

### 1.3 删（业主第 2、3 句 + 名册口径："A1 退役"）

- **触发（事件）**：某个子代理**宣布收工** —— 写自己那一行的终态 + 把交差通报挂到**父**名下
  （后者是 `D89` 修完的形态）。**宣布不是决定。**
- **决定（谁说）**：**父**。只有父知道"我还有没有别的子在跑"；子判不了"我是不是最后一个"，
  所以子**不许**自己删。父说的是**一句话**：「A1 退役」—— 名字是名册名，不是绝对编码。
- **执行（谁改）**：**秘书**（业主逐字："名册的增、删我觉得都应由秘书做……因为要同时改名册
  和对照表"）。它做三件事，**同一趟**：① 按下面的判据核对（不许在子还在跑时把它划掉）；
  ② 名册里那一项标"退役"（**只追加一行退役事件**，不物理删行 —— 这样"名册里少过谁"读得回来）；
  ③ 对照表那一条同步标退役（本地名 → 绝对编码那一行保留，编号**不回收**：`A1` 退役之后
   `A2` 继续，绝不让同一个名字换一个人）。
- **判据（2026-10-08 深夜订正：按业主给的算法，见 §1.9）**：退役**不是**一个四合一谓词，
  而是**三个分支**的一趟查询 ——— A1 还在跑 ⇒ 把 A1 **最近的工作报告**端给父、不退役；
  A1 在等待 ⇒ 查 **A1 名下**的活跃子代理：空 ⇒ 执行退役，非空 ⇒ 把那些子代理的
  **任务简介**端给父（"A1 还在干什么活"）、不退役。

  > **我此前读错的一处**：把"无活跃子代理且自身完全停止"读成了**对父**的要求
  > （写成"P 自己已完全停止"）。业主的算法说明这两条都是**对 A1 自己**说的 ——
  > "父名下是否还有别的活跃子代理"**不是**退役条件（否则只能退最后一个子，荒唐）。
  > 台账行层面还会附一条**读数**（A1 名下未消的项有几条），但它**不参与判定**
  > （附在回报里，见 §1.9 末）。
- **核对不过 ⇒ 受控拒绝 + 带内容回报**：秘书回的不是干巴巴一句"不行"，而是**把父要看的
  东西端上来**（A1 最近的工作报告 / A1 名下那些活的简介），**名册一个字不动**
  （不许先划掉再补）。
- **顺序**：入口最先、**消边最后**（业主 T2 逐字）；释放严格**自叶向根**。
- **幂等**：`(本地名, 尝试)` 只许退一次；重复的"A1 退役"不产生第二条退役事件。
- **父的"删"与台账的关系**：父说的是名字，秘书译成绝对编码之后才动台账里那一行
  （或写父侧消边读数）—— **没有名字就没法退役**（对照表查不到 ⇒ 受控拒绝并点名）。

### 1.4 查（业主第 5 句里"自动化"的那一半 + "看伪表"）

- **谁查**：**代理自己调工具看**（业主逐字："代理的'查'自己调用工具看伪表"）。
  视图叫"伪表"是因为它是**名册的投影**（不是台账原文）。
- **必须看到三样**（业主逐字："要能看到名册及工作状态，因为代理主要关注角色和工作"）：
  ① **名册名**（本地名，角色字母 + 序号 —— 角色就在名字里）；
  ② **一句任务简介**（那一项是干什么活）；
  ③ **工作状态**（活跃 / 待命 / 已停 / 退役，以及它名下有没有未消的项）。
- **三态**：读到 / 确实为空 / **没读成** —— 三者不许折平（读不成时报"没读成"，
  不许报"名下没有子代理"）。
- **两轴分开查**：名册（代理轴）与 `in_flight_items`（工作项轴，收件人写**本地名**）。
- **查不许改状态**（只读；与"渲染即 seen"那条区分开：seen 是框架在渲染时写的，
  不是查出来的）。
- 名册、对照表与台账三处不许漂：对账判据见 §1.6 的判据②。

### 1.5 一张图（三个操作与两份读数）


### 1.6 名册与对照表的落点、格式与对账判据（施工照这里）

**落点**（都归秘书写，append-only；与既有 `secretary/decisions-<role>.jsonl` 同一族的位置）：

```text
<workspace>/secretary/roster.jsonl          # 名册事件流（一台工作区一份）
  {"kind":"add",    "parent":"t-0003", "name":"D1", "role":"D", "task_id":"t-0011",
   "brief":"把 X 的族构造证据补齐", "at":…}                     # 增（拿到绝对编码后补 task_id）
  {"kind":"retire", "parent":"t-0003", "name":"D1", "task_id":"t-0011",
   "why":"子已停 + 无别的活跃子 + 父已停 + 板项轴空", "at":…, "by":"<秘书>"}   # 删（退役）
  {"kind":"keep_alive","parent":"t-0003", "name":"D1", "value":true, "at":…} # A6=丙 的待命声明
<workspace>/secretary/roster-index.jsonl    # 对照表（电话簿；一条一行，只追加）
  {"parent":"t-0003", "name":"D1", "role":"D", "task_id":"t-0011", "at":…}
```

- **本地名的分配**：`<角色字母><序号>`，序号**每个父、每个角色各一套**（`A1` / `D1` / `F1` / `F2`），
  由秘书在 `roster_add` 时按"当前最大序号 + 1"分配；**退役不回收序号**。
- **工作项行写本地名**：`open_item` 的 `detail`（或将来的 `to_name` 格）写本地名，
  绝对编码仍落在 `parent_task_id` 上（**两处一个键**的纪律不破）。
- **判据②（对账，必须有一条机器判据）**：三个方向各一条 ——
  ① 对照表每一条 `(parent, name) → task_id` 都能在台账里找到那一行，且那一行的
  `parent_task_id == parent`、`kind == ""`；
  ② 台账里每一条挂在 `parent` 名下的**代理行**都能在对照表里找到（找不到 ⇒ 读侧标"未登记"，
  报一条读数，**不许**静默给个新名字）；
  ③ 名册里"活跃"的项数 == `_in_flight_children_of(parent)` 的条数（两轴分开之后这一条才成立）。
- **判据③（不许三处漂）**：名册/对照表**只许追加**；任何"物理删行"的实现都算红
  （否则"某天名册里少了谁"读不回来）。
- **谁读**：代理用工具查（§1.4 的视图）；框架判据（消边、扇出、读数）读**对照表 + 台账**
  的现算结果，不读内存缓存。

### 1.7 "造一个子代理"的完整流程（业主 2026-10-08 深夜："这对父代理如何造一个子代理提出了很高的要求，请明确流程"）

**父代理要给的四样，与它一概不许碰的四样**（这是"高要求"的边界）：

| 父**必须**给（内容面，模型自己写） | 父**不许**碰（框架/秘书的面） |
|---|---|
| ① 角色字母（`A`–`H`/`V`，决定名册名里的字母） | ① 绝对编码（`t-00xx`） |
| ② 干什么活（`action` + `params`） | ② `parent_task_id`（框架按"我是谁"填） |
| ③ **一句任务简介**（进名册；退役时读的人靠它认人） | ③ 名册行与对照表行（秘书写） |
| ④ 要不要"做完一件还待命"（`keep_alive`） | ④ 序号（提名可以，定号是秘书的事） |

可选的第五样：**提名本地名**（"我想加一个 D3"）。提名可用 ⇒ 用它；提名被占或跳号 ⇒
**受控拒绝**（**不许静默改名** —— 名字是父子之间的共同指称，悄悄换一个会让后面的对话指错人）。

#### 步骤（每一步都写清：谁做 / 写什么 / 失败时盘上是什么）

| # | 谁 | 做什么 | 写什么（落点） | 失败姿态 |
|---|---|---|---|---|
| 0 | 父（模型） | 发出"造/派活"意图（形状见下） | 会话事件 `agent_step`（既有） | 形状不合法 ⇒ 打回（既有） |
| 1 | **秘书** | **洗格式**（S1g）：真名 / 键名 / 必填 / 受控取值 / `instance` / `input_key` 归一；**内容面一字不动** | `secretary/decisions-<role>.jsonl`（`before`/`after` 两格） | 洗不动 ⇒ 受控拒绝（受控词表里的理由码），**一行都不落** |

#### 为什么是"先拿编码、后落名"（一笔成形，但有一个必须认清的窗口）

- 反过来（先给名后拿编码）会造出**"有名字、接不到人"**的项：电话簿里一个号码拨不通，
  比没有这个名字更坏。
- 所以顺序是第 3 步（编码）→ 第 4 步（名册 + 对照表）。代价是第 4 步失败时出现
  **"有代理、没名字"** 的窗口。这个窗口的处理写死为：读侧如实标 **"未登记"** + 下次补登记；
  **绝不允许**在提示词里给一个临时名。

#### 模型面（形状）要动的地方（会碰冻结面）

今天的 `summon` 只有 `role` / `action` / `params` / `instance`（`agent_loop.SHAPES`）。
按名册口径至少要加两格：**`brief`（必填，一句简介）**与 **`new_or_reuse`（新起 or 复用）**；
"退役"要一个新形状 `retire`（或一件写口工具）。**这两处都动冻结面**
（`agent_surface_snapshot` / `tool_surface_snapshot` 金标 + `PROMPT_VERSION`），
按 B1=丙（先归一化版本行、再逐格看）走人做的重冻。

## §1.8 消息：父 → 子、子 → 父（名册口径下的两个方向）

> 口径来源：业主 T20（"留言给谁就让谁**亲自**消化，禁止代读"）、T21（"知道我的父代理是谁、
> 子代理有谁，然后往它们**按编号**沟通"）、T21 附二（`#public` 的可见面 = 发信人的子代理），
> 以及名册口径（本地名 ⇄ 绝对编码，秘书做接线员）。

### 下行：父 → 子

| 步 | 谁 | 做什么 |
|---|---|---|
| 1 | 父 | 说"给 `D1` 发一条：<内容>"（收件人写**本地名**；`to` 也可以是 `ALL` = 我名下所有子代理） |
| 2 | **秘书（接线员）** | `D1` → 绝对编码（对照表；查不到 ⇒ 受控拒绝并点名）；`ALL` ⇒ 展开成**我名下名册的每一项** |
| 3 | **conductor** | 每个收件人开一条 `kind="message"` 的**项**：`parent_task_id = <收件人的绝对编码>`（**收件人**的编号，D89 口径）、`called_by = <我>（我自己的本地名/角色）`、`expects="ack"`；带正文的另写一行手稿（`handoffs`），项里只写"有一份手稿 NNNN" |
| 4 | 收件人 | 在自己的下一步开头渲染到它（S1i 的 `board_digest`，**渲染即 seen**）并**自己**读、自己 ack —— **父不许代读、不许替它消化**（T20） |
| 5 | 读数 | 谁发的（本地名）、发给谁（本地名）、什么时候被渲染（`seen_by`/`seen_step`）、什么时候 ack（`item_close=acked`） |

### 上行：子 → 父

| 步 | 谁 | 做什么 |
|---|---|---|
| 1 | 子 | 说"给父发一条：<内容>"（收件人写**父的本地名** = 父在祖父名册里的名字；顶层父没有本地名 ⇒ 写"（顶层）"） |
| 2 | **秘书（接线员）** | 译成父的绝对编码（顶层 ⇒ 直接就是它那一行的 `task_id`） |
| 3 | **conductor** | 开一条项挂在**父**名下（`parent_task_id = 父的绝对编码`、`called_by = 子的本地名`、`expects=ack`） |
| 4 | 父 | 自己的下一步渲染到、自己读、自己 ack（**子不许替父读**） |
| 5 | 子**宣布收工** | 同一形态：终态 + 交差通报挂到父名下（收件人写父的本地名、发信人写子的本地名，`D89` 的形态） |

### 广播（两个方向都按"名册展开"，不新开通道）

- **父广播给子**：`to = ALL` ⇒ 秘书按**我名下名册**逐项开 `message` 项（内容一条、行为 per-recipient；
  T21 附二的"乙"形态）；
- **子广播给它的子**：同一做法（级联**自愿**，子决定要不要继续向下 —— T21 逐字）；
- **主控 M 的全树广播**：逐层向下调用即可（不需要特权通道，T21 逐字）；
- **`#public`**：可见面 = **发信人的直接子代理**（T21 附二"乙"）；老消息按角色级兜底并留读数。

### 三条不许（都是业主点过名的）

1. **不许代读**：发给谁的，只有谁能读；父转发内容必须**盲转**（不改、不读、留痕），
   或者干脆拒绝（见下）；
2. **不许用"再起一个实例"当传话**（S12 的判据会报）；
3. **兄弟之间不直接发**：边表里没有这条边 ⇒ 想联络就**各自和自己的父说**（父是接线员，
   不是邮局）。是否允许父"盲转一条给兄弟"我今天没有业主原话，登记为待一句话（§5）。

## §1.9 退役是一个工具，它自己是一趟三分支的查询（业主 2026-10-08 深夜逐字）

业主原话：

> 「可以把父代理宣布子代理退役做成一个 tool，但这里面其实是：比如父代理拿着 A1 说要把它
> 退役，然后秘书查看 A1 是否活跃，若活跃则将 A1 最近工作报告父代理，若在等待则继续查对应
> 真实代理的活跃子代理表，若空则执行退役，若有成员则继续查询 A1 活跃子代理的任务简介，
> 报告父代理说 A1 还在干什么活。」

⇒ 工具名（暂定）`retire`，调用者是父，执行者是秘书。**它有三条出路，只有一条会真的退役**：

```text
retire(父 P, 名册名 "A1"):
  ① A1 活跃（此刻在跑一件活：status == running，或它名下有一条正在做的项）
       ⇒ **不退役**；把 **A1 最近的工作报告** 端给 P
         （读侧：A1 作为发信人的最新一条手稿/交差通报 —— 见 E19）
  ② A1 在等待（已停下、实例还在：keep_alive 待命，或已写终态但未退役）
       ⇒ 查 **A1 名下**的活跃子代理表（`active_children(A1)`，代理轴，S1e 之后才准）
            · 空   ⇒ **执行退役**：名册追加 retire 事件 + 对照表标退役（编码保留、序号不回收）
            · 非空 ⇒ **不退役**；逐个查那些子代理在 **A1 的名册**里的**任务简介**，
                      端给 P："A1 还在干什么活"（附绝对编码与状态）
  ③ A1 未登记 / 对照表读不成 / A1 名下子代理表读不成
       ⇒ **受控拒绝**，把"哪一步没读成"原样报给 P（三态纪律：**没读成 ≠ 可以退役**）
```

三条配套口径：

1. **"活跃"和"在等待"的分界就是"它在不在跑"**：在跑 ⇒ 报最近报告（父要先看它刚报了什么）；
   停下但实例还在（`keep_alive` 待命）⇒ 走第 ② 支。⇒ **待命本身不妨碍退役** ——
   这一条订正了我此前 S2' 那句"待命 ≠ 完全停止 ⇒ 不许消边"（**读错了**，见下）。
2. **第 ② 支要看的是 A1 自己的子代理表**，不是父的（父还有别的活跃子代理与 A1 能不能退役无关）。
3. **附一条读数（不参与判定）**：A1 名下未消的**项**有几条（`in_flight_items(A1)`）。
   它是本仓加的（子交差的通报没被读掉时，退役会让那条通报从此没人看）——
   **只作为回报里的一行**，不额外拦；若业主要它参与判定，改一处。

**判据（红/绿）**：

- **正控**：A1 在等待 + A1 名下没有活跃子代理 ⇒ 退役执行、名册追加、对照表同步、序号不回收；
- **负控（三条，各对应一支）**：① A1 在跑 ⇒ **不许**退役，且回报里带 A1 最近的工作报告原文
  （不是"它还在跑"这种空话）② A1 在等待但名下有活跃子代理 ⇒ **不许**退役，且回报里逐个列出
  那些子代理的任务简介 ③ 重复退役 ⇒ 只有一条退役事件；
- **反真空**：A1 未登记 / 对照表读不成 ⇒ 受控拒绝（**不许**当"已退役"或"可以退役"）。
