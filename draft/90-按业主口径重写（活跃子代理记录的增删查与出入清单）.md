## §1 规范形态（重新写过的版本；施工照这一节做）

### 1.1 这份记录是什么

- **名字**：父侧**活跃子代理记录** `R(P)`（`P` = 某个父代理/父实例）。
- **内容**：`R(P)` = `P` 派出去、**还没消边**的那些**子代理的代号**（`task_id`）。
- **归属**：它在**父这一侧**（业主措辞："父代理关于活跃子代理的记录"）。读它的是父与框架
  判据；改它的人只有父的那两个决定点（派活、消边）。
- **成员只许是代理，不是工作项**：业主 A1=甲 之后 `tasks` 装两类行 ——
  **代理行**（`kind == ""`）才是"子代理"；**工作项行**（`kind` 非空：`delegation` /
  `message` / `notice` / `report`）是"活"，它们进的是另一份读数
  `in_flight_items(P)`（"某条边名下未消的项"）。两轴一起才是 T2 的消边谓词，
  **不是互相代替**。
- **一致性（不许两本账）**：本仓的读侧实现是派生的（对 `tasks` 行现算），因此必须有一条
  判据把"记录"与"派生读"钉成同一件事（§3 的判据①）；并且**每一次删都要留下父侧消边读数**
  —— 否则"消过边"与"从没派过"在盘上长得一样。
- **为什么仍然不建一张表/一列**：`R(P)` 是可从台账现算的（`parent_task_id` + 行的出身 +
  终态），加一份缓存就多一个会漂的副本（I-9 的同族）。所以"维护一份记录"落在盘上的形态是
  **两个写入点**（派活建行 / 消边落终态+读数）加上**一条现算读侧**。

### 1.2 增（业主第 4 句）

| 问题 | 答案（按业主口径） |
|---|---|
| 什么时候发生 | **派活那一刻**（`summon` / `summon_many` 这一步） |
| 谁决定 | **发起方（父）**：派给谁、派什么、几个实例 —— 模型给的是**意图** |
| 谁洗格式 | **秘书**（委托离开本体之前走一遍） |
| 谁落册 | 框架（`conductor` 一处建行：`_write_new_row` 是唯一的新行临界区） |
| 幂等键 | `input_key`（已有：`<action>@<12hex>`；**不许挪用**，它是环检测键） |
| 读数 | `R(P)` 加一个代号（且那个代号必是 `kind == ""` 的代理行） |

**"洗一遍格式"的边界**（这一段是给施工的人看的，越界就是改内容）：

- **可以洗（格式面）**：动作真名（错名映到 `specs/<role>.py` 的候选）、`params` 的键名、
  必填字段、受控词表取值、`instance` 标签、`input_key` 归一；
- **一个字不许动（内容面）**：派给谁、派什么、`params` 里的值、`notify` 的正文与主张、
  证据与结论；
- **洗不动就受控拒绝**：不许静默补一行默认值；拒绝理由走受控词表（`REFUSAL_REASONS`）；
- **洗前 / 洗后并列落账**（`note_decision(before=…, after=…)`）：否则"模型说错了"与
  "秘书替它补对了"在盘上分不清；
- **权限面一个字不放宽**：过边表、闸门、能力面仍在 `conductor`；秘书不许因为"洗"而让一次
  本该被闸门拒掉的派活过门。

### 1.3 删（业主第 2、3 句）

- **触发（事件）**：某个子代理**宣布收工** —— 写自己那一行的终态 + 把交差通报挂到**父**名下
  （后者是 `D89` 修完的形态）。**宣布不是决定。**
- **决定（谁）**：**父**。只有父知道"我还有没有别的子在跑"；子判不了"我是不是最后一个"，
  所以子**不许**自己删边。
- **判据**（业主两句合起来，再加本仓 T16 之后必须有的一条）：

  ```text
  can_release(P, c) =
        该子 c 已停（终态：done / failed / cancelled，带 ended_at）
    and R(P) 里除 c 之外没有别的成员（"无活跃子代理"：子全停或为空）
    and P 自己已完全停止（已写终态、入口已关；"待命"（keep_alive）不算停止）
    and 板项轴为空：in_flight_items(P) == []（P 名下没有未消的项）
  ```

  第三条是本仓必须补在业主那句之外的：子向我交差的通报本身也是一条**项**，
  它没消就消边，等于"子说完了话、父已经不算它了"（`draft/84` §T21 附二 / `D89`）。
- **执行**：成立 ⇒ **从 `R(P)` 里删去那个代号**。落到盘上 = 那一行离开非终态，
  **并且父侧写一条消边读数**（谁、什么时候、依据上面哪几条）。
- **顺序**：入口最先、**消边最后**（业主 T2 逐字）；释放严格**自叶向根**。
- **幂等**：`(边, 尝试)` 只许删一次；重复的"子宣布收工"不产生第二条消边读数。

### 1.4 查（业主第 5 句里"自动化"的那一半）

- 自动、只读、**三态**：读到 / 确实为空 / **没读成** —— 三者不许折平；
- **两轴分开查**：代理轴 `R(P)`、工作项轴 `in_flight_items(P)`；
- 不许缓存成第二本账（A1=甲 之后台账是唯一真相）。

### 1.5 一张图（三个操作与两份读数）

```text
增：派活（父决定）── 秘书洗格式 ──▶ 框架落行            ⇒ R(P) 加一个代号
删：子宣布收工（事件）──▶ 父判定 can_release ──成立──▶ 落终态 + 父侧消边读数
                                                          ⇒ R(P) 删去那个代号
查：R(P)            = 代理轴（kind == ""）
    in_flight_items = 工作项轴（板项；含子交差的那条 notice）
```

## §2 出入清单（今天的代码 vs §1）

每条格式：**形态 → 证据（`文件:行` + 实测读数）→ 与业主口径的差 → 应当是什么 → 落点与判据 → 批次**。

### E1 板项被算成"活跃子代理"（最重；会让 T1 重跑半路卡住）

- **形态**：`_in_flight_children_of(task_id)` 只按 `parent_task_id` + `status ∈ {pending,
  running}` 数行，**不看出身**（`conductor.py:676-700`）；而 `open_item` 建的行
  `status="pending"`（`conductor.py:874`），板的状态机 `_set_item` **只改 `item_state`、
  从不改 `status`**（`conductor.py:910-917`）⇒ **一条已 ack 的板项永远是"在飞的子代理"**。
- **实测**（`temp/_probe_board_vs_fanout_and_dispose.py` / `temp/_probe_fanout_refusal_reason.py`）：
  父名下挂 20 条 `notice`（一条代理都没有）⇒ `_in_flight_children_of(父)` = **20** ⇒
  同一父下派活被拒 `fanout_exceeded`，detail 逐字「此刻在飞 20 个子代理，达到发起方 M 的
  同时在飞上限 20」；**负控**（不挂板项）同一个调用走到执行（`not_wired`）。
  板项全部走完 `queued → seen → done(acked)` 之后读数**仍是 20**。
- **与业主口径的差**：§1.1 —— `R(P)` 的成员"只许是代理"。今天这条读数把**工作项**算了进去。
- **应当是什么**：实例轴只数代理行（`kind == ""`）；工作项留给 `in_flight_items`。
- **落点与判据**：`conductor._in_flight_children_of`；判据 = 正控（20 条板项不拒派活）+
  负控（真子代理行照旧占名额，`test_fanout_admission` 既有那一批不许变绿变红）+
  边界（`kind="delegation"` 的派活项**不算**在飞代理，但 `in_flight_items(父)` 数得到它）。
- **批次**：**S1e**（T1 重跑之前的硬前置 —— 现在这个形态会让 M 在累积约 20 次交差后开始拿
  `fanout_exceeded`）。

### E4 子"宣布"了，但**没有消费者**

- **形态**：子的宣布已经落地（`_emit_settlement` 落一条挂在父名下的 `notice`，
  `agent_loop.py:2934`），而**没有任何一处读它来触发判定**；同时子那一行的终态是
  **父的 `summon` 调用栈**写的（`conductor.py:1807` → `_end_from_payload` → `finish`
  `:2233`），不是子写的。
- **与业主口径的差**：业主第 3 句的"**子代理宣布收工后**"今天只是一个事实，不是一个**事件**
  —— 没有"父被叫醒去重判"的那一步。
- **应当是什么**：宣布 = 事件（已有载体：父名下的 `notice` 项）；父在下一步/下一轮读到它时
  **先判消边再干别的**（顺序：入口最先、消边最后）。
- **落点与判据**：`agent_loop` 的步首（与"渲染即 seen"同处）+ `conductor.can_release`；

### E5 洗格式只出**建议**，不改载荷（与业主第 4 句的差）

- **形态**：派活路径上秘书已经在跑（`agent_loop.py:2079`，在 `_execute` **之前**），但它的
  产物并进的是**结果**（`{"秘书": …}`），真正发出去的是模型原样那一份

  `secretary.optimize_outbound` 返回 `payload: original`）。
  这条"不改载荷"是**有判据守着的**：`tests/test_secretary_noise.py:187`（"原键一个不许丢、
  值一个不许改"）与 `:306`（`…never_rewrites_the_payload`），出处 `draft/53` §2 两条红线。
- **与业主口径的差**：业主要"**委托秘书洗一遍格式**" —— 即秘书的产物要**回到这一次派活上**，
  而不是只摆在模型的下一步结果里。今天格式不对的派活不是被洗掉，而是被 **summon 的声明面
  拒掉**（实测：`A.run_once({"request_id": …})` ⇒ `done / refused / invalid_params`，
  detail「出现未声明的参数」）。
- **应当是什么**：秘书的职责从"只报不改"扩成"**格式面可以改写**，内容面一个字不改"，

  改成"格式键可规范化、内容键与值逐字不许动"。
- **落点与判据**：`secretary.optimize_outbound`（新增"洗"的产物 `after=`）+
  `agent_loop._do_summon` / `_do_summon_many` 用洗过的载荷；判据 = 正控（错名/缺键被洗成受控
  形状，且 `before`/`after` 两份都在台账里）+ 负控（内容面的值被改一个字 ⇒ 红）+
  反真空（洗不动 ⇒ 受控拒绝，不许静默补默认值 + 秘书跑过之后 `tasks` 行数不变）。
- **批次**：**S1g**。
- **注**：这一条有**岔口**（"建议" vs "改写载荷"），见 §4。

- **落点与判据**：`can_release` 读 `keep_alive`；判据 = 正控（待命的父不许消边）+

- **批次**：**S2'**（A6=丙 的落地，排在 S1f 之后）。

### E7 无子树停 ⇒ 停止不沿边传播（S4=4a / S1=1e 没有载体）

- **形态**：`stopctl.request_stop(root, reason, by, force, sid)` **没有 `root_task_id`**；
  停止是**工作区级开关文件**，各个循环在步边界自读（`agent_loop.py:2285-2310`）。
  另外 `conductor.tree(root_task_id=…)` 里的 `root_task_id` 只是**只读视图**参数。
- **与业主口径的差**：业主 T2「释放严格自叶向根」与 C 组 S1=1e（停止通知 = 板上的
  `kind=notice` 项，**ack 才算传达到**）在今天**没有载体**：停止既不下传、也不要求 ack。
- **落点与判据**：`stopctl` 加子树参数 + `conductor` 沿边下发 `notice`；判据见
  `draft/84` §2.2（父停 ⇒ 沿边下发 ⇒ 子 ack ⇒ 父消边，每步板状态可读；负控：抹掉子那一步
  的 ack ⇒ 消边判据必须拒绝）。
- **批次**：**S4**（原排期不变；本页只把它与 §1.3 的顺序口径对齐）。

### E8 边级幂等键 `(edge, attempt)` 不存在

- **形态**：今天只有 `finish` 的"终态先到先得"（`conductor.py:2156`）与**全工作区**粒度的
  `stopctl.consume_stop`。
- **与业主口径的差**：§1.3 要求"`(边, 尝试)` 只许删一次"。全工作区粒度的幂等挡不住
  "同一条子交差两次"。
- **落点与判据**：消边读数里带 `(边, 尝试)`；判据 = 重复宣布两次 ⇒ 盘上只有一条消边读数、
  且第二次如实写"已经消过"（不是静默）。
- **批次**：**S1h**。

### E9 三态：部分读数把"没读成"折成"空"

- **形态**：`board_readings()` 是三态的（`checked=False` + `reason`，`conductor.py:963`），
  而 `_children_of` / `_in_flight_children_of` 没有三态（读失败 = 抛或空表）。
- **与业主口径的差**：§1.4 要求"读到 / 确实为空 / 没读成"三者分开 —— 折平会让父把
  "没读成"当成"没有活跃子代理"从而**误消边**。
- **落点与判据**：`R(P)` 的读侧函数返回三元组或 `checked` 位；判据 = 反真空（台账读不成时
  `can_release` 必须拒绝，不许放行）。
- **批次**：**S1h**（与 E8 同一批）。

### E10 `dispose()` 会给**板项行**写 `status`，与板面的 `item_state` 打架

- **形态**：`dispose()` 把**所有**仍在 `pending`/`running` 的行写成 `cancelled`
  （`conductor.py:2353-2360`），板项行的 `status` 恰好是 `pending`。
