### 1.4 这些判据的共同形态：**把"没做到"折成"不许提交"**

- 一条还没形式化的证明 ⇒ `proof_text` 缺失/`evidence_kind` 不合格 ⇒ **拒绝入库**（E/B 侧）；
- 一条找不到逐字引文的联系 ⇒ **不许产出**（C/B 侧）；
- 一条"我读过、觉得成立"的判断 ⇒ 没有对应的**等级**可以挂 ⇒ 只能写成 `heuristic` 然后
  在门上被"承重结论缺 T3"打回（D/G 侧）；
- 一份改过一处的稿 ⇒ 旧签名失效 ⇒ 要么重审、要么不许交（H/M 侧）。

结果就是用户在 T1–T5 里看到的那三件事：**（一）"哪几条没查到"当交付；（二）数字实验
9/10 `inconclusive` 也算过关（因为"如实"）；三）手稿是三行骨架（因为正文没人管）**。
机制上是同一个：**系统只会惩罚"说了没证据的话"，不会奖励"把不确定的东西带等级地推上去"**。

## §2 新分工（用户口径落地）

### 2.1 三条根本原则

1. **提交永远被接受，等级由机器盖**（`epistemic grade`）。
   模型不必判断"这句话算不算证明" —— 它只说它相信什么、依据是什么；**框架**按依据机械盖级：
   `checked`（形式化检查器通过）/ `argued`（有可读的论证文本）/ `numerical`（有可复算的数值读数
   或界）/ `paraphrase`（转述/二手）/ `speculation`（无依据的猜测）。等级只影响**后续动作**
   （要不要派形式化、要不要派复核），不影响**能不能提交**。
2. **每一个"不许"改写成"标注 + 自动跟进"**。
   - 没有逐字引文 ⇒ 关系**仍然入库**，`quote_status=missing|paraphrase`，自动进"待核引文"队列
     （秘书派 A 取原文 / 派 B 复核），而不是把 C/B 挡回去；
   - 参数错 ⇒ 框架按 schema **自动补齐/纠正**（默认值、枚举近义、容器包壳），自动重试一次；
   - 稿子改了 ⇒ **自动**把"这一版未复核"派给 H（`verify_fixes`），而不是把 M 拦在门外；
   - 命令/落点错 ⇒ 自动修正一次（相对路径、目录不存在就建）。
3. **文书交给自动化；自动化不了的配秘书**。
   已经可以完全自动化的：验收表（由台账现算，M 不该手写 kind/min/na）、报告骨架与读数表、
   手稿账本（自动起草"谁交给了谁、依据哪几条"，模型只补结论段）、`notify`/留言、状态报告、
   收工门自检。秘书 = 一个**确定性子系统**（不是新的 LLM 角色）：`agentflow secretary …`
   + conductor 在每次派活/收工后自动补齐。**留在 LLM 提示词里的只剩：任务目标、领域方法、
   盘上事实、可用能力。**

### 2.2 每个角色的"只想学术"版本（提示词的目标形态）

| 角色 | 现在在想什么（被规则逼的） | 改后应该只想什么 |
|---|---|---|
| M | 34 条：验收 kind / na 理由 / 收工门 / 留痕 / 简报… | "这一趟要回答什么、谁最合适、下一步该往前推哪一格"（文书全部自动） |
| D | 证据包够不够、能不能下钻、置信度能不能升 | "这条命题我信到什么程度？下一步该怎么试它"（等级自动盖，采信不要求形式化） |
| E | 同一命题最多试 3 次、每次只改一处、REPRO_RESULT 格式… | "这个命题怎么写才更容易被检查器验过 / 数值上怎么设界才更有说服力" |
| C | 只读、不许写、引文要逐字… | "哪两个概念之间的缺失联系最值得研究、结构洞背后是哪条路线"（产物自动落盘，引文自动送核） |
| G | 断言必须带 disclaimer、citations 必须存在… | "怎么把这一轮的结果讲成一篇论文"（版式与合规自动补） |
| H | 只读、五元位、签名链… | "这篇稿子哪里说得比证据强、哪条引文撑不住"（其余自动） |

### 2.3 一条纪律的处置只有三种去向

对现存每一类纪律，必须落到三者之一（不许留在提示词里）：
**① 自动化**（框架自己保证，例如 schema 校验、自动补齐、自动派活、自动生成文书）；
**② 秘书**（确定性脚本产草稿，模型只改研究内容）；
**③ 读数**（写进状态报告/收工门，作为"给研究者看的事实"，不再是"拦人的门"）。
M 的 34 条 policy 按这个三分法逐条过一遍：预期删到 ≤ 8 条。

## §3 改造清单（按依赖排序；禁改区改动一律"先改后报备、不自签"）

**P1 等级机制（`epistemic grade`）—— 框架的地基**
- `schema`：为 `statements` / `documents.claims` / `relations` 增加/派生 `grade` 字段（机械计算，
  不由模型填）；`proof_text` / `disclaimer` / `citations` 由"必填"改成"缺失即降级 + 进待办"。
- `closing`：`load_bearing` 那一格从"proof 级没有 T3 ⇒ 红"改成"读数：本轮的论断按等级分布 +
  哪些 `argued` 还没被形式化（自动派 E）"；门不再因为等级不够拦人。
- 判据：一批"只有论证文本、没有形式化"的提交**必须成功入库**且被盖 `argued`。

**P2 待办队列（秘书的核心）**
- 框架维护 `pending/` 待办（待核引文、待形式化、待复核签名、待补检索），每条带"谁做、为什么、
  依据哪几行"；M 的状态报告自动带这份清单；`conductor` 在收工前自动把能派的派掉。
- 判据：C/B 提交一条 `quote_status=missing` 的关系 ⇒ 自动出现一条"派 A 取原文"的待办。

**P3 参数自动修复**
- `invalid_params` 从"拒绝"改成"自动纠正一次"（按 schema 补默认、纠正枚举近义、容器包壳、
  去掉多余键并留痕），仍失败才回给模型。
- 判据：把真机那 567 次形状摩擦重放一遍，自动可修的必须修掉（目标：形状摩擦 < 10%）。

**P4 文书自动化**
- 验收表：由 `closing` 从台账**生成**（八环读数现算），M 只写"这一趟想证明什么"；
- 报告：九节骨架 + 读数表自动生成，M/G 只写研究叙述；
- 手稿账本：`secretary` 自动起草（派活/收工各一行，带 `refs`），模型只补结论段。

**P5 提示词重写**
- M：34 条 → ≤ 8 条（研究指挥 + 目标 + 方法），纪律条目删除并在每处注明"由框架自动保证"；
- E/D/G/C/B/A/H 同法；`stance` 与领域方法**加强**（怎么攻命题、怎么找反例、怎么读关系图）。
- 判据：M 的 policy 字符数 < 4 000；且重跑同一任务时"被拒/失败"总数下降 ≥ 50%。

**P6 研究产出读数（`draft/39` §6.49 的 D66）**
- "算"那一环从"跑过实验"改成"**跑出结论**"（`supports|refutes` + 界/证书）；
- "造"那一环要**我方派生命题**（`origin=own_result` + `grade` 达 `argued` 以上）。

## §4 验收（怎么证明不是嘴上说说）

同一任务（T2 从零研究 / T5 费马）用改造后的系统重跑，读四个数：
1. **摩擦率**：被拒/失败里"形状"占比 < 10%（当前 65%）；
2. **提示词纪律量**：M 的 policy < 4 000 字符（当前 14 921），且 0 条"不许提交"型；
3. **知识提交被拒数 = 0**：所有"我信但没形式化"的提交都入库并带等级；
4. **研究产出**：有结论的实验 ≥ 1、我方派生命题 ≥ 1、论文/手稿里引到 `rel:`（C 的产物）≥ 1。
