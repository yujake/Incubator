## T2（唯一真待裁）事件级回放要不要保留

**盘上事实**（W5 收工时给出，我复核过）：
- 旧壳 `/run/{sid}` 里那张"逐条事件卡片"（每条 `agent_step` / `llm_call` 的 payload / result 明细、
  `第 N 步`、shape）**今天没有任何端点给得出** —— `RunView` 只给 `runs[]` 的聚合（`steps`/`llm_calls`/
  `last_shape`/`stop_reason`/`usd` 等）+ `report` + `checkpoint`；`GET /api/stream` 只推**新**事件、不补历史。
- W5 把那条判据 `test_run_detail_replays_events_and_report` 从"旧壳页里能找到四个 kind + `第 0 步` + `fs.write`"
  **迁移**成"`/api/run/r1` 的 `task` / `last_shape` / `steps` / `llm_calls` / `stop_reason` / `report` 原文可读"
  + `/run/nope` 的 `tri=unreadable` 与理由行，**并给了负控**；它明确写"**逐条回放这件事我守不住、没有自己放行**"。
- 我认同这个判断：把"逐条事件能被读到"这半迁走是**能力缩水**（不是判据放宽），所以我没有代为放行。

| 选项 | 做法 | 代价 | 回退 |
|---|---|---|---|
| **T2-a** | **加一条只读端点** `GET /api/run/{sid}/events`（或 `?events=1` 加在现有端点上），返回该趟的事件行（分页/上限由参数给），并在 `draft/75 §1.1` 的 C1 表加一行、`ui/src/api.ts` 加一条、`Run.tsx` 加一块时间线 | **动 C1 契约面**（敲定过的表要加一行）：加完要重跑契约 A 条（前端字面量集合 == 后端 `ROUTES`）与判据 C（`types.ts` 键 == 真读数），并补一条"分页/上限"的判据与负控 | 删那一行 + 删前端消费 |
| **T2-b** | **不加端点，接受缩水**：Run 页只给聚合读数 + 报告原文（现状），把"逐条回放"记成 `draft/81 §13` 的未做项 | 真机排障时看"第几步发生了什么"要退回 CLI（`agentflow status` / 直接读 `sessions/*.jsonl`）；页面上没有"逐条"这一层 | 想加时按 T2-a 做 |
| **T2-c** | 让 `RunView` **带上** `events[]`（不加端点、改 C3 类型） | 也要动契约（C3 表 + 生成物 + 判据 C 的双向比对）；而且把"可能很大的一张表"塞进每次页面刷新都要拉的 JSON 里 | 从 `RunView` 里去掉那一栏 |

**我的建议：T2-a**。理由：① 它是三条里唯一"不改变既有端点的语义、只增加一条只读面"的做法，
与 `draft/78 §3` 的"子表 + `type_decls()`"接缝完全同形（B 线加只读面已经有成熟套路，代价最小）；
② 逐条回放是排障与复核最需要的那一层（`draft/74` 的 Run 页设计里本来就有"一趟回放"）；
③ T2-c 会让每次刷新都拖一张大表，T2-b 则把"页面上能不能复核"降成"退回命令行"。

**不裁会怎样**：不致命 —— 现状是**诚实的缩水**（判据已迁移、页面显聚合读数、未做项在 `draft/81 §13` 里点着名）。
但"用户端能不能逐条复核一趟"这件事会从设计里消失，而它本来是 `draft/74` 的 Run 页功能之一。
