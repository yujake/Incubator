**⚠️ 判"活/死"的三层判据（所有者 2026-10-07 两问逼出来的，**必须三层都过才算"活"**）**：

2. **L2 调用链必须递归到"真入口"**，且 **`selftest` / 测试 / 探针一律不算入口**。

### §8.5 **留痕格式**（**所有者 2026-10-07 追加，本批的主要产出**）：废案教训清单

**所有者原话**："每个废案的删除需要留痕：1. 这个废案原先是想做什么，怎么做的；2. 这个废案为什么被淘汰了。这是个**教训清单**，免得之后重新踩坑。"

⇒ **清仓账 `draft/65` 的主体不是"删了什么"，而是"每个废案的两段留痕"**。删除是副产品。

**每条废案必须写满这四块（缺一块就不许删）**：

| 块 | 字段 | 写法（**可判**，不写形容词） |
|---|---|---|
| **① 原先想做什么** | 要治的问题 | 当时**观测到的现象/缺口**是什么（有读数给读数；没有就写"来源没记录"）——不许写成"为了更优雅"这类动机 |
| | 意图一句话 | "它想让 X 变成 Y" —— 用**当时的话**，逐字引 |
| **② 怎么做的** | 机制 | 入口在哪（动作/工具/菜单/文档段）、数据面动了什么（表/字段/文件）、**提示词或文档教了人怎么做**；**逐字原句 + `文件:行`** |
| | 有没有成功过 | 有没有**判据或真机读数**证明它真的 work 过；没有 ⇒ 写"**没查成**"（这本身就是一条教训：**一个没被任何读数证明过 work 的机制，是怎么活到今天的**） |
| **③ 为什么被淘汰** | 直接原因 | 哪一次**实测/裁定**否掉的 + 逐字出处 |
| | **坑的形态** | 如果淘汰原因本身是个设计坑：**错在哪一步 · 当时为什么看不出来 · 什么读数能提前发现它** —— 这三句是这一块的价值所在 |
| | 教训一句话 | 写成"**下次遇到 X 就别做 Y，改成 Z**"的可判形态（可判 = 下次能被一条判据或一条读数挡住） |
| **④ 账** | 出处逐字 · 删除面 · 删了会红什么 · **反回流判据** | 同 §8.3-2/6 |

**两条纪律（这条最重要）**：
1. **来源没写的，写"来源没记录"** —— **绝不许编一个听起来合理的淘汰理由**。教训清单的全部价值在于"这条是**真的**踩过的"；编一条比不写更坏（它会让人以为查过了）。
2. **凡是"③ 为什么被淘汰"查不到出处的**，该条**不许删** ⇒ 落 **C 类**（列出来报所有者）。这条与"删除要留痕"是同一件事的两面：**说不清为什么废的，就没资格删**。
