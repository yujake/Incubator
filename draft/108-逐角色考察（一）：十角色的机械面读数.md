# 逐角色考察（一）：十角色的机械面读数

> 依据业主 2026-10-11 口径（逐字）：「**F 每个角色在做提示词迁移时需先考察系统真实情况，
> 避免提示词工具继续遥遥落后于系统实现**」。模板见 `draft/103` §3.5 的十项。
>
> **为什么先只做机械面（1~5、8、9 项）**：这七项全部**现算**（注册表 / 能力表 / 官能表 /
> 装配结果），可以一次量完、逐格复核；而第 6 项（代码里为它做的机制）、第 7 项（真机失败形态）、
> 第 10 项（共享块与专属块边界）**必须一个角色一个角色地读代码与读真机读数** ——
> 按业主的口径，那三项是在**迁移该角色那一批**里做的，本文件先给 A 一份填好的示范。
>
> 复跑：`python -B temp/_probe_recon.py`（口径 = 探针里的参数，逐字写在那个文件里；
> 本文件的正文由它现算产出）。上游：`draft/103`（三轴方案）、`draft/105`（提示词↔代码对照）。

### CS-14（仍开·语义）"空写集"的两个不同原因被折成同一个值

- **现象**：`capabilities.write_set_of()` 对 `M` 与 `V` 都返回 **16 张表（全部）**，
  与它对"完全不认识的执行单元"（`write_set_of("Z")`）返回的东西一模一样。
- **代码事实**：`capabilities.py:1580-1594` 逐字：
  ```
  ws = WRITE_SETS.get(role)
  if ws is None:  return _ALL_TABLES          # 未知 ⇒ 保守
  if not ws:      return _ALL_TABLES          # 没有写集的角色（M）… 与任何角色串行
  return ws
  ```
  第二支的理由写的是 **M**："它的召唤本身会写 `tasks`，而且它派生的子任务可能写任何东西"。
  而 `WRITE_SETS` 里**空集有两个**（本批现算）：`WRITE_SETS["M"] = []` 与
  `WRITE_SETS["V"] = []` —— V 的空写集理由是另一个：**"它的台账是一个文件，不是表"**
  （`specs/v.py:21-26`）。V 没有子代理、也不写 `tasks`。
- **现场读数**：`C.WRITE_SETS["V"] = []` → `C.write_set_of("V")` = **16 张表**；
  `C.WRITE_SETS["M"] = []` → 16 张表；`C.write_set_of("Z")` = 16 张表（本批现算）。
- **影响面**：**潜伏**（V 从未运行 ⇒ 没有任何一次调度真的被它影响）。一旦 V 跑起来，
  写集轴的判据（`write_sets_intersect` / `policy.waves_of` / `scheduler` 的 `write_set` 读数）
  会把 V 当成"能写全部 16 张表"的角色。
- **两条修法（不替业主裁）**：① 在 `write_set_of` 里把 V 这一档分开（返回空集并写清理由：
  它写的是文件、没有子代理 ⇒ 与别人的表写集不冲突），代价是函数里多一个角色名；
  ② 给"文件台账"建一根独立轴（今天写集轴只管表），代价是新机制。
  **注意**：无论选哪条，"空集"这两个字的两种含义都必须在代码里写清 —— 这正是三态纪律
  在写集轴上的形态（"没有这张表"与"不写任何表"不是一件事）。
