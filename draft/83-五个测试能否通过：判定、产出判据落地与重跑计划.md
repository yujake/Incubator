- **盘上交付物**：T1 修订稿与说明、T2 研究手稿、T3 论文包、T4 清单、T5 进展手稿；

**两条所有者 2026-10-08 的口径修正（本节的判法按它们改）**：

1. **T10「10 和 11 甭管，不要机器验证，跑完你亲自读产出」** ⇒ **产出质量不加机器判据**：
   机器只保证**硬事实**（台账行、边、命中/取回的分类、成本、判据红绿），
   **质量由人逐字读交付物来判**。上一轮我提的"缺陷→判据时效""质量指标/误报率"两条**撤回**，
   本节不再出现任何"用机器给产出打分"的口径。
2. **T9「LLM 的结果啥时候能复现了？飘是正常的，那些硬的结果（比如搜没搜到）智能体们在交流中会留痕」**
   ⇒ 撤掉"可复现"这个目标：设计里只写"**从台账可离线复算**"，不写 reproducibility；
   而**硬事实必须进交流**（搜到没搜到、取回没取回、下载成没成、实验跑没跑），
   不能只躺在表里 —— 这正是 `draft/85` §4 那张受控词表与 §5 那三条硬约束的来源。
   **推论**：每一趟的"通过"里，凡是**模型说它做了什么**的话，都要能在交流/台账里找到那条硬事实；
   找不到 ⇒ 按"没做"处理（而不是按"它说做了"处理）。

**五条所有者 2026-10-09 的裁定（这一节第一句"收工门 can_close=true 且八格全 pass"按它们改）**：

3. 逐字：「是否收工不要用机械判据，由 M 制定的目标是否达成为准，M」
   ⇒ **收工的判据归 M**：`can_close` = M 自己交的那份判据（`goal` / `goal_met` / `basis` /
   它自列的 `task_list`）里的 `met`。机械那八格**一格不减**，但从"门"退成**读数**
   （`readings` + `machine_pass`）。
4. 逐字：「所有智能体是否能停都是看自己被派的活有没有做完，M 也不例外，只是 M 需要根据用户
   指令给自己设计任务列表」
   ⇒ 判据不是"别人说你能停"，是"**你被派的活做完了没有**"；M 的活来自用户指令，
   所以 M 必须自己把用户指令翻成一张 `task_list`（每项 `done` / `not_done` / `cannot`），
   再拿它判"达成没有"。**没有人交判据 ⇒ 不是"通过"，是"没人判过"**（退出码 2）。
5. 逐字：「如果某代理认为某件任务自己无法胜任且无法通过派子代理解决，则会将情况上报父智能体。
   特别地，M 向用户上报」
   ⇒ 上报是**判据的一部分**：`task_list` 里没做完/干不了的项**有没有被说出来**（M 问用户、
   子代理发报文或写交差手稿）进 `escalation_gaps`。找不到 ⇒ 逐项点名（读数，不阻断 ——
   判据仍归 M，但"闷着不说"看得见）。
6. 逐字：「上述层层上报困难也会带来一种停机状态，即所有活跃子代理的状态都是 blocked
   （或者按你的风格写）」
   ⇒ 第五种停机态：`subtree_blocked(parent).all_blocked` —— **在飞的直接子每一个都 blocked**。
   没有在飞的子 ⇒ `all_blocked=false` 并说清（"没有活跃子"既不等于"整支卡住"也不等于"都做完了"）。
7. 逐字：「如果被委托的任务单纯是在职责之外，则应该将自己能力内的做完后上报情况就 over 了；
   如果是需要请示上级指导任务实施细则，才会 block」
   ⇒ **两档分开**，这是"blocked"的窄定义：
   - **职责之外** ⇒ 做完能力内的（`cannot` 项如实进 `task_list`）+ 上报 + **正常收工**（不写
     `blocked`）；
   - **要请示实施细则** ⇒ 才 block，且必须同时给 `what` / `why` / **`needs`**（要请示什么）——
     说不出 `needs` ⇒ **不落痕**，只记读数（那多半就是上一档）。
   `blocked` 的落点是**父那一行 `inputs`** 上的痕 `blocked:<子>@<时间>|<为什么>`（与
   `edge-released:` / `stop-notified:` / `stop-acked:` 同族，`schema.py` 零变更）。

   > 若要使用则必须在论文正文里从零搭建，使内容自包含，不以引文格式落实」

### §5.3 禁改区改动授权 + 拦截理由要写清 + C 的"最短证明依赖链"（业主 2026-10-09 新裁）

> 论文正文里重建。这时可能需要智能体C的衍生能力，即寻找一个成果在手稿和引文中的

- **收尾动作**：跑 `python scripts/noai_gate.py --git --since <ref>`，把 **requires_human(1)**

#### (2) 拦截理由必须把"出路"写在信里（业主第二句的前半）

论文正文引手稿被拦时，拒信要**逐字**给出那句口径：**手稿里的成果若要用，只可在论文正文里
重建**（此刻写的是"必须重建"，要补成这一句），并给出"重建之后怎么引"
（`stmt:` / `exp:` / `rel:` 落台账的行，`lit:` 只指真实论文）。

  （否则模型会以为手稿之间也不能引）。

#### (3) C 的衍生能力：一条成果的"最短证明依赖链"（业主第二句的后半）

**要解决的问题**：论文里重建一条来自手稿的成果，最费步数的是"这条结论到底靠哪些前提、
哪几个实验/命题/文献撑着，最省的那条链是哪一条"。这件事今天是**人读手稿**在做，
模型只能把整份手稿重读一遍（真机 T2 `t2a` 就是：M 把 `rel:` 写进报告而不是台账，
因为"该重建哪一条、靠什么"没有一处可读的读数）。

**机器形态（待施工，符号级）**：

```python
# C 的新动作（`specs/c.py` 的 ACTIONS + capabilities 的派生表，一处声明、四处派生）
def C.proof_chain(target: str, *, max_depth: int = 4, k: int = 1) -> dict:
    """给一条成果（`stmt:` / `exp:` / `conj:` / 手稿里的 `doc:<稿件>#<断言>`），
    算出它到**可重建的最小前提集**的最短依赖链。

    读（只读，零模型调用）：`statements`（own_result 的命题）、`experiments`
    （proof / numeric 行）、`dependencies`（FC-23：theorem/experiment/prior_art…）、
    `relations`（B 整理出的关系边）、`literature`（`lit:` 只作为**叶子**：
    真实论文不进重建链，它是"外部来源"）。
    返回：{"checked", "target", "chains": [{"hops": [...], "leaves": [...],
    "length", "why"}], "truncated": bool, "reason"}
    """
```

三条口径（写在这里，免得施工时走样）：

1. **边从哪来**：`dependencies`（有向：谁依赖谁）+ `relations`（无向：同族/对立）——
   最短链只在**有向依赖边**上找；`relations` 只用来在并列候选里挑"同一条线上的"。
2. **叶子是谁**：`lit:`（真实论文，论文里可以照引）与 `exp:`（我们跑过的实验，论文里
   可以引台账行）是叶子；**手稿本身（`doc:`）不是叶子**（业主：正文里不许引手稿）
   ⇒ 链算到叶子为止，正文照链重建，每一步都能落到一个可引的台账行上。
3. **三态**：目标不在盘上 / 依赖表读不成 ⇒ `checked=False`（不是"没有依赖"）；
   链长超过 `max_depth` ⇒ 截断 + `truncated=True`（读数，不假装"就是这条"）。

**判据（红 / 绿成对）**：正控——造一条 `stmt:0002 → exp:0003 → lit:0005` 的两跳链，
`k=1` 给最短那条；负控——环（A→B→A）不许死循环且要报 `cycle`；反真空——依赖表读不成
⇒ `checked=False`；口径——链上的每一步都要是**可引的台账行**（`doc:` 不许出现在链里）。

**与已有的东西的关系**：`closing.research_chain_gaps` 判"四环节有没有行"；
这一条判"**一条成果能不能被重建**"（链在不在、几步）。两者不互相代替。
施工批次：**S1o**（C 的衍生能力），排在 T3 之前——T3 的任务正是"把成果整理成论文"。

#### (3b) 前置条件：D 的手稿过审 ⇒ B 逐条消化 ⇒ C 才找得到链（业主 2026-10-09 追加）

业主逐字：

> 「且观查 B 侧的"证明消化"和 D 的手稿过审后是否被 B 消化或研究成果逐条入库。
> 前置条件具备了，C 才能在里面找依赖链」

⇒ 这条链有**四个环节**，C 的 `proof_chain` 只在最后一环上工作。前三环缺一环，
链就是空的 —— 而**今天没有任何读数说"缺了哪一环"**（T2 `t2a` 的现场正是
`statements=0`、手稿 `refs` 空、`analysis_reports=0`，而收工门只报得出"报告缺附件"）。

| 环 | 谁做 | 落成什么 | 今天的状态（**只读核实，`draft/91` 的口径**） |
|---|---|---|---|
| ① 手稿成稿 | G（`build_document` / `revise`） | 一行 `documents`（`claims` 带 `citations`） | 通（真机有行） |
| ② 手稿过审 | H（`review` / `verify_fixes`）+ 签名 | `status` ∈ accepted/revised + `DOC-SIGNATURES.jsonl` 一行 | 通（`reviewed_current_rows` 那一档就是它的读数） |

1. **`C.proof_chain` 必须带"前置条件读数"**（三态，逐环报，**缺环时明确说缺哪一环**，
   不是返回空链）：

   ```python
   {"checked": bool, "target": str,
    "preconditions": {"document_reviewed": "yes|no|unknown",
                      "results_registered": "yes|no|unknown",
                      "dependency_edges": "yes|no|unknown"},
    "chains": [...], "truncated": bool, "reason": str}
   ```

   - `results_registered="no"` ⇒ 一句话给出**出路**："这份手稿过了审，但它的成果没有

   这一档问"审过**之后**有没有人接着把它变成可引的台账行"。T2 `t2a` 的现场正是
   "① ② 都有、③ 没有" ⇒ 这一档当场报 0，而不是等 C 返回一条空链。

#### (3c) 正文怎么重建：去 B 维护的定理库里复制粘贴 + 序号重写（业主 2026-10-09 追加）

业主逐字：

> 「G写正文时应该去B维护的定理库里找定理证明然后做复制粘贴和序号重写（比如某手稿里

⇒ 这一句把"重建"从一句口号落成**一个可核的动作**：重建 = 从**定理库**取原文 +
搬进正文 + 换成本论文的编号 + 标出处。逐条定死：

| 问题 | 答案 |
|---|---|
| **定理库是什么** | `statements` 表（**B 维护**：`B.register_statement` 是它唯一的写入口）——`origin=own_result` 的行就是"我们自己的定理"，`statement_full` 是要搬的正文、`proof_text` 是要搬的证明，出处是 `doc_id`/`line_range`（B 侧"第四条必填"的 own_result 档，逐字支持） |

| **怎么搬** | **逐字复制粘贴**（`statement_full` + `proof_text`）进 `out/paper/main.tex` —— 搬的是**定理库里的原文**，不是手稿里的叙述（业主"手稿内容不可直接引用"⇒ 手稿只是来源，正文的物料是库里那一行） |

| **映射落在哪** | **不改 `schema.py`**（硬约束）⇒ 两条候选：**(甲)** 写进 `dependencies` 表（`kind="theorem"`、`label` = 论文号如 `1.5`、`used_by` = 论文里那一处断言/文档号）—— 好处是 C 的链能走它、`verify` 既有判据能核它；**(乙)** 落一份 `out/paper/THEOREM-MAP.json`（`[{"stmt":"0007","paper_label":"1.5","section":"…"}]`）+ 正文里 `stmt:` 引用。**建议甲**（不新增落点、可被既有不动点审计到），乙作为甲不适用时的退路 |
| **谁核** | H（审校：编号与引用一致、证明与正文同一条、出处标注在）；收工门加一档读数（见下） |
| **M 排期** | 这条链要作为**一条任务链**写进 `task_list`：①手稿成稿 → ②H 过审 → ③B 逐条消化（成果进定理库）→ ④C 找最短链 → ⑤G 复制粘贴 + 序号重写（落映射）→ ⑥H 核编号与引用一致 |

**判据（记作 S1q，排在 S1o/S1p 之后）**：

| 档 | 判据 | 说明了什么 |
|---|---|---|
| 正控 | 库里一条 `own_result` 定理被搬进正文 ⇒ 正文里找得到 `statement_full` 的逐字片段 + 那条 `stmt:` 引用 + 一条"台账号 → 论文号"映射 | "复制粘贴 + 标出处"真的发生了 |

| 负控③ | 论文里出现 `doc:` 直接引手稿 ⇒ 红（两阶段口径：`paper_cites_manuscript`） |
| 反真空 | `statements` 里没有这条成果（③没做）⇒ 报的必须是"先去 B 登记"（S1p 那一档），不是"没有这条定理" |

**与 (3b) 的关系**：`C.proof_chain` 给"哪几条、几步"，(3c) 给"怎么搬、怎么编号"——
两处合起来才是业主说的那句"这样重建会变轻松"。

> 依赖（某文献或某无前提依赖的自证定理）为止」

⇒ 这句话把问题的重心从"找链的算法"挪到**"边是谁写的"**：**链算不出来，九成是记录时
没写依赖**（T2 `t2a` 的 `statements=0`、`dependencies` 里没有定理级的边，正是这一档）。
分两半写：**记录侧**（边从哪来）与**搜索侧**（怎么找最短）。

##### 记录侧：定理/证明入库时**同笔**写依赖，两处字段各管一件事（都不动 `schema.py`）

| 字段（**都已存在**） | 管什么 | 口径 |
|---|---|---|
| `statements.derived_from` | **来路**："这条成果是从什么派生的"（我方派生那一档的老字段；S2 的判据就是"`origin=own_result` 且 `derived_from`/`source_lit_id` 至少一个非空"） | 一条指向上游的号（`stmt:` / `doc:<稿件>#<断言>`） |
| `dependencies` 行 | **前提**："这条定理**用到**了哪些东西"（逐条边；`kind` ∈ `DEP_KINDS`（theorem/definition/lemma/proposition/dataset/experiment/prior_art）、`label`、`source_lit_id`/`source_experiment_id`/`source_doc_id`/`source_claim_id` 指向被依赖的那一行、`status` ∈ `{closed, dangling, external_unavailable, refuted, disputed}`） | **一条前提一行**；`closed` = 真的找到了，`dangling` = 悬空（**可见**，不当作到了根），`external_unavailable` = 拿不到（"引了但拿不到"是合法终局） |

**"写清"的机器形态**：`B.register_statement` 在 `origin=own_result` 那一档**再加一格
`deps`**（可选数组，每条 `{kind, ref, why}`）—— 给了就按上面那张表逐条落 `dependencies`；
**没给 ⇒ 这一行落 `unknown`**（"依赖没写"），**绝不落成"无前提"**（三态不许折平：
`unknown ≠ closed`）。M 排期时这一步就是 (3c) 链里的 ③。

**一处要核实（如实列，别当已核）**：`dependencies.used_by` 今天登记的口径是**使用点**
（`"doc:0001#claim-3"` / `"relation:0007"` / `"experiment:0002"`）——**它接不接受
`stmt:0007` 这种"被用的是一条命题"的形态，我在本页写设计时没有逐字核到**。
两条退路（施工 S1o 时先核一次，再选）：**(甲)** `used_by="stmt:0007"` 若被接受 ⇒ 直接用；
**(乙)** 不接受 ⇒ 把边挂在 `derived_from` 上（`"stmt:0007 <- stmt:0003"` 这类字符串解析），
或扩 `used_by` 的词表 —— **后者动 `schema.py`，要人裁**（本页不擅自选）。

##### 搜索侧：C 怎么找最短链（记录侧写全之后才有意义）

```python
def C.proof_chain(target, *, max_depth=4, k=1, weights=None) -> dict:
    """从 target 出发，沿**有向依赖边**（`used_by` → 被依赖项）走到根，取最短的 k 条。

    图：节点 = `stmt:` / `exp:` / `lit:` / `conj:`；边 = `dependencies` 行（有向）。
    根（走到它就算完）只有两种：
      ① `lit:` 行 —— 真实论文（论文里可以照引，不需要重建）；
      ② **无前提自证定理** —— 该 `stmt:` **一条 `dependencies` 行都没有**，且
         `evidence_kind="proof"` 且检查器 verified（无 sorry、无公理）。
      ⚠️ 「没有任何边」**只在 ② 的条件同时成立时**才算根；只有"没有边"而没有
      proof 证据 ⇒ 那是**依赖没写**（`unknown`），不是根。
    最短：缺省按**跳数**（BFS，等权）；`weights` 给了就按代价（例：`lit:` 0、
      `definition` 1、`stmt` 1、`experiment` 3 —— 实验要重跑最贵），用 Dijkstra。
    返回：{"checked","target","preconditions","chains":[{"hops","leaves","length","why"}],
           "truncated","reason"}
    """
```

**四条边界（写在这里，免得实现时走样）**：

1. **环**：`stmt:A → stmt:B → stmt:A` ⇒ 报 `cycle` 并**跳过那一条**（不许死循环、也不许
   把环上的节点当根）；整张图全是环 ⇒ `checked=False` + 说清。
2. **悬空边**：`dependencies.status="dangling"` ⇒ 那条路**不算到根**，记 `dangling` 读数；
   `external_unavailable` 可以算到根（业主的口径：引了但拿不到是合法终局）但要在
   `why` 里点名。
3. **`doc:` 不入链**：手稿不是前提（两阶段口径）⇒ 边上出现 `doc:` 时按"手稿"处理：
   要么改指它登记的那条 `stmt:`（③ 做完之后应当如此），要么报 `doc_in_chain` 读数。
4. **截断**：超过 `max_depth` ⇒ `truncated=True`（读数，不假装"就是这条"）。

**判据（S1o）**：正控①三跳链（目标 → 中间定理 → 文献根，`k=1` 给最短那条）；
正控②**无前提自证定理**作根（`dependencies` 空 + proof verified ⇒ 链长 1）；
负控①环（报 `cycle`、不死循环）；负控②**"没有边但没有 proof 证据"不许当根**
（报 `unknown` / 依赖没写）；负控③悬空边不算到根；反真空依赖表读不成 ⇒ `checked=False`。

##### 定义也是依赖项、也入库 ⇒ C 的图统一（业主 2026-10-09 追加）

业主逐字：

> 「注意：新概念的定义也是依赖项，是特殊形式的"定理"，也入库。这样C的职责面就统一了」

⇒ 三件事，都有**现场依据**（不是推想）：

1. **定义就是一条 `statements` 行**，`kind` 写"定义"。依据：`Statement.kind` **刻意不是受控词表**
   （`schema.py` 的注释逐字：「`kind`（theorem / lemma / …）：刻意不是受控词表。理由：它不参与
   任何判据分支（分支只看 `origin` / `status` / `evidence_kind` / `bits`）」）
   ⇒ **不用动 `schema.py`、不用加词表**；而稿件那一侧的 `CLAIM_KINDS` 本来就含"定义"
   （现算：`('定义','定理','命题','引理','推论','例','注','反例')`）⇒ 两边说的是同一件事。
2. **"用到某个定义"是一条依赖边**：`DEP_KINDS` 逐字含 `"definition"`（现算：
   `(theorem, definition, lemma, proposition, dataset, experiment, prior_art)`）
   ⇒ C 的图上，"定理 → 定义"与"定理 → 定理"是同一类边，只是 `kind` 不同。
3. **所以根的第三种**：**无前提定义**（一条 `kind="定义"` 且没有任何 `dependencies` 行的
   `statements` 行 —— 原始定义没有前提，它就是重建链的合法终点）。
   于是"没有边"这句话要**按 kind 分档**读：

   | 节点 | 没有依赖边时算什么 |
   |---|---|
   | `kind="定义"` | **根**（原始定义，无需前提） |
   | 其余 kind 且 `evidence_kind="proof"` 且检查器 verified | **根**（无前提自证定理） |
   | 其余 kind 而没有 proof 证据 | **依赖没写**（`unknown`）—— 不是根 |

**C 的职责面因此统一成一张图**：节点 = `statements`（定理 / 定义 / 引理 / 命题 …）+ `experiments`
+ `literature`；边 = `dependencies`（`kind` 说这是哪一类前提）。C 已有的动作
（`hottest` / `gaps` / `contradictions` / `paths` …）分析的是**关系图**（`concepts`/`relations`），
新动作 `proof_chain` 分析的是**依赖图** —— 两张图在**定义节点**上接起来：
一个概念 ↔ 它的定义那一条 `statements` 行。

**一处如实登记的缺口（待核/待定）**：`concepts` 行与"它的定义那一条 `statements` 行"之间
**今天没有字段把两者钉在一起**（`Concept` 的字段是 `concept_id`/`name`/`definition`/
`related_concepts` 那一族，`Statement` 的字段里没有 `concept_id`）⇒ 两张图今天只能靠
**名字**对上。要么接受"靠名字对"（并在读数里如实写"按名字匹配"），要么加一列 ——
**后者动 `schema.py`，要人裁**。本页建议：先用"S1o 的链 + 名字匹配"跑起来，
把这条缺口作为待裁题交上去（它不影响链的算法，只影响"这条链上的定义对应哪个概念"）。

### D85 —— 空口 ack：模型可以 ack 而根本没读

- **形态**：T16 把"确认读过（ack）"定为每条留言的最小行为，而 ack 是**收件人自己报的** ——
  它完全可以嘴上说读过。本仓对"自述不是事实"有成文先例（`_record_interjection_effect`
  逐字：「"我听了"这句话不算数，那一步调了什么才算」），板时代这条纪律必须同族。
- **判据**：ack 必须与"**那一步的提示词里确实渲染过这一项**"配对；配不上 ⇒ 落
  `ack_unbacked` 读数，并在 `conductor.board` 里可见。**不拒绝**（拒绝会把"我早就知道"挡掉）。
- **归属**：S1（与板同批落地，不许留到"以后再说"）。

### D86 —— 板项与 `tasks` 行没有共同键

- **形态**：`item_id`（板）与 `task_id`（实例）今天毫无关系；`tasks.input_key` 是幂等键、
  板项只有描述性的 `edge`。于是"**这条 delegation 项对应哪个实例**"读不出来 ——
  而消边谓词（T2）、"谁领的"、"做完没做完"全要这个锚点。
- **判据**：每个 delegation 项都能在 `tasks` 里找到 `input_key == f"item:{id}"` 的那一行；
  负控：改掉那一行的 `input_key` ⇒ 红。
- **归属**：S1。

### D87 —— 两本账两把锁（`manuscripts/` 目录下）

- **形态**：`manuscripts.write` 用的是 `manuscripts/.lock`；板账本若自带 `.board.lock`，
  那么"交差 = 写 handoffs + 关板项"要**按顺序拿两把锁**。两处若顺序相反就死锁，
  而 `store.LOCK_ORDER` 那套**管不到台账文件锁**（它是表锁的口径）。
- **修法**：**账本目录一把锁** —— 两本账共用 `LOCK_NAME`（一次只 append 一行，
  粒度变粗的代价可接受），并在 `manuscripts` 模块注释里写死这条口径。
- **归属**：S1。**这条要修得快**：它是唯一一条"新机制会引入死锁"的风险。

### D88 —— 共存期没有"不许两处渲染"的判据

- **形态**：板是新增的，而既有工作区有 **579 条** `agent_message` ⇒ 必须共存一段时间。
