## §1 目标形态（按五条裁定展开）

### 1.1 前端工程（裁定 `1C`）

- **技术栈**：`Vite` 构建 + `TypeScript`；框架见 **§3 题 A**。工程落在 `agentflow/webui/`（源码）与 `agentflow/src/agentflow/web/dist/`（构建产物，见题 B）。
- **样式单一来源**：现在的 `THEME_CSS`（DSH 令牌）**不重写**，改成构建期被前端入口 `import` 进来 —— 保住"令牌只有一份"这条既有资产（判据 `test_app_css_uses_only_tokens` 升级成"构建产物里的颜色/间距都必须来自令牌变量"）。
- **路由**：服务端保留 4 个 API 前缀，其余路径一律吐 `index.html`（前端路由：`/` 待答 · `/run/:sid` 运行态 · `/project/:name` 项目总览 · `/evidence` 证据链 · `/artifacts` 产物 · `/settings` 本机设置）。
- **迁移策略**：**并行期**——旧的 HTML 渲染函数保留，直到 W1/W2 全部迁完；每条面迁完就删对应的旧函数（不留两套）。
- **R009 同族纪律**：前端代码里**不许**出现硬编码的本机路径（本批刚把源码里 11 处例子改成相对写法）；新增判据扫 `webui/**` 里的"盘符绝对路径 / `temp/<环境目录>`"这类形态（判据正则与逐条说明见 `tests/test_settings.py` 的残留登记表）。

### 1.2 SSE 实时面（裁定 `2B`）

- `GET /api/stream?sid=<会话>` ⇒ `text/event-stream`：事件 = `state`（这一趟的状态与读数增量）· `question`（新的待回答）· `answered` · `stop`（停机开关状态）· `cost`（花销增量）· `heartbeat`（保活）。
- **断点续传**：支持 `Last-Event-ID`（服务端按事件序号补发最近 N 条）。
- **降级**：`/api/state` 轮询保留（浏览器不支持 EventSource / 流被中间层截断时用）。
- **边界**：只读投影（**不**通过流回写任何东西）；同时最多 N 个订阅者（超了回 503，别把线程池吃光）；进程收尾时主动关流。
- **判据**：content-type 与分帧、首个事件有界时间、心跳周期、`Last-Event-ID` 续传、**盘上新增一条事件 ⇒ 流里出现**（端到端，用 `tmp_path` 造工作区）。

### 1.3 写面（裁定 `3C`，**最重的一条**）

现在写路径**只有** `POST /answer` → `userio.answer_question`。裁定要加的三件（都要**走既有闸门**，不另开一条路）：

| 端点 | 干什么 | 走哪条既有实现 | 三态怎么报 |
|---|---|---|---|
| `POST /api/stop` | 落停机开关（优雅停）/ 强制停（连子孙进程） | `stopctl`（停机的唯一实现） | 落没落开关、进程有没有收尾，各自带读数；`force` 必须显式确认 |
| `POST /api/submit` | 入队一条检索请求 | `interactions.admit_search_request`（I7 准入配额闸门）+ CLI `submit` 同一条路径 | `admitted` / **被拒**（如实回 refusal_reason，不假装成功） |
| `POST /api/task` | 给 M 派活 / 留言 | 用户频道（`userio`）与 `inbox` 语义：**落成"用户给 M 的一条输入"**，不绕过 M 直接指挥角色 | 落盘后有行号/编号可回查 |

**授权与审计**（见 §3 题 C/D）：至少要有 CSRF（已有）+ 来源校验 + 一个**显式开关**（默认不开写面？还是默认开？）+ **每一次写都留审计**（谁、什么时候、改了什么、结果）。
**纪律**：写面**不许**绕开权限面 —— 若发现某件事**没有**既有闸门可走，那就**先裁"要不要新开一条闸门"**（那是 FC-27：`capabilities.py` / `interactions.py` / `tools/base.py`），**不在网页里补一条**。

### 1.4 设置写面（裁定 `4B`）

- `POST /api/settings`：可写 `toolchain.{lean_bin,mathlib_root,coq_bin,isabelle_bin}` · `model.{api_key,base_url,name}` · `workspace.projects_dir`。
- **key 的三条硬约束**（照既有安全阀，判据先写）：① 表单是"只写不读"（`type=password` + 永不回填）② 响应里**永远**只回"配没配"+ `***` ③ 服务端**不打日志、不进错误信息、不进事件流**。
- **落盘**：走 `settings.settings_path()` 同一口径 + 原子写（`store._atomic_write` 的同族做法）；POSIX 上 `0600`，Windows 上尽力收紧 ACL 并在响应里如实说"Windows 上权限靠 ACL，本项目不做保证"。
- **风险如实写**：这会**新增一条把密钥写到磁盘的路径**（比"手工编辑文件"多一个入口）⇒ 因此必须有审计记录 + 默认只在**本机回环**上开 + 可 `--no-settings-write` 关掉。

### 1.5 浏览器端到端（裁定 `5C`）

- 驱动见 **§3 题 F**；**opt-in**：`pytest -m browser` 才跑（与既有 `-m network` 同一形态），默认套件**不装、不跑**。
- 断言什么（至少）：四条主页面渲染成功 · **SSE 在 N 秒内把某个读数改掉（不刷新页面）** · 回答表单提交后面板更新 · 设置表单不回显 key · 无 console 报错 · 基本可达性（label/focus/键盘可达）。
- **三态**：驱动/浏览器没装 ⇒ 这条报 `unknown`（**绝不**报 pass）——与发布门既有的 `unknown ≠ pass` 口径一致。
- 证据：截图写 `temp/`（不入库）；若要在 draft 里引用它们，按 `.gitignore §14` 的规矩登记。

## §5 我建议的开工顺序（你点完 §3 的八道之后）

1. **W0**（骨架与构建链）→ 门。
