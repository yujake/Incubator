   `C.proof_chain`（一条成果的最短证明依赖链，按 `path_group` 分组、根 = 文献 / 无前提自证定理 /
   原始概念）—— 它是为 T5 这一族问题专门加的动作。

## 四、判「通过」的标准（逐条，全部从盘上裁定；产出质量那一层由人读）

`draft/38` §11 五 的八条 **一字不改**：

1. **收工门**：`can_close=true`；验收表覆盖研究链六环节（不适用的写 `na` + 理由）；
2. **A 真的取回**：`search_requests` 全部 `done` 且 ≥4 条 `ok`；`literature` ≥20 行；
3. **C 真的被用**（**本趟重点**）：C 的动作被派过 ≥2 种，且 `relations` ≥50 行；
4. **手稿成体**：`documents` 有一份 `kind=note`/`survey` 的手稿，≥4 条断言、**每条带 `citations`**，
   其中 ≥1 条 `lit:`；**每一节 `body` 非空**（七趟栽在这一条）；
5. **说明九节**：`out/review/REPORT.md` 九节齐全、每节有读数；
6. **诚实边界**：手稿与说明都要明说 FLT 已被证明（Wiles–Taylor 1995），
   **不许出现「我们证明了 FLT」或等价措辞**；
7. **活性**：没有 `no_progress_limit`；被拒的检索/派活如实落读数；
8. **人的抽查**：读稿件抽 3 条，引文与原文一致；候选路线在文献里确有出处。

**加上 `draft/83` 的三条口径修正**：收工的判据归 **M 自己**那份 `task_list`（裁定 3）；
「模型说它做了什么」必须能在交流/台账里找到那条硬事实（找不到按"没做"算）；
产出质量**不加机器判据**，由人读。

### 7.3 裁定一（**已修**）：DNS 失效被算成"模型回了坏 JSON"

**现场**（`sessions/t5h.jsonl`，第 27/28/29 步）：

```
problem = 'judge_failed:ModelReplyNotOk'
detail  = 'gaierror: [Errno 11002] getaddrinfo failed'
```

**链条**：本机 DNS 中途失效 → 网关把 `gaierror` 折成 `error_kind="network"` →
`judge.problem_of_reply` **当时只认 `timeout` 与 `output_exhausted` 两个名字** →
落成 `judge_failed:ModelReplyNotOk` → 循环按**坏 JSON** 计数 → 三步连击 ⇒
`stop_reason = "bad_json_limit"`，收场那句话是：

> 连续 3 次没有给出可解析的 JSON（最后一次：judge_failed:ModelReplyNotOk），停止

**三句话没有一句是真的**：模型一个字都没说，是这台机器没连上。
这与 2026-10-12 那次（超时被当成坏 JSON）是**同一个病**，病根就在"只认两档"那一行 ——
修过一次，但修的是那两个名字，不是那一行。

**修法（以根除为纲，不是加两个名字）**：

1. `judge.problem_of_reply` 改成**按 `modelgw.NOT_CHECKED` 这张已声明的词表分流** ——
   词表加一档，这里自动跟着走：`timeout` → `judge_timeout`、`output_exhausted` →
   `judge_output_limit`、其余 `NOT_CHECKED`（`network` / `server_error` / `unknown` / `no_key`）
   与重试完仍失败的 `rate_limited` → **`judge_no_reply:<error_kind>`**（后缀逐字保留原因）；
   `auth_failed` → **`judge_auth_failed`**（它不是"没查成"：查过了、确定不行）；
   `bad_response` 及其余 → 仍是 `judge_failed:ModelReplyNotOk`（**它回了**，只是那份回复不可用）。
2. 成员判据收成**一处** `judge.is_no_reply`（`judge_no_reply:` 带后缀，写成元组必漏 ——
   这个"漏"在真机上已经发生过两次）；`agent_loop._is_no_reply` 只转发。
3. 停止理由逐档说实话：`model_timeout` / `model_output_limit` / **`model_unreachable`**；
   `auth_failed` **立刻停**（`model_auth_failed`）且不并进任何 streak ——
   重试三次只是把钱再烧一遍。两个新理由登记进 `webui/server.py` 的 `_STOP_BADGES`。
4. 纠正行第三档：`judge_no_reply:*` 那一行**不许**写"把这一步拆小"（那是超时/输出吃光的处置），
   只如实说"这条路这一会儿不通，你什么都不用改，把同样这一步再做一遍"。

**判据**（5 条，每条都两个方向）：

| 判据 | 钉的是 |
|---|---|
| `test_a_network_failure_is_not_a_bad_json_either` | 真机那一行原样（`kind="network"` + `gaierror`）⇒ `model_unreachable`、`bad_json` 保持 0、`problems == ["judge_no_reply:network"] * n` |
| `test_the_boundary_bad_response_is_still_counted_as_bad_json` | **反负控**：`bad_response` 仍走坏 JSON —— 否则上一条可以靠"凡失败都算没拿到回复"满足 |
| `test_a_dead_key_stops_at_once_with_its_own_reason` | `auth_failed` 一次就停、两个 streak 都是 0 |
| `test_every_kind_in_the_gateway_vocabulary_lands_on_a_declared_code` | 词表里**每一档**都落到受控码上（词表加档自动覆盖） |
| `test_the_reply_failure_split_is_the_same_set_as_the_gateway_declares` | 本层的"没拿到回复"集合**恰好**等于网关声明的 `NOT_CHECKED ∪ {rate_limited}` |

### 7.4 裁定二（**未修，登记下一轮**）：`outcome=ok` 的检索里可以是**垃圾文献**

本趟 A 取回 41 条，两条请求都是 `outcome=ok`，而题名逐条是：

```
The Fermat Last Theorem — A Brief, Elementary, Rigorous Proof
Fermat's Last Theorem Proof (3 lines Way)
Facts indicate that Fermat had a simpler proof for his last theorem!
An Alternative Elementary Proof for Fermat's Last Theorem   …（下略）
```

41 条里只有 **10** 条有本地全文，B 因此抽不出概念与关系（`relations` 0 行）——
这正是判据 ③ 挂掉的直接原因，也是**重点考察项没被测到**。

**机制面的事实**：收工门第②环读的是 `retrieval_ok_rows`（`outcome=ok` 的条数），
而 `outcome=ok` 的含义只是"这条请求跑完了"，**不是**"取回来的东西相关/可信"。
`draft/83` §11 的 **D74** 早就登记了这个缺口：

> `literature.matched` 有词表、有两条判据，**却没有写入者、也没有"还没校验"的读数**

**归属（诚实说）**：这一趟我把 `--provider` 从默认的 openalex 换成四家并联（因为开跑前实测
OpenAlex 503），而 Crossref / DOAJ / EuropePMC 对"elementary proof of FLT"这种**题面式说法**
会如实返回大量非同行评议的自称证明。所以**语料质量有一半是我的部署选择造成的**，
不能全记在系统账上；但"系统没有任何判据能看出这件事"是系统的缺口。

**为什么这一轮不修**：它要动的是 `providers.py`（**禁改区**）与"检索那一腿"的判据口径 ——
是个真设计题（凭什么算"可信"：同行评议标记？venue？被引？`type_code`？），
不该在一轮收尾时顺手糊一个。**下一轮第一件事**：按 D74 把它做成可判的读数
（`literature.matched` 的写入者 + 三态），并让验收表第②环读它。
