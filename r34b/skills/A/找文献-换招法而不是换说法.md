# 查不到时换什么：四个旋钮、五条代换、三档缺口，以及引文图怎么走

- 名字：`找文献-换招法而不是换说法`
- 属于：`A`
- 什么时候读它：一次检索什么都没查到、只查到一堆自称证明了某定理的条目、要为一个方向做一轮系统调研，或**已经攥住一篇关键文献、想顺着引文往上/下游走**时
- 一句话：检索式怎么变（题面→规范术语→对象→参考文献）、纳入/排除判据、交回时按三档写清缺口；攥住关键文献后用它走引文图
- 会用到的动作（角色.动作）：A.search_literature, A.shelf_search, A.run_once, A.walk_citations
- 会用到的工具：search.literature, search.shelf, search.local, search.providers, search.register, search.dedup_check, search.walk_citations, table.get, table.search, fs.read, manuscripts.read

# 查不到就换招法

这一条补的是**方法面**（来源 `literature-survey` 里的"检索式、纳入/排除、缺口表"那三件）。
顺序与"交回什么"在 `检索-先本地再联网` 那一条里，这里只讲**换什么**。

## 一、四个旋钮（都在 `A.search_literature` 的参数上，不用新工具）

| 旋钮 | 怎么用 |
|---|---|
| `topic` | **短、英文、用规范术语**。题面式说法查不到不等于这个方向没有文献 |
| `mode` | `precise`（手上有题名，按题名找原文）/ `topical`（探一个方向）/ `broad`（只看"这片有没有人做"）。**别拿 `broad` 当主力**：它给的是面，不是那几篇 |
| `description` | 英文检索式写这里也能让这一问适用（`topic` 是中文时靠它兜） |
| `providers` | 可以点名后端。**同一个问题换后端 = 换一批语料**（实测同一篇在不同后端下"有没有可读全文"是不同的） |

⚠️ **它没有 `limit`**（2026-10-16 亲测记下）：`A.search_literature` 是"**入队 → 领跑 → 交回**"
那种动作，条数由 `mode` 档位与上游给什么决定；**`limit` 是工具 `search.literature` 的旋钮**
（1..50，指**单次调用返回的候选条数**）。两者的面**故意不同**：要"少拿几条"就用工具面，
或拿回来自己截；**别把不存在的参数往动作上写**（框架会按声明拒，白跑一趟）。

## 二、五条代换（查不到时按下表换，**换招法不是换说法**）

1. **题面 → 规范术语**（最有效的一条）。业主点过的那次真机读数：4 次检索里 2 次
   `no_results`，两次都是题面式说法。例：问"某某定理有没有更短的证明"，
   换成**那条路用到的定理与猜想的名字**去查；
2. **目标 → 对象**。问"证明 X"往往查不到，而问**X 的证明用到的那个物件**
   （构造、曲线、群、猜想）常常一查就有 —— 找的是那条路，不是那个愿望；
3. **宽 → 窄**：先找一篇综述/教科书章节（`topical`），再**顺着它的参考文献往下走**
   —— 两个入口：**引文图**（`A.walk_citations` 的 `backward`，见第五节）与
   "用 `fs.read` 读已下到盘上的那一篇的参考文献、再逐条去查"；
4. **换 `mode`**：`precise` 查不到换 `topical`；`topical` 太散换 `precise` 试题名；
5. **换 `providers`**（或换后端组合）。

⚠️ 一次都没成功时**如实记**"这一条没出网/没查到，因为 X" —— 被闸门拒、被滤光、真 0 条，
是三件不同的事，别折成一句"没找到"。

## 三、纳入 / 排除（这一节的用途：别把"自称证明了 X"当文献）

- **纳入的判据**：题名/摘要与**你要问的那件事**有实质交集，且能指到来源标识。
  只因为题名里出现了那串字母就纳入 ⇒ 你会收进来一大批与本问题无关的东西；
- **必须排除但要留痕**的三类（实测那一批里它们占多数）：
  ① **题名自称证明了某大定理**、来源类型是非同行评议那一档的条目（真机：一次检索
  41 条里 13 条 `type=EB`，而**只有 6 条**真的下到了可读全文）；
  ② 拿到的是落地页/登录墙（`download.status=content_mismatch`）；
  ③ 没有可取的全文地址（`download.status=skipped`，原因 `no_pdf_url`）。
- **排除是判断，判断要留痕**：交回时写清"排除了几条、按哪一条理由"。
  静默丢掉的条目在台账上不存在，事后没人能复核你排得对不对。

## 四、交回的三档缺口（`literature-survey` 的第三件，落在这里）

一轮调研交回时**分三档写**，不许混成一句"相关文献如下"：

1. **找到了**：每条给 `lit_id` + 来源标识 + **盘上有没有可读全文**（`table.get` 读那一行的
   `download.status` / `path`）+ 凭什么相关（命中在哪一句）。没有全文的照实标出来 ——
   它是"有出处但不可逐字回验"，与"有全文"不是一回事；
2. **确认没有**：写清**查过哪些式**（把用过的 `topic`/`mode`/`providers` 列出来）。
   **"我查过两次没有"与"这个方向没有文献"是两件事**；
3. **还没查**：下一步该换哪条招法（第二节那五条里选一条），写清为什么选它。

## 五、引文图（**2026-10-15 已接上**：`A.walk_citations`）

上面第二节第 3 条那条替代路，现在有**专门的入口**了 —— 动作 `A.walk_citations`
（工具 `search.walk_citations`，业主裁定"引文图用新动作的方式落"）。两个方向：

| 方向 | 拿到什么 | 什么时候用它 |
|---|---|---|
| `backward`（**回溯**） | 这一篇**引了谁** | 你已经攥住一篇**奠基/关键**的文献，但不知道它引的那几十篇里哪几篇与本问题相关 —— 顺着它的参考文献挑，比重新糊一个检索式准 |
| `forward`（**前推**） | **谁引了这一篇** | 想知道**后来有没有人简化/改进了某一步**（找"更短的那条路"通常在这里），或者想知道这一篇有没有被后续工作推翻 |

四条用法上的硬话（都是实现里写死的，不是风格）：

1. **源必须是盘上已登记的那一篇**（给 `lit_id`）：走查从"我们手上这一篇"出发。
   不接受任意 DOI —— 那样它就成了第二个检索入口，而检索的账只在
   `A.search_literature` 那一处记；
2. 它只走**一步**，不是递归爬。走完拿到的是**候选**，要不要继续往上下游走由你判；
3. 候选**没有判重标注**（本工具刻意不复制判重实现）：登记前先 `search.dedup_check`，
   登记走 `search.register`；
4. **它不按热度排序，这是刻意的**：本项目别处按被引次数排是为了找主流的奠基那批，
   而"找更短/更冷门的那条路"恰恰相反 —— **越热越是被广泛引用的经典**。
   同理：`broad` 那一档的结果**不能按被引次数当选优依据**。

⚠️ 一条**还没接**的（别当已有能力用）：`cited_by_api_url`（OpenAlex 的"谁引了它"接口）
没有取；前推那一侧走的是 `filter=cites:<W…>`。两者在"能不能翻页取全"上不同。

## 六、下不到全文时：**先看类别，再决定**（业主 2026-10-16 口径："随机应变，别频频撞墙"）

`search.download` **失败时会给 `fetch_kind`** —— 那是"为什么没下到"的受控档。
**先读它，再决定下一步**；五类处置完全不同：

| 你读到的 `fetch_kind` | 它到底是什么意思 | 你该做什么 |
|---|---|---|
| `tls_cert` | **本机**证书/吊销检查够不到（不是你被墙） | **换源**。同一个 URL 重试**修不好**这件事 —— 实测同一 URL 默认要 **122 秒**才判死，换客户端开关后才 **0.55 秒**拿到状态码 |
| `tls_timeout` | TLS 握手超时（多半是对方挡脚本，例如 MDPI／机构库） | 至多再试**一次**；仍不行就**换源** |
| `http_403` / `http_401` | 明确不给脚本（反爬） | **别重试**：换源。实测把请求头装成浏览器也照样 403 |
| `network_error` / `timeout` | 真·网络抖动 | 可以重试（换一跳/换镜像常常能过） |
| `all_sources_failed` | **候选与镜像都试完了**（它外层包着上面某一类，原因在 `error` 文本里） | 这一条路**走完了**：别再对同一个 URL 动手，去换招法（第六节末那句）或如实交回 |
| `content_type_mismatch`（这条在 `ok=True` 侧，是**软警告**） | 下到的是落地页/登录墙 | 换直链；**别把它当全文**（B 会把网页导航文字当成概念 —— 这是踩过的坑） |

**一句话：换源 > 重试。** 同一个 URL 失败两次以上就别再碰它 —— 去
`search.walk_citations`（从你已攥住的那篇往回/往前找落点）、或换 `search.providers`
再查一次同一篇的另一个托管点，比在原地上耗时间值得多。**"我试过三个源都不行"是可以交回的
结论**，但必须把**试过哪些 URL、各是什么类别**写出来。

## 七、经验要留痕：开工先读、收工写一条（**这是你自己的账，不是框架替你写的**）

下载/检索这类事上，"哪条路通、哪条路不通"是**会跨趟复用**的。所以：

1. **开工先读**：若工作区里有 `out/lit-experience.md`，先 `fs.read` 它 ——
   里面是前几趟（包括你自己）踩出来的路（哪些托管点能下、哪些域名挡脚本、哪个检索式命中率低）；
2. **收工写一条**：这一趟**新学到的**（能复用的）追加进 `out/lit-experience.md`，
   一条一句、**带证据**（域名 + 类别 + 实测数字），例如
   `- library.oapen.org：连不上（超时 20s）⇒ 别在这家上重试，换 Europe PMC`；
3. **只写会复用的**：一次性的偶发失败不要写（否则这份账会被噪声淹掉，下趟读了等于没读）；
4. **它不是台账的替代**：正式结论仍要落 `literature` 行与交回文本；这份文件是**你的备忘**。

## 八、判"这条文献符不符合需求"：**这是你的判断，且必须留痕**

框架**不会**替你判相关性（它只给题名/摘要/年份/来源类型这些**材料**）。
所以每条都要落到一个判词上，并写清凭什么：

- **纳入** ⇒ `search.register` 时把"凭什么相关"写进 `summary`（**不要只抄题名**：
  写清"它回答的是哪一个子问题、命中在哪一句"）；
- **排除** ⇒ 留痕（第二节末那三类：自称证明大定理而非同行评议、落地页/登录墙、没有可取全文地址），
  并在交回时给"排除了几条、按哪条理由"；
- **判不了** ⇒ 也写出来（"题名相关但看不到摘要"≠"不相关"）——
  **三态：没查／查过不相关／查过相关**，不许折成一句"没有相关文献"。

## 九、交回时的一句话摘要（给主控读的）

除三档缺口（第四节）之外，多加一行**这一趟的经验**：哪条路通了、哪条路不通、下一步该换哪条招法。
主控不需要知道你查了几次，它需要知道**"这个方向还能不能往下走、往哪走"**。
