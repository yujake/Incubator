# 研究记忆就这一份

## 落点与七节（业主 2026-10-14 第 1 条 + 同日追加）

`reports/RESEARCH.md`（相对工作区根）——**项目级、单份、越写越厚**。七节：

0. **成果概述**（写在最前面，见下一节）；
1. **定义与已知**：这个项目里用到的概念与已入库的结论（指到 `stmt:` / `lit:` 那一行）；
2. **已确定的结论**：这一趟之后仍然站得住的（带五元位现状）；
3. **尝试与失败**：每一次失败写清**卡在哪一步** + 属于哪一档（技术性 / 结构性 / 反例不成立）；
4. **例子与反例**：E 从数值实验里撞见的、或 F 造出来的例子（引到落点那一行）；
5. **未解问题**：还开着的 `research_questions` / 缺口清单；
6. **下一步**：如果明天有人接手，他该先动哪一件。

## 成果概述那一节：每句声称都要有落点

业主 2026-10-14 追加：概述回答四件事 —— **证明了哪些命题 / 证伪了哪些猜想 /
做了哪些数值实验或测过哪些样例 / 过程中总结到的经验**。四件事之外，真正的规矩是**引用纪律**：

| 这一句声称 | 必须引到 |
|---|---|
| 「命题 P 证明了」 | **F** 落的那一份：`statements.proof_text` + `reports/attack-<plan_id>.md` |
| 「猜想 C 被证伪」 | 那条带 `counterexample` 的 `experiments` 行（`exp:` 号） |
| 「做了数值实验 / 测了样例」 | **E** 的代码文件（实验行里的 `code_path`）|
| 「存在这样的例子 / 反例」 | **描述那个例子的文件**；F 造的例子由 F 整理成**命题—证明格式**（命题写成「某某例子符合某形式」），引 F 那一份 |
| 「经验 / 教训」 | 那一节没有落点要求，但要说清**是哪一次尝试**教会的 |

**引不到就如实写「没有落点」**。为什么这条是硬的：手稿是下一趟唯一的记忆，
一句没有落点的声称会被当成**已核的事实** —— 它比不写更坏（不写只是不知道，写了就是错的记忆）。

## 硬次序：先读后改

改手稿前**必须先 `fs.read` 读回来**：覆盖一个没读过的文件会被观测闸门拒
（`fs.write` 只在"你见过它现在这一版"时才允许替换）。改动小就用 `fs.edit` 定点改；
整节重写才用 `fs.write`。

## 谁给你送料（别等，去收）

- **E**：数值实验里的反例 / 玩具例（`experiments` 里 `result=refutes` 带 `counterexample`）；
- **F**：攻坚的中间成果与卡点（`reports/attack-<plan_id>.md` + 它回报给你的 message）、
  以及它造的例子整理成的那份**命题—证明**；
- **A**：泛化搜索三档（推广 / 类比 / 特例）—— 进「定义与已知」那一节；
- **C**：结构读数（哪里薄、哪两条矛盾）—— 进「未解问题」。

## 与自动渲染那份的分工

`D.write_report` 渲染的 `reports/<qid>-research.md` 是**工作稿**（一份问题一份、自动生成）；
手稿是**记忆**（一份、手写、跨趟）。两处都要，但别指望工作稿替记忆干活 ——
下一趟的人不会去翻上一趟的 30 份工作稿。

## D 的动作**返回形状是杂的**（2026-10-16 亲测逐个读出来的）

D 的动作**多数**回一个带 `ok`/`kind`（或各类读数）的字典，但**这四个故意不是**：

| 动作 | 返回 | 意思 |
|---|---|---|
| `D.submit_gaps` | **一串请求编号**（`list`） | 这一次**真正提交出去**的那几条缺口。**空列表 = 没有可提交的**（配额/已提交集挡住，理由在 `consider`/`assess` 的读数里）—— 空与"没做成"是两件事 |
| `D.write_report` | **一个文件路径**（`str`） | 它**写下的那份工作稿**在哪；它**只写文件、不落表**（落表是 `D.research` 的事） |
| `D.ingest` | **一串**（`list`） | 这一次从报告里**新建**的那些问题（明细用 `D.ingest_detailed`） |
| `D.ingest_detailed` | **明细字典** | 含 `created`/`created_count`/`skipped`/`decisions`/`merged_by_content_key`/`contradictions` ⇒ **"被跳过者及原因"看这里** |

⇒ 别对这四个动作的返回取 `.get(...)`（会炸）。**要判"成不成"，看它给的东西是不是真的
落了地**：编号能不能在 `search_requests` 里找到、路径上有没有那个文件。

## 一条纪律

**没写进手稿的等于没发生**：会话记录不会自己走到下一趟。所以收尾时先问一句
"这一趟哪三件事是下一趟必须知道的"，把它们写进去。
