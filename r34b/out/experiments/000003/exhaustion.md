## 三块之二：程序设计思路

**要解决什么。** 上界那一半要在论域「K_9 的全部红/蓝二着色」上判定「没有一个是干净的（无红 K_3 且无蓝 K_4）」；下界那一半要给一个 K_8 的干净着色作为见证。程序用一个确定性 DFS 一次跑完两件事，并附两条自校准。

**对象的编码。** n 个顶点的边集 E(K_n)，m = n(n-1)/2 条边。每条边一个布尔色：0 = 红、1 = 蓝。内存里三件东西：① `red[i]`、`blue[i]` 是顶点 i 的邻接位掩码（第 j 位为 1 表示 ij 是该色）；② `rdeg[i]` 是红度；③ 字典 `colour[(i,j)]` 记当前完整/部分着色。位掩码让「这条边会不会造出红三角形 / 蓝 K_4」是一次位运算，而不是重新扫子图。

**边的字典序（DFS 的变量序）。** `edges = [(i,j) for i in range(n) for j in range(i+1,n)]`，即 (0,1),(0,2),…,(0,n-1),(1,2),…,(n-2,n-1)；DFS 的第 e 层就给 `edges[e]` 定色。这是全序且每个着色恰好对应一条长度为 m 的赋值路径 ⇒ 搜索树是一棵完整的二叉深度 m 树，叶子数 = 2^m（未剪枝时）。

**DFS 结构与剪枝规则。** `dfs(e)`：e == m 时 `count += 1` 并把（至多 keep 个）完整着色存进 `solutions`。否则对边 (i,j)：
1. 涂红前判 `red[i] & red[j] != 0` —— 若有公共红邻居，涂红立刻造成红 K_3，剪。
2. 若启用了 `max_red_deg`（引理 L 变体），再判 `rdeg[i]+1 > max_red_deg or rdeg[j]+1 > max_red_deg`，超界则剪。
3. 涂蓝前判 `blue_edge_creates_clique(blue, i, j, blue_clique)`：`blue_clique=3` 时只要 `blue[i] & blue[j] != 0`；`blue_clique=4` 时要找两个公共蓝邻居 a、b 且 `blue[a]` 含 b（即 a、b 之间有蓝边）—— 只有「经过新边 (i,j)」的蓝 K_4 才可能新出现，所以只查过这条边的团是完备的。
4. 两条分支都递归、回溯时把位掩码 / rdeg / colour 原样撤回（纯回溯，无副作用）。

**capped / 节点上限怎么处理。** `over_cap()` 在每次进入 `dfs` 时检查两种上限：`cap_nodes`（访问节点数超过上限）与 `cap_seconds`（每 0x3FFFF 个节点查一次墙钟）。一旦触顶：置 `capped=True`、记 `cap_reason`（'nodes' / 'seconds'），并沿递归栈一路返回 True（abort），整个搜索立刻停下。**触顶的 count 不是完成计数**：脚本的判定式写死 `r34_ok = (s9d['count'] == 0 and not s9d['capped'])`，即只有未触顶的 0 才算上界成立。本次 n=9 的两次运行参数：plain 用 `cap_nodes=4,000,000, cap_seconds=180`（结果 capped=True，reason='nodes'，nodes=4,000,001）；度数界变体用 `cap_nodes=40,000,000, cap_seconds=600`（结果 capped=False，nodes=1,920,213，1.867s，跑完）。

**引理 L（剪枝的正确性依据，模块 docstring 里写着，本报告转述）。**
> L. 在一个既无红 K_3 又无蓝 K_4 的着色里，任一顶点 v 的红邻域 N_R(v) 是红独立的：若 x,y ∈ N_R(v) 且 xy 红，则 vxy 是红三角形。于是 N_R(v) 内部的每条边都是蓝的；若 |N_R(v)| >= 4，那 4 个顶点就撑出一个蓝 K_4。故 |N_R(v)| <= 3，即每个顶点的红度 <= 3。所以任何干净着色都不会被「红度 >= 4 就剪」这条规则剪掉。

**引理 L 与 plain 搜索的一致性交叉检验（n=7、n=8）。** 在 n=7：plain 计数 13842，度数界变体计数 13842，`agree=true`（变体节点 100,892，0.103s）。在 n=8：plain 17640，度数界变体 17640，`agree=true`（变体节点 629,777，0.649s）。两次都未触顶。**口径说明**：这只证明「本实现的两条搜索在 n=7、8 上给出相同的解数」，是实现的交叉检验，不是引理 L 的机器证明 —— 引理 L 的成立靠上面那段纸面论证（对全部 n 成立），n=7、8 是它的两个实例点。

**自校准（机器可能悄悄出错的那个检查）。** 同一套机器对 (红 K_3, 蓝 K_3) 跑 n=5、n=6：n=5 得 12 个无单色三角形的着色，n=6 得 0 个（nodes 987，未触顶）。这与已知 R(3,3)=6 一致。若机器有系统性错误，这两点会先炸。

**独立复核（不信 search 自己）。** 见证着色由 `forbidden_configuration(n, colour, blue_clique)` 复核：暴力枚举全部 3-子集与全部 4-子集，逐条查颜色。K_8 见证的复核结果是 `no red K3 and no blue K4`。这条复核不经过 DFS 的任何数据结构，只读 `colour` 字典。

## 三块之三：穷举论证

**搜索空间有多大、怎么算出来的。** 论域是 E(K_n) 的全部红/蓝二着色，共 2^m 个，m = n(n-1)/2：
- n=5：m=10 ⇒ 2^10 = 1,024
- n=6：m=15 ⇒ 2^15 = 32,768
- n=7：m=21 ⇒ 2^21 = 2,097,152
- n=8：m=28 ⇒ 2^28 = 268,435,456
- n=9：m=36 ⇒ 2^36 = 68,719,476,736（约 6.87e10）

每个数的口径：一个「对象」= 一个把 36 条边逐条染成红/蓝的完整赋值；没有任何两个不同赋值被当成同一个对象（脚本不做商掉同构，见下条）。

**为什么这个 DFS 真的穷尽（不漏一个对象）。** DFS 在深度 e 上只做两件事：把 `edges[e]` 涂红、把 `edges[e]` 涂蓝，二者互斥且穷尽该边的两种取值；深度从 0 走到 m，每条从根到叶的路径恰好是一个完整着色的 m 次逐边赋值；不同的路径在某个 e 上取值不同 ⇒ 是不同的着色。所以「不剪枝时」叶子集合 = 全部 2^m 个着色，一一对应。没有随机、没有抽样、没有启发式提前返回（唯一的提前返回是 capped，那种情况被记成 capped=True 且判定式拒收）。

**为什么剪枝不丢解（这是穷举论证的关键一步）。**
1. 红 K_3 剪枝：在深度 e 上，已定色的边是 `edges[0..e-1]`。涂红 (i,j) 时若 `red[i] & red[j] != 0`，说明存在 h 使 ih、jh 已红 ⇒ {i,j,h} 已是红三角形，且这三条边都在 `edges[0..e]` 内。此后无论剩下的边怎么涂，这个红 K_3 不会消失 ⇒ 该分支下所有叶子都是脏的（含红 K_3）⇒ 剪掉不丢干净解。
2. 蓝 K_clique 剪枝：同理，`blue_edge_creates_clique` 只判断「经过新边 (i,j) 的」团。因为其余边的颜色没变，任何一个已经变蓝的团在涂蓝 (i,j) 之前就已经存在并被更早的层拦住，所以只需查过新边的团；查到即该分支下所有叶子都含蓝 K_q ⇒ 剪掉不丢干净解。
3. 红度 <= 3 剪枝（仅在 `max_red_deg=3` 的变体里）：由引理 L，任何干净着色在每个顶点上红度 <= 3，因此一旦当前部分着色里某顶点红度已到 4，该部分着色的**任何**完整化都不干净 ⇒ 剪掉不丢干净解。注意方向：引理 L 说的是「干净 ⇒ 红度 <= 3」，所以「红度 >= 4 ⇒ 不干净」，与剪枝逻辑同向，不反。
4. 边界处理：n 的上界取到 9（m=36 全部边都被赋值才计数）；n=9 的 plain 运行被节点上限截断（capped=True, cap_reason='nodes', nodes=4,000,001），它给出的 0 **不是**完成计数，本报告的结论不建在它上面；建在未触顶的度数界变体（capped=False, nodes=1,920,213）上。这就是「边界那一档由谁覆盖」：n=9 由度数界变体覆盖，plain 那一档只作截断读数如实登记。

**n=8 的 17640 与 K_8 见证的具体边集。** n=8 的 plain 搜索（cap_seconds=300，未触顶）在 1,420,332 个节点上数出 **17640** 个既无红 K_3 也无蓝 K_4 的着色 —— 这是 K_8 干净着色的**精确**个数，不是近似（穷尽 + 未被截断）。脚本取 `solutions[0]` 作为见证并独立暴力复核通过：
- n = 8，红边 12 条：(0,1),(0,2),(0,3),(1,4),(1,5),(2,4),(2,6),(3,5),(3,7),(4,7),(5,6),(6,7)
- 蓝边 16 条（= 28 - 12）：补集
- 独立复核：`forbidden_configuration(8, colour, 4)` → `None`，即 `no red K3 and no blue K4`
所以 R(3,4) > 8。

**n=9 两次读数都是 0 的含义（必须分开读）。**
- plain 运行：count=0，nodes=4,000,001，capped=True（cap_reason='nodes'），3.649s。**这是截断读数**：它在 4,000,000 个节点之后被叫停，并没有把 2^36 走完，因此它的 0 只说明「走过的 4,000,001 个节点里没有干净叶子」，不构成上界证明。
- 度数界变体：count=0，nodes=1,920,213，capped=False，1.867s。**这是完成读数**：DFS 正常走到返回（未被节点上限或时间上限打断），全树搜毕，干净叶子数 = 0。由引理 L，这条搜索的剪枝不丢干净解 ⇒ K_9 的 2^36 个着色里没有一个是干净的 ⇒ R(3,4) <= 9。
- 两句合起来：R(3,4) <= 9（上界）与 R(3,4) > 8（下界）⇒ R(3,4) = 9。

**这个证据到什么档。** 本行 evidence_kind 按框架规矩落 `cross_check`（自报 proof 一律降级），method = exhaustive_search。要把「穷举 = 证明」那一档签下来，需要 V 用 `verify.verify_proof` 会审这份报告（程序路径 + 本报告 + 只读读数），V 那一签才是该档的唯一凭据；在 V 签之前，最多是「有数值实验支持」。
