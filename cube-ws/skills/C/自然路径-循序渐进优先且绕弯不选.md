# 最自然路径：不是最短那条，是每一步都支撑结论的那条

- 名字：`自然路径-循序渐进优先且绕弯不选`
- 属于：`C`
- 什么时候读它：有人问「哪条证明路径更自然 / 该用哪一条」、或你拿到一列候选路径（`path_shapes`）要在里面挑一条的时候；链很长、一批没搜到根（`frontier` 非空或 `frontier_note` 说停下的原因不是深度）的时候；以及唯一那条路径带着跳变或旁挂节点、你怀疑台账缺东西的时候
- 一句话：形状读数只是材料：循序渐进优先、绕弯不选、唯一且曲折就上报并给构想；长链按 max_depth 一批一批往回搜，前沿是下一批的起点，拼起来要交代接缝
- 会用到的动作（角色.动作）：C.proof_chain
- 会用到的工具：analysis.register_report, conductor.escalate, table.get

# 最自然路径：不是最短那条，是每一步都支撑结论的那条

## 一、先要形状，再判自然

要比较"最自然、最直接"的关系路径时，第一步永远是 `C.proof_chain`：它的读数里
带一列 `path_shapes` —— 同一个目标可以有好几条候选路径，每条一行，摆的是形状，
不是分数：

- `hops`：跳数；
- `steps`：大步骤数（这条路的承重脊上要经过几个不同的命题段）；
- `gaps`：有几处"无依赖直达" —— 链在某个命题上断掉，而它自己没有任何依赖、
  却被当成根（`gap_nodes` 点名是哪几个）；
- `detour_nodes`：挂在这条路上、但不被结论用到的节点；
- `off_path_ratio`：旁挂节点占这条路上出现过的节点的比例；
- `support_edges`：真的支撑结论的那几条边（`dep_id` / `from` / `to`）；
- `alternatives`：同一个目标还有几条别的候选路径。

这套读数只回答"这条路长什么样"。判"它自不自然"是你的活 —— 下面三条是判据的方向，
不是阈值：本系统不给你"几跳以内算自然"这类硬规定，因为自然与否取决于那道题的数学，
不取决于一个数字。读数是给你反驳用的材料，不是替你下判决的分数。

## 二、长链一批一批往回搜：`max_depth` 是一批能搜多深

`max_depth` 说的是**一批**分析能往回搜多深（默认 6），不是"一条证明最多几大步骤"。
一条证明有几十个大步骤，就一批一批往回搜、最后拼起来。所以读数里这三件事要分开读：

- `closed`：这一批到根了没有；
- `frontier`：这一批因深度用尽停在哪些节点（`why` 只取 `depth_limit`）；
- `path_shapes`：这一批各条候选路径的形状。

"这一批没到根"不等于"这条链断了"，更不等于"没有这条路"：深度用尽是**还没搜完**
（`frontier` 非空），而依赖没写 / 悬空边 / 环才是**链在这儿断了**（那种行的
`frontier` 是空的，`why` 写着原因；整批一行都没停在前沿上时 `frontier_note`
会直接说"停下不是因为深度用尽"）。这两种"没到根"必须分开说。

做法是下面这个循环 —— 搜几批、先挑哪一条前沿，由你定；框架不会替你接着搜：

1. **先搜一批**：`C.proof_chain(target, max_depth=6)`。`closed` 为真 ⇒ 这一批就到根了，
   直接按下一节「三条判据」判自然性，循环到此结束。
2. **没到根就看 `frontier`**：它逐条给 `{node, from, via_dep_id, depth_reached,
   proof_no, path_group, why, next_hint}`。`why="depth_limit"` 说的是"深度用光了、
   前面还有"，那几条 `node` 就是把这一批深度用光的节点。
   一条候选路径可能有好几个前沿节点（组内 AND 的几条分支各自被截断）——
   不必全搜，先挑一两个最接近结论的。
3. **接着搜之前先想清楚要什么**：你要的是"把这条链补全"，还是"确认这条路其实走不通"。
   要补全就往下搜；要确认走不通就停手，把"哪一处接不上"写成结论 —— 那时只能说
   "搜到的那一段之后还没有可查的推理"，不能说"这条路不存在"。
4. **下一批把 `target` 换成前沿节点**：`C.proof_chain(node, max_depth=6)`，
   `node` 照抄（`stmt:` 前缀照抄即可，两种写法目标解析都认）。换起点时别换到别的
   候选路径上：`frontier` 那一条里写着 `proof_no` / `path_group`，照它走同一条。
5. **拼的时候自己交代"拼的是哪几段、接缝在哪"**：每段说清起点、终点、各几跳，
   接缝说清"前一批停下的节点 = 后一批的起点"；再交代每一段是不是"无依赖直达"
   （那一段的 `gaps` 非零，就是业主说的 T4 跳变），以及拼起来之后的总跳数与总步骤数。
   接缝怎么核（手上只有读数时也核得动）：前一批 `frontier[]` 里那一条的 `node`
   必须就是后一批那一行的起点，它的 `from` 必须是前一段走通的最后一个节点
   （`walked_nodes` 的末一个），`via_dep_id` 就是接缝那条边 —— 三样对得上才叫一处接缝。
   框架侧另有一份核对读数 `path_shape.join_segments([批1, 批2])`：它把 `segments`
   （每段的起点 / 终点 / 跳数）与 `seams`（接缝节点）摊开，并按拼后的边重算
   `hops` / `steps`（不是把两批的数字相加 —— 前一批报的跳数里含着"越界那一跳"）。
   它是核对材料，不是替你把链拼好了：这么拼对不对、拼起来自不自然，仍由你判。
6. **拼不起来就如实报哪一段缺，补全之后仍绕弯就上报**：接缝对不上、成环、某一段
   断了（`checked=False`，`note` 点名断在第几批）时，把那条 `note` 的实质写进结论：
   "缺的是哪一批到哪一批之间那一段"。**不许**把"没搜完"说成"没有这条路"，也不许
   拿几段拼出一个"看起来完整"的链交出去。补全之后这条路仍然绕弯或全是跳变 ⇒
   走下面「唯一且曲折要上报」那一条，并把"我分了几批搜、每批停在哪儿"一起写进
   上报正文 —— 那是父代理复核这条链时的唯一依据。

## 三、三条判据

1. **循序渐进优先**。同样走到根，优先选"一步接着一步、每一步都由上一步兑现"的那条。
   一条 T4 级的东西"无依赖地生生证出来"（`gaps` 非零、`hops` 很小、中间没有可查的
   推理段），与一条"几个大步骤自然推出"的路（`steps` 大、`gaps` 为零、每一步都有
   `support_edges`），后者才是该交出去的答案。理由不是它更短或更长，而是它可复核：
   每一步都能被问"这一步凭什么"。
2. **绕弯子不选**。链上挂着不直接支撑结论的引理或定理（`detour_nodes` 非空、
   `off_path_ratio` 高），说明这条路在那一段是绕的 —— 它经过的东西与这条结论无关。
   例外只有一个：那些旁挂节点其实是这条路的必要中间步骤。那时不许沉默地选它，
   要在说明里写清"它支撑的是哪一步"；写不出这一句，就按绕弯处理。
3. **唯一且曲折的路径不许默认接受**。如果绕弯的那条是台账里唯一能走到根的路径
   （`alternatives` 为 0，而它带着 `gaps` 或 `detour_nodes`），这不是"那就用它"，
   而是台账缺东西：缺一条更短的证明、缺一个把跳变补起来的引理、或缺一件让我们能
   自己排出那条自然路径的工具。这时你要**上报**，并给出自己的**构想**。

## 四、上报口径（C 没有出边，走的是"上行"）

C 的可召唤边是空的：你不能给别人派活。你能做的是把判断交回**召唤你的那个代理**
（通常是 D 或 M），由它决定让谁去做。两条通道都要用，次序是先留痕、后交人：

1. **先留痕**：把候选路径的形状、你判它不自然的理由、以及你的构想，用
   `analysis.register_report` 登记成 `analysis_reports` 的一行（`kind` 取 `paths`，
   `summary` 一句话说清"哪条路不好、该补什么"，`markdown` 写正文：形状表 + 选与不选的理由）。
   不登记的上报在台账上等于没有发生。
2. **再上行**：用 `conductor.escalate` 把这件事写进召唤者的收件箱 —— 它不是一条召唤边
   （收件人是运行期解析出的召唤者），本趟会以 `stop_reason=escalated` 收工等父处理。
   三个参数怎么填：
   - `need`：一句话说清要父代理做什么，例如"找 D 组织一次研究，把这条唯一且曲折的路径
     换成一条可复核的路径"，并写明你建议的入口。它有字数上限，说不清就说明还没想清；
   - `kind`：要把这件事交给 D 组织研究用 `reroute`；缺的是一件具体的东西
     （一条引理 / 一件工具 / 一段原文）用 `missing_input`；
   - `evidence`：点名台账 id（`stmt:` / `lit:` / `exp:` 那几个），父照它去核，
     不要让它自己猜是哪几条。
   被受控拒绝（例如 `not_caller`）时如实写进你的回复：那是"没上报成"，
   不是"不需要上报"。

## 五、构想长什么样（至少给一条，而且要能被执行）

"提出自己的构想"不是"建议再研究一下"，而是给 D 一个能派下去的活。三种形态，
挑与你这条路径最贴的那一种写：

- **补引理**：缺口在哪一步、那条引理要说什么（结论是什么、由哪些已收录的命题推出），
  以及它为什么能把 `gaps` 那一处跳变补成一步可查的推理；
- **造工具**：要 D 造什么（例如"一条按证明号与路径组枚举到根、并标出每一处无依赖跳变
  与旁挂节点的读数"），它要回答什么问题，现有读数为什么答不了；
- **换收录**：台账里那条证明该由哪一条更短的证明替换，新证明的第一步与最后一步
  分别落在哪条已收录的命题上。

三条都要落到"下一步谁做什么"，而不是一个评价。构想与读数一起进上报正文，
两者缺一条，父收到的就是一句没有依据的建议。

## 六、别把形状读成判决

`gaps` 非零不等于这条是假的（经审核的自证定理本来就该是根）；`detour_nodes` 非空
也不等于那条路是错的（旁挂的引理可能正是补桥的材料）。形状只告诉你"该去问哪一句"：
判决在 V/H 那一侧。你说的是"这条路不自然、建议这样补"，不是"这条命题不成立"。

## 七、读不到形状的时候

`path_shapes_checked` 为假（依赖读不懂 / 目标找不到 / 分支太多没算完）时，
这一趟没有形状可判。那时不许把"没算成"读成"没有候选路径"：如实说清哪一格没算成，
并把 `path_shapes_note` 的原话带上。长链要比较时，按第二节那个循环一批一批往回搜
（`max_depth` 仍是一批的深度上限）；读数里 `spine_found` 为假的那些行，
是"这一批没算到脊"，不是"这条路不存在" —— 看 `frontier` 与 `frontier_note` 分清
"还没搜完"与"链在这儿断了"。
