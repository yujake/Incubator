# 把问题溯源到证据（L1→L2，按需 L3）与矛盾裁决的闭环

- 名字：`溯源-问题到L1L2L3与矛盾裁决`
- 属于：`D`
- 什么时候读它：要写结论却要交代「这条靠什么站着」、证据互相矛盾、或手上有一条矛盾问题要收口时
- 一句话：L3 只在两个可核实条件下才下钻；trace_l3 只取事实不做抽取；裁决的 verdict→状态是设计
- 会用到的动作（角色.动作）：D.trace_question, D.trace_l3, D.adjudicate, C.contradictions, D.research
- 会用到的工具：trace.relation, trace.concept, trace.literature, trace.chain, table.get, table.search, fs.read

# 溯源：L1 → L2，按需 L3

## 一、三档各拿什么（`D.trace_question`）

| 档 | 由什么取 | 拿到什么 |
|---|---|---|
| **L1** | `relation_id` | `quote` / `description` / `page_range` |
| **L2** | `concept_id` | 概念定义 ＋ 它参与的全部关系的表述 |
| **L3** | `lit_id` | 文献元数据 ＋ 本地文件 ＋ **正文片段** |

## 二、L3 是"按需（贵）"，而**按需的判据是两个可核实条件**（不是感觉）

只有下面两条之一成立时才下钻正文：

1. **证据互相矛盾**；或
2. **要写结论了，却没有一条 `quote_verified=True` 的关系**。

这两条都是**可核实**的读数。**不做**"感觉需要更多细节"这种判断 ——
那种判断没法复核，也没法反驳。

`qid` 不在 `research_questions` 表里时它**抛** `EvidenceError`（不是返回空证据）：
调用方要能区分"**问题号写错了**"（调用方 bug，应立刻停）与"**证据不足**"（正常业务状态）。

## 三、`D.trace_l3` 只取事实，**不做抽取**

它只取三件事实：**文件在不在**、**是否 processed**、以及（有工具时）**正文片段**。

**它不在这里做 OCR 或正文抽取** —— 那是 B/K 的职责。D 下钻正文的目的是
"**核对引文语境**"，所以必须由专门的工具返回**带页码**的片段。
工具缺失时**如实写 `found=False`**，而不是假装读过 ——
**"没做"与"做了但没结果"是两件事**。

## 四、`D.adjudicate`：矛盾裁决（I2 的收敛点）

**verdict → 状态**这张映射是**设计**，不是实现细节：

| verdict | status | contradiction_verdict | 后续 |
|---|---|---|---|
| `resolved` | `answered` | `resolved` | 清空等待集；notes 写 winner 与 code |
| `unresolved` | `needs_evidence` | `unresolved` | 轮数 +1，并提交下一轮检索请求 |
| `new_contradiction` | `needs_evidence` | `new_contradiction` | 为**新的矛盾对**新建一条问题；原问题的轮数… |

⇒ 你判的是"**这两条到底哪个站得住**"，而不是"它们看起来冲突"。
冲突的**发现**是 C 的活（`C.contradictions` 给两行编号与判据）；
**收口**在你这里，且收口必须落到上表某一格 —— 判不出就老实走 `unresolved`
（它会去要更多证据），**不许**为了结案硬判一个 `resolved`。

## 五、一条纪律

溯源给你的是**表述、代号与页码**，不是"这条成立"。
写结论时引的是**你溯到的那一行**（`stmt:` / `rel:` / `lit:`），不是"我记得文献里说过"。
