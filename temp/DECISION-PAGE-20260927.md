## 题 1 · 检索相关性：要不要给**中文题面**改检索口径？

### 在裁什么

`T1`/`T1.5` 两次真实运行取回来的来源**根本不切题**（主题"同调代数中导出函子的长正合列"，
取回"铁基高温超导体"、"化学混合物毒性预测"等）。根因是
`providers._ascii_keywords` 只抓英文词 ⇒ 中文题面抽出 0 个关键词 ⇒ `keyword_hit` 返回 `None`（无法判定）
⇒ 精筛**100% 弃权**（`rejected: 0`）；而"宁可不过滤也不能误杀"是**刻意的**取舍（`keyword_hit` docstring 逐字）。
更前一层：产品把**中文原串**打给英文库（`provenance.query_by_source = {"openalex": "素数分布中的筛法", …}`）。

### 已有第一手读数（2026-09-27 14:36，零 API 花费，见 `draft/28` §102）

6 个主题、23 条来源，走的就是产品默认路径（`evidence.retrieve(topic, search_fn=None)`）：

```text
5/6 主题（全部中文）  ⇒ 每一个候选的 keyword_hit 都是 None（精筛整体弃权），keep 全 True，rejected 全 0
英文对照那 1 个主题    ⇒ hit 全 True，3 条来源**全部切题**（homological algebra 的三篇）
中文题面取回来的实例    ⇒ "机动车运动控制"、"军事飞机识别"、"柏拉图哲学视域下《我的柏拉图式甜心》"、"城市大数据"
23 条来源里与题面**一个二字片段都不重合**的有 7 条
```

### 选项

| 选项 | 做什么 | 代价 / 后患 |
|---|---|---|
| **A**（自决，无论如何都做） | 只把"弃权"报出来：`sources_detail` 分列 `judged_relevant` / `rejected` / **`unjudged_no_ascii_keywords`**，并把逐条 `filter_note` 带进产物（今天它被丢掉了） | 读数不再说谎；**但检索行为一字不动**，中文题面仍取回噪音 |
| **B**（已完成大半） | 只度量不拦截：把"检索切题率"作为常设读数（`T1.4` 探针已产出第一手读数） | 无风险；但它只让问题可见，不解决问题 |
| **C** | 加 CJK **过滤**：汉字重合度低于阈值就剔（带负控与回滚开关） | 立刻减少噪音；但可能**误杀**（原作者担心的那一类），且阈值只能在英文库上校准 |
| **D**（**推荐立刻做 · 止血**） | **fail-closed**：题面抽不出任何英文关键词时，**不拿中文原串去打英文库**，而是如实落第三态（如 `query_not_applicable_cjk`），把"检索口径不适用"写进产物与未接线/未知清单 | 中文题面在英文术语补齐之前**检索不到东西** —— 但今天检索到的是**噪音**，而噪音比"没有"更危险（它会进台账、假装是证据） |
| **E**（**推荐作为正式修法 · 治病**） | 修**检索侧**：中文题面 → 英文术语（受控词表/词典，或一次模型调用做 query expansion）后按 provider 原生检索；用 B 的读数验收 | 最根本；代价是引入新依赖与新的失败面（术语错 ⇒ 检索偏），要花掉几次模型调用 |

### 我的推荐与理由

**D 立刻做 + E 作为正式修法，C 只在 E 的读数不达标时再上。**
理由：① 今天最危险的不是"检索不到"，而是"检索到噪音却报成功"，它已污染两次运行读数，
且下游所有以回验率为分母的指标（O6/P3/O8/单位经济）都建在这上面；② 英文对照那一跑证明**管道本身没问题**
（同一套 provider、同一个精筛，英文题面取回三篇全切题），缺的只是"中文题面 → 英文检索式"这一步；
③ C 是在错误的层打补丁：过滤只能删噪音，不能带来切题文献，而且阈值靠英文库校准会同时误杀。

**无论选哪个，A 我都会做**（纯观测、不改判据，属自决范围）。
落点是 **FC-27 `solver-core` 区**（`providers.py`）⇒ 改它需要 2 名 reviewer + 一个写入窗口。

### 证据与重新触发条件

- 读数：`draft/28` §102（原始 `temp/t14-topicality.json`，探针 `temp/_t14_topicality.py`）；根因链 §100.2 / §102.3
- 重新触发：选 D+E ⇒ D 做完"不再产生假证据"**永久关闭**；E 按 B 的读数验收
  （建议线：中文题面切题率从今天的 ~13% 提到 **≥ 70%**，且 `filter_note` 不再是"弃权"）；
  达不到就上 C 或换 provider，并把"检索切题率"写进阶段 C 的止损线。

## 题 2 · 能力表的 `params` 是"契约"还是"声明 + 接缝"？（`sleep` 该改哪一侧）

**在裁什么**：`capabilities.py` 的 `CAPABILITIES['E'].run_experiment` 声明了 `sleep`，
而真实现 `AgentE.run_experiment` 既没有这个形参、也不收 `**kw`；`Conductor._check_params` 读的正是这张表
⇒ **参数门在这一格被绕过**（放行 ⇒ 写 running 行 ⇒ handler 抛 `TypeError`）。

| 选项 | 做法 | 代价 / 后患 |
|---|---|---|
| **A（推荐）声明 + 显式接缝登记 + 导入期交叉断言** | 能力表每个 `property` 必须被 `handler` 签名接受，**除非**登记在显式的"接缝表"里（`sleep` 入表 + 注明"只服务替身夹具"）；`_check_params` 改读"声明 ∩ 实现签名" | 写 `capabilities.py`（今天非禁改区）+ `agent_e.py`；顺带一次落地"schema 每个 property 必须被 handler 签名接受"这条通用判据 ⇒ **消灭整族**（`name`/`checker_name`/`run_name`/`sleep` 同族） |
| B 对齐实现（删 `sleep` 声明） | 替身夹具改成按**工具 schema** 声明 | 要改 `tests/test_conductor.py`、`tests/test_scheduler.py` 大量 `sleep=0.x` 调用点与两个 `FakeE.run_experiment` 签名；丢失"编排层给单次实验更短时限"的接口；同类问题仍在 |
| C 对齐声明（加 `sleep` 形参） | 给 `AgentE.run_experiment` 加 `sleep` 并实现语义 | 今天**没有任何真实调用方**传它 ⇒ 造一个没人验的"假特性"；语义还要另裁一次 |
| D 保持现状（接受为残余） | 只把事实登记在 `tools/verify_tools.py:195-227` | 参数门在这一格永远被绕过；任何按能力表构造调用的调用方拿到与实现不一致的契约 |

**推荐 A**。理由：它不是"改哪一侧"的单点选择，而是把"声明与实现必须对得上、对不上就必须显式登记"
变成**可执行的判据**；其余三选项都只是消掉这一格。
**证据**：`temp/residuals.tsv` 的 `D-2`（B 类第 3 行 + E 类第 45 行，**重复登记**）；`draft/28` §2 的 `D-2`、§39.4；
代码 `capabilities.py:881-886`、`tools/verify_tools.py:204-218`。完整选项表见 `STAGE-B-CLASSIFY.md` §3 Q1。
**重新触发条件**：若选 D，触发条件 = 任何按能力表构造调用的调用方真的跑起来并拿到 `TypeError`。

## 题 4 · 清单↔台账的对账取哪种语义（要不要一条机械判据）？

**在裁什么**：三件套里"清单 ↔ 台账"这一对**没有任何命令完整校验**。今天是

属"刻意先登记路径"）。差集要不要机械判？判哪种语义？

| 选项 | 做法 | 代价 / 后患 |
|---|---|---|
| **A（推荐）非对称 + 区分"预登记"与"漏登记"** | 新增只读子命令：对清单**每条唯一路径**断言台账里有对应条目，输出"清单有而台账无"的差集；**不要求对称**（台账允许清单外的历史条目）；差集里"盘上文件不存在"的标为**刻意预登记**、其余标**漏登记** | 写 `scripts/noai_gate.py`（禁改区 ⇒ 2 名 reviewer + 窗口）；差集今天就 1 条且可解释 ⇒ 落地即绿，不引入新红 |

## 题 5 · `owner-1`/`owner-2` 这两个**代记名**算不算"人已签"的终态？

**在裁什么**：`draft/28` §93.2 逐字：所有者 2026-09-27 确认"找人看过了，全都可以签字"，
并**选择**由父代理代录、姓名记 `owner-1`/`owner-2`；门在每条后面打印
「署名归属由改动者/签字人**声明**：`attested`，**门无法机械验证该声明**」。
⇒ 台账里的 `owner-1`/`owner-2` 是**代记名**，可信度来自所有者的口头确认，**不是**机器证据。

| 选项 | 做法 | 代价 / 后患 |
|---|---|---|
| **A（推荐）接受代记名为终态** | 不动机器可读台账；把 §93.2 的边界声明**逐字**留在交接件里，并写明"若将来需要可追溯的真实署名，必须由人用手改写这两个字段" | 真实姓名不可追溯（`attested` 不可机械验证）；但这是**唯一不需要再买窗口、也不伪造证据**的选项，且与判据五 HARD（`reviewers` 只由人写）不冲突 |
| B 要求真实署名重签 | 由人用真名对 22 条（今天 20 条有效 ×2）`--approve` 重签 | `--reviewer` 是**单值参数**（同一次调用给两个名字只有最后一个生效，§93.1 ② 实测）⇒ 需要 **40 次**调用；台账 `sha256` 随之变化 ⇒ 必须**再买一个窗口**并重派 `R1d` |
| C 改成自我描述的代记名 | 把名字改成如 `attested-delegated-1` | 仍不是真实署名（`attested` 不变），却要改禁改区台账（窗口 + 人签）⇒ 只换来措辞更诚实 |
| D 不裁，继续记"待办" | 交接里保留"签字待人" | **违反 Goal B 的关闭条件**：`F` 类要么人已做、要么写明"为什么必须由人做"并进交接，**不许用"待办"含糊过去** |

**推荐 A**。理由：它同时满足两条硬要求 —— 不伪造证据（`attested` 边界逐字保留）、
不让残余悬空（明确"这是终态"）；而 B 的 40 次调用 + 一个新窗口，换来的只是"名字更真"，
而**没有任何机械判据能验证人名真伪**（门自己承认这一点）。
**证据**：`draft/28` §93.1/§93.2/§93.3；`residuals.tsv` 的 `F-人类动作`；今日实测 `entries=22`、
`reviewers_total=40`、`owner-1` 20 / `owner-2` 20（0 reviewer 的只有 `.noai-approvals.json` 与 `pyproject.toml`）。
完整选项表见 `STAGE-B-CLASSIFY.md` §3 Q4。
**重新触发条件**：若将来出现**需要对外举证署名**的场合（审计、交付验收），则触发 B。
