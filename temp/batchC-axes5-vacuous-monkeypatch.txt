axes-5 的附带发现（实测读数，2026-09-26 本批）：SANDBOX_AVAILABLE 的那个唯一下游
消费者是一个不生效的 monkeypatch。

命令（在 D:\Incubator\agentflow 下，PYTHONPATH=src）：

    python -c "
    import pathlib, tempfile
    import agentflow.tools as T
    from agentflow.store import Store
    from agentflow.tools import build_registry
    d = pathlib.Path(tempfile.mkdtemp()); st = Store(d)
    reg = build_registry(store=st, workspace_root=d, strict=True).registry
    reg.for_role('H'); n1 = list(reg.role_filter_notes.get('H', []))
    T.SANDBOX_AVAILABLE = True      # 正是 tests/test_r4_roles_surface.py:198 做的事
    reg.for_role('H'); n2 = list(reg.role_filter_notes.get('H', []))
    print(n1, n2, __import__('agentflow.tools.base', fromlist=['x']).SANDBOX_AVAILABLE)
    "

实测输出：

    patch T.SANDBOX_AVAILABLE 前 notes: []
    patch T.SANDBOX_AVAILABLE 后 notes: []
    base 模块里那个名字还是: None
    => 那次 monkeypatch 是否真的改变了判据: False

含义（两条，都是给父代理决策用的）：

1. `tests/test_r4_roles_surface.py::test_for_role_notes_follow_the_current_state`
   的 `monkeypatch.setattr(T, "SANDBOX_AVAILABLE", True)` 打的是 `agentflow.tools`
   包对象上的属性，而 `tools/base.py::ToolRegistry._role_surface` 读的是
   `base` 模块自己的全局 `SANDBOX_AVAILABLE` —— 两者不是一个名字空间，所以那次
   patch 不改变任何判据。该用例今天靠"真实 H 工具面里没有 external=exec 的工具"
   而静默通过（P16 形态：判据看起来在跑，实际没接上）。
   要让它真的咬，应改成 monkeypatch `agentflow.tools.base.SANDBOX_AVAILABLE`
   （或 `m.setattr(B, "SANDBOX_AVAILABLE", True)`，`B` 就是 `agentflow.tools.base`）。

2. 这正是本批把 `SANDBOX_AVAILABLE` 留在 `tools/__init__.py` 的 import 里的原因：
   删掉它，上面那个 `setattr` 会因为属性不存在而抛 AttributeError ⇒
   `tests/test_r4_roles_surface.py` 变红，而 `tests/` 不在本批授权改动范围内。
   若父代理决定要删这个名字，配套的一行改动就是上面第 1 条那句 —— 两件事应当同一次做，
   否则基线从 2129 passed 变成 1 failed。
